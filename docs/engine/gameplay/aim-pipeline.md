# The weapon aim and fire pipeline

The weapon-side aim and fire path runs from the camera matrix, through the single stored aim target, into the per-weapon fire construction. The camera-getter split is in "The camera getters" below, and the body's native turn reactions to the aim direction are in "Body-turn reactions to the aim direction".

The addresses and field offsets behind every name below are in the pyxis defs, chiefly [`PlayerAimControl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl), [`Character`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character), [`Inventory`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory), [`WeaponBase`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase), [`Explosive`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Explosive), [`Vehicle`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle), and [`Player`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::Player).

## The short version

Everything the player fires is aimed at one point. [`PlayerAimControl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl) casts a single ray from the camera transform and stores one target position per purpose (weapon, grapple, melee, grenade, sticky, snap). It does not store one per weapon or one per hand. Each frame [`CPlayer::UpdatePostCamera`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/character::player##func-Player_UpdatePostCamera) reads the weapon slot's point and stamps it onto the character as [`Character::m_AimTargetPositionWeapons`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AimTargetPositionWeapons). That single point fans out unchanged to every weapon the character is holding. Each weapon stores it as its own [`WeaponBase::m_AimTargetPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_AimTargetPosition) and, at fire time, builds its shot from the muzzle toward that point. Dual-wielded guns, wingsuit guns, and mounted guns all receive the identical point.

The shot origin is per weapon (each weapon's own muzzle bone), and the shot direction converges on one shared aim target. Each weapon stores its own copy of the target point, so the data path carries a distinct point per weapon; the game writes the same value to every copy.

## The aim target: `PlayerAimControl`

One [`PlayerAimControl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl) hangs off the player ([`Player::m_AimControl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::Player##field-m_AimControl)). It is a target cache, indexed by [`TargetType`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::TargetType) with one slot per purpose: [`TargetType::TARGET_WEAPONS`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::TargetType##variant-TARGET_WEAPONS), [`TargetType::TARGET_STICKY_AIM`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::TargetType##variant-TARGET_STICKY_AIM), [`TargetType::TARGET_GRAPPLE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::TargetType##variant-TARGET_GRAPPLE), [`TargetType::TARGET_MELEE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::TargetType##variant-TARGET_MELEE), [`TargetType::TARGET_GRENADE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::TargetType##variant-TARGET_GRENADE), and [`TargetType::TARGET_SNAP`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::TargetType##variant-TARGET_SNAP).

Every per-slot array on the struct is [`TargetType::NOF_TARGET_TYPES`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::TargetType##variant-NOF_TARGET_TYPES) long: [`PlayerAimControl::m_Target`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_Target), [`PlayerAimControl::m_AimPos`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_AimPos), [`PlayerAimControl::m_DirectPositions`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_DirectPositions), [`PlayerAimControl::m_MaxAimDistance`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_MaxAimDistance), and so on. There is exactly one weapon aim position, `m_AimPos[TARGET_WEAPONS]`. Its accessor is [`PlayerAimControl::GetAverageWeaponTargetPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-GetAverageWeaponTargetPosition), which returns that one entry; the name is historical, and the value is a single point.

The per-frame update is [`PlayerAimControl::UpdatePostSim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-UpdatePostSim), which runs, in order:

- [`PlayerAimControl::UpdateInput`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-UpdateInput), which folds stick input and applies dead zones.
- [`PlayerAimControl::UpdateRange`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-UpdateRange).
- [`PlayerAimControl::UpdateDirectAim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-UpdateDirectAim), the raycast.
- [`PlayerAimControl::UpdateAllTargets`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-UpdateAllTargets), the target selection and aim assist.
- `UpdateLastValidGrappleTarget` and [`PlayerAimControl::UpdateCrosshairLook`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-UpdateCrosshairLook).

### The raycast (`UpdateDirectAim`)

A single ray. [`PlayerAimControl::UpdateDirectAim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-UpdateDirectAim) fetches one matrix from [`PlayerAimControl::GetAdjustedCameraMatrix`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-GetAdjustedCameraMatrix) and derives both the origin and the direction from it. `GetAdjustedCameraMatrix` reads [`GameCameraManager::GetCameraMatrix`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/camera::game_camera_manager::GameCameraManager##func-GetCameraMatrix) (see "The camera getters" below) or [`GameCameraManager::GetAlternateAimMatrix`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/camera::game_camera_manager::GameCameraManager##func-GetAlternateAimMatrix) when the alternate-aim transform is active. For the current weapon ([`PlayerAimControl::GetCurrentWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-GetCurrentWeapon) with `TARGET_WEAPONS`) it adds a small ballistic pitch (`FOV × weapon tuning`). The pitch is a per-weapon-type offset, not a per-hand one. The direction is the matrix's `-Z` axis, normalised. The origin is the matrix translation moved 0.1 units along that direction.

`UpdateDirectAim` computes the origin inline. It does not call [`PlayerAimControl::GetRaycastStartPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-GetRaycastStartPosition), which applies the same 0.1 offset to the unadjusted `GetCameraMatrix`. `GetRaycastStartPosition` serves distance measurements instead: `GetAimDistance` and the grapple reticle's blend factors call it. `UpdateDirectAim` does call [`PlayerAimControl::GetRaycastMinDistanceStartPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-GetRaycastMinDistanceStartPosition), but not for the origin. That function returns a start point blended from the wielded weapon's barrel and the character's head. `UpdateDirectAim` divides the distance from the ray origin to that point by the ray length ([`PlayerAimControl::m_RayCastDistance`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_RayCastDistance)) and stores the result as `m_MinDistanceHitFractionLimit` on the raycast filter (`CPlayerAimRaycastFilterCacheFirstHoleyHitAndMinDistanceHit`). The filter records a hit below that fraction in its own fields (`m_HasHitMinDistance`, `m_MinDistanceHitFraction`); the filter's hit logic is not traced here.

`UpdateDirectAim` has one vehicle-specific step. When the character is in a vehicle and that vehicle is the rocket boat ([`Vehicle::IsRocketBoat`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##func-IsRocketBoat)), `UpdateDirectAim` raises the matrix translation's height to at least a water height, queried through [`PhysicsSystem_s_WaterQueryProxy`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/physics::PhysicsSystem_s_WaterQueryProxy), plus a constant before it computes the origin. IDA labels `IsRocketBoat` as `CWeaponBase::MarkNextWeaponComponentForFire`, but the function is a predicate on the vehicle.

[`PhysicsSystem::CastRay`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/physics::PhysicsSystem##func-CastRay) runs the ray. [`PlayerAimControl::CheckDirectTargets`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-CheckDirectTargets) writes the hit into `m_DirectPositions[TARGET_WEAPONS]` and `m_AimPos[TARGET_WEAPONS]`.

The ray's origin and direction both derive from `GetCameraMatrix`, so the whole raycast runs through the one camera transform.

### The camera getters

`GameCameraManager` splits its camera getters by phase:

- [`GameCameraManager::GetInputMatrix`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/camera::game_camera_manager::GameCameraManager##func-GetInputMatrix) reads [`m_NextRenderContext`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/camera::camera_context::CameraControlContext##field-m_NextRenderContext), the render-phase camera context. Movement-direction mapping uses this getter, so it follows the render-phase camera.
- [`GameCameraManager::GetCameraMatrix`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/camera::game_camera_manager::GameCameraManager##func-GetCameraMatrix) reads [`m_NextCameraContext`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/camera::camera_context::CameraControlContext##field-m_NextCameraContext), which the sim-phase camera update rewrites from the internal camera. Every sim-side aim consumer reads this getter: `PlayerAimControl` (the raycast above, plus `GetAdjustedCameraMatrix` and the target visibility casts), the weapon aim-target queries, and the melee and grapple tasks (see `docs/engine/gameplay/grapple-pipeline.md`).
- [`GameCameraManager::GetAlternateAimMatrix`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/camera::game_camera_manager::GameCameraManager##func-GetAlternateAimMatrix) reads `m_NextRenderContext.`[`m_AlternateAimTransform`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/camera::camera_context::CameraContext##field-m_AlternateAimTransform), part of the same render-phase context that `GetInputMatrix` reads.

### Body-turn reactions to the aim direction

[`NStateTask_LocoUtil::GetAimMoveAngle`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_LocoUtil##func-GetAimMoveAngle) measures the XZ angle from the move direction to the player's aim target, and the aim-relative act dispatchers (`QueueAimRelativeOnSpotActions`, `QueueRotateOnSpots`, `QueueStopTurns`, and related helpers) queue turn acts from it, so the game turns the body toward the aim direction whenever those acts run. The aim-relative family also turns the body a second way: it passes `track_face_dir` to the orientation executor with its own blackboard face dir, also derived from the aim reference, so the executor's continuous yaw turns the body toward the aim direction independently of the turn acts. Because the aim target derives from `GetCameraMatrix`, both reactions turn the body toward whatever direction that getter returns.

### Aim assist (`UpdateAllTargets`)

Assist is applied on the aim target, upstream of any weapon. [`PlayerAimControl::UpdateAllTargets`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-UpdateAllTargets) scores candidate game objects with per-purpose fitness functions (`SetTargetWeaponsFitness`, `SetTargetSnapFitness`, `SetTargetStickyFitness`, and others) driven by angle-to-camera-forward and distance, and picks `m_Target[TARGET_WEAPONS]`. The sticky and snap machinery then nudges `m_AimPos[TARGET_WEAPONS]` toward the selected target. Separately, [`NAutoAimToTarget_Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/aim::aim##func-NAutoAimToTarget_Update) is the character-state task that rotates the aim and camera direction toward a locked target. Both are computed once, from the single camera-derived aim, so magnetism is a property of the one gaze ray and not of any weapon.

Assist exists only on the camera-coupled path inside `PlayerAimControl`. A target point written downstream of it, into [`Character::m_AimTargetPositionWeapons`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AimTargetPositionWeapons) or a weapon's [`WeaponBase::m_AimTargetPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_AimTargetPosition), receives no assist.

The candidates are the [`TargetSystem`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::TargetSystem)'s three sets of [`Target`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::Target)s: characters, vehicles, and other objects. The wielded weapon's aim-assist tuning chooses which sets a pass walks, and the choice is left in the system's include flags. Each purpose has its own fitness function. The weapon, grenade, and snap purposes share [`PlayerAimControl::GetFitnessScore`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-GetFitnessScore), which scores the target inside a cone around the adjusted camera matrix's forward, higher being better. Melee uses [`PlayerAimControl::SetTargetMeleeFitness`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-SetTargetMeleeFitness) along a horizontal direction (the move input, or the body's forward), lower being better, over characters in the player's melee reach; `UpdatePostSim` clears the melee slot at its start, and the melee input task (`NStateTask_InputMeleeTask`, in the state-machine pass that runs before the post-camera pass) reads the slot the previous tick's pass wrote. The melee attack needs [`Character::CanUseMelee`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-CanUseMelee) and the hammer ability ([`AbilitiesHandler::IsAbilityEnabled`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::AbilitiesHandler##func-IsAbilityEnabled)).

## From aim control to the character: `CPlayer::UpdatePostCamera`

[`CPlayer::UpdatePostCamera`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/character::player##func-Player_UpdatePostCamera) is the hand-off, each frame after the camera update:

1. [`PlayerAimControl::UpdatePostSim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-UpdatePostSim) recomputes the target cache (above).
2. It reads `m_AimPos[TARGET_WEAPONS]` into a local `weapon_target_pos`, and copies it into [`ControlParameters::m_AimTargetWeapons`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::control_parameters::ControlParameters##field-m_AimTargetWeapons) of the character's control parameters ([`Character::m_ControlParameters`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_ControlParameters)). This second copy is the aim point the animation-side consumers see.
3. [`Character::UpdateWeaponAiming`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-UpdateWeaponAiming)`(character, &weapon_target_pos)`.
4. [`Character::UpdateGrenadeAiming`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-UpdateGrenadeAiming) writes the grenade point, `m_AimPos[TARGET_GRENADE]`, directly; it does not go through `UpdateWeaponAiming`.
5. For a driver, [`Vehicle::SetAimTargetPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##func-SetAimTargetPosition) (see "Vehicle, turret, mounted, wingsuit, and mech weapons" below).

`UpdateWeaponAiming` is a five-line setter. It writes the point into [`Character::m_AimTargetPositionWeapons`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AimTargetPositionWeapons) (a `CVector3f`) and raises the one-frame flag [`Character::m_AimTargetPositionWeaponWasSetThisFrame`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AimTargetPositionWeaponWasSetThisFrame). The grenade point lands in [`Character::m_AimTargetPositionGrenade`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AimTargetPositionGrenade).

The flag matters: if nothing set the weapon target this frame, `Character::UpdateWeapons_Serial` falls back to a point 25 m along the character's body forward (`m_WorldMatrixT1` forward). AI and remote players reach the same field through other callers (`CSniperAimer`, the AI action `AiSetAimTarget`); the player path is the `UpdatePostCamera` one above.

The single field `m_AimTargetPositionWeapons` is the narrowest global choke point for the player's weapon aim direction. Everything below reads it.

## The fan-out to weapons: `Inventory`

[`Character::UpdateWeapons_Parallel`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-UpdateWeapons_Parallel) passes `m_AimTargetPositionWeapons` and `m_AimTargetPositionGrenade` down as two `CVector3f`s to [`Inventory::Update_Parallel`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-Update_Parallel), which forwards them to [`Inventory::UpdateWeapons_Parallel`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-UpdateWeapons_Parallel). That function drives each active weapon with the same `aim_position_weapons` argument:

- the mounted-gun weapon (`GetWeaponInInventory(E_SLOT_HEAVY)`) receives `aim_position_weapons`;
- every wingsuit weapon (`m_Wingsuit->m_WingsuitWeapons[]`) receives `aim_position_weapons`;
- the wielding weapon (`GetWieldingWeapon(...)`) receives `aim_position_weapons`;
- the selected grenade receives `aim_position_grenade`.

Each call is `weapon->UpdateFromUserPostSim_Parallel(dt, aim_position, inputs)`, the [`WeaponBase::UpdateFromUserPostSim_Parallel`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-UpdateFromUserPostSim_Parallel) virtual, whose base implementation is [`WeaponBase::UpdateFromUserPostSim_ParallelBase`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-UpdateFromUserPostSim_ParallelBase). Inside, the weapon validates the point and stores it in its own [`WeaponBase::m_AimTargetPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_AimTargetPosition) (a `CVector3f`) via the `SetWeaponAimTargetPosition` write, which is inlined.

Every weapon therefore holds a private copy of the one shared point. The copy is real per-weapon state, written from a single source.

## Dual-wield

Dual-wield is a weapon slot, [`WeaponSlot::E_SLOT_DUAL_WIELD`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_DUAL_WIELD) (the first [`WeaponSlot`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot)), distinct from [`WeaponSlot::E_SLOT_TWO_HANDED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_TWO_HANDED), [`WeaponSlot::E_SLOT_HEAVY`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_HEAVY), and the others. A dual-wield equip is a single `WeaponBase` instance occupying that slot whose animation and fire pattern drive both hands, not two independent `WeaponBase`s. JC3's akimbo pistols are one weapon object with two guns ([`WeaponData`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData) entries), each with its muzzle fire points in [`WeaponData::m_InternalFirePositions`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##field-m_InternalFirePositions), alternated by the fire-point bookkeeping at the tail of `Fire_Projectile` (see "Dual-wield barrel bookkeeping" below). The inventory's `GetWieldingWeapon` returns that one instance, and it receives the one `aim_position_weapons`. Both barrels therefore fire toward the identical target. There is no second aim slot, and no per-hand target state on the weapon.

There is no per-fire-point aim target: `GetShotMatrix` reads the one `m_AimTargetPosition` for every fire point of the weapon.

## Fire direction, end to end (`GetShotMatrix`)

When a weapon fires, the launch transform is [`WeaponBase::GetShotMatrix`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-GetShotMatrix), called from the fire functions: [`WeaponBase::Fire_Projectile`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-Fire_Projectile) (base implementation [`WeaponBase::Fire_ProjectileBase`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-Fire_ProjectileBase)), [`BulletWeaponBase::Fire_Projectile`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::BulletWeaponBase##func-Fire_Projectile), and their siblings. JC3 has no separate hitscan path for small arms. Bullet weapons spawn fast projectiles through `Fire_Projectile`, so the muzzle-to-target construction below governs everything. [`BulletWeaponBase::GetTuning`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::BulletWeaponBase##func-GetTuning) decides explosive and water behaviour; [`NWeaponUtil::Trajectory_GetAngleToHitPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::NWeaponUtil##func-Trajectory_GetAngleToHitPosition) is called only from `BulletWeaponBase::Fire_Projectile`; thrown grenades use a different solver (see "Grenades" below). The raycast in `UpdateDirectAim` is only for the aim target and the reticle; it is not the projectile's ray.

`GetShotMatrix` builds the shot as follows:

- The origin is the [`WeaponBase::GetFireFromPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-GetFireFromPosition) virtual (base implementation [`WeaponBase::GetFireFromPositionBase`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-GetFireFromPositionBase)): the gun's world matrix composed with the current fire point from `m_InternalFirePositions`, which is the muzzle bone of this weapon's current fire point. It is per weapon and per barrel. Grip transforms for hand attachment come from the separate [`WeaponBase::GetGripPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-GetGripPosition); see `docs/engine/character/hands-locomotion-and-state.md`.
- The aim point is [`WeaponBase::m_AimTargetPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_AimTargetPosition), the stored shared target. For a remote player it is instead read off the network component.
- The direction is [`Matrix4::CreateOrientation`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/types::math::Matrix4##func-CreateOrientation)`(from = muzzle, at = aim point, up)`, so the shot points from this weapon's muzzle toward the shared target.
- Fallbacks and modifiers: if the aim point is within about 0.3 m of the muzzle, or the weapon is in [`ProjectileFireDirectionMode::E_PROJECTILE_FIRE_DIRECTION_BARREL`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::ProjectileFireDirectionMode##variant-E_PROJECTILE_FIRE_DIRECTION_BARREL) mode ([`WeaponBase::m_ProjectileFireDirection`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_ProjectileFireDirection), overridden by [`WeaponBase::m_ProjectileTempFireDirection`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_ProjectileTempFireDirection)), or `force_barrel_direction` is set, it uses the barrel-forward direction instead of the aim point (10 m along the weapon's own forward). [`WeaponBase::m_ProjectileOffsetFromAimPos`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_ProjectileOffsetFromAimPos) applies a spread ring, and scatter (`RotationYawPitchRoll` from tuning) is layered on unless suppressed.

`SetProjectileFireDirectionMode` and `ResetProjectileFireDirectionMode` set the barrel-direction mode per weapon instance. In that mode the weapon fires along its own barrel instead of at the aim point.

## The reticle

The HUD has one reticle, and it comes from the same single aim point. [`HUDUI::UpdateGrappleReticle`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##func-UpdateGrappleReticle) projects it to screen; the projected point and the projection call are in [grapple-pipeline.md, "The grapple reticle"](grapple-pipeline.md#the-grapple-reticle). The reticle projection is the first world-to-screen call of the frame; the later calls in the frame are the wire-attachment and grip-radius samples. There is one Scaleform reticle clip (`MCI_reticles`).

## Grenades

Thrown grenades take their target from the grenade slot, `m_AimPos[TARGET_GRENADE]`, which `UpdatePostCamera` stamps onto [`Character::m_AimTargetPositionGrenade`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AimTargetPositionGrenade) and the inventory passes to the selected grenade weapon as its `m_AimTargetPosition`. `CThrownGrenadeWeapon::Fire_Start` copies that into `m_GrenadeTargetPosition` (with a special case when grappling).

The throw itself is `CThrownGrenadeWeapon::Fire_Projectile`, which runs on the throw animation's release event (medium confidence: inferred from `CThrownGrenadeWeapon::HandleTrackMessage` and the fire acts, not traced end to end), so the grenade spawns at the hand's animated position on that frame. It places the primed grenade at the weapon's world matrix (the hand), then calls [`Grenade::PropelToward`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Grenade##func-PropelToward) with the target point and the character's velocity. That calls [`Explosive::PropelToward`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Explosive##func-PropelToward), which:

- stores the relative (character) velocity in [`Explosive::m_RelativeVelocity`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Explosive##field-m_RelativeVelocity) and raises [`Explosive::m_DeferredPropelTowards`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Explosive##field-m_DeferredPropelTowards);
- calls the virtual `VelocityToHitTarget` ([`Grenade::VelocityToHitTarget`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Grenade##func-VelocityToHitTarget), wrapping [`Explosive::VelocityToHitTarget`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Explosive##func-VelocityToHitTarget)) from the grenade's position to the target;
- stores the result in [`Explosive::m_DeferredInitialVelocity`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Explosive##field-m_DeferredInitialVelocity), which is applied to the physics body later, and resets the time since throw.

`Explosive::VelocityToHitTarget` clamps the target to the explosive's `m_Range` and chooses a flight time from the grenade weapon's arc tuning: `m_t_flat`, `m_t_up`, and `m_t_down`, blended by distance over `m_max_distance_for_blend` and by the elevation angle against `m_angle_up_max` and `m_angle_down_max`. Roof targets use a height-based time. It then solves the launch velocity with [`NWeaponUtil::Trajectory_GetVelocityToHitPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::NWeaponUtil##func-Trajectory_GetVelocityToHitPosition) (`(start, end, time, gravity_factor)`, using the physics world's gravity). `Grenade::VelocityToHitTarget` then adds the relative velocity unless the grenade has a homing target. `Grenade::PropelToward` also records the target in [`Grenade::m_InitialLandingPos`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Grenade##field-m_InitialLandingPos) and starts the homing search when the homing upgrade is enabled.

The only input to this chain is a target point; the flight time is chosen by the solver, so a given launch velocity cannot be requested through the target alone.

The throw animation drives the grenade weapon through two requests, each raised by a track message and serviced by the weapon's update from its user ([`ThrownGrenadeWeapon::UpdateFromUserPostSim_Parallel`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::ThrownGrenadeWeapon##func-UpdateFromUserPostSim_Parallel)), which runs on the player's post-camera pass right after the aim update:

- The prime request, [`ThrownGrenadeWeapon::m_PrimeGrenade`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::ThrownGrenadeWeapon##field-m_PrimeGrenade), is serviced after the base weapon update by [`ThrownGrenadeWeapon::PrimeGrenade`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::ThrownGrenadeWeapon##func-PrimeGrenade) (`CreatePrimed<CGrenade>`). Priming consumes one grenade and spawns the grenade live at the weapon's world matrix, stored in [`ThrownGrenadeWeapon::m_PrimedGrenade`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::ThrownGrenadeWeapon##field-m_PrimedGrenade). The spawn can fail when the ammunition pool is full. The grenade's fuse ([`Explosive::m_DetonationTimer`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Explosive##field-m_DetonationTimer)) runs from the spawn, so a grenade held longer than its fuse explodes before it is thrown; the quick release of the throw animation hides this. While primed, the weapon's attachment update ([`ThrownGrenadeWeapon::UpdateAttachmentTransforms`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::ThrownGrenadeWeapon##func-UpdateAttachmentTransforms)) sets the grenade's transform ([`Explosive::m_WorldMatrixT1`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Explosive##field-m_WorldMatrixT1)) to the weapon's world matrix.
- The fire request, [`WeaponBase::m_ForceFireProjectile`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_ForceFireProjectile), makes the base [`WeaponBase::UpdateWeapon_Parallel`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-UpdateWeapon_Parallel) call `Fire_Projectile` for each gun whatever the fire input. The base update runs before the prime is serviced, so a fire and a prime requested in one update release nothing and prime afterwards.

The primed grenade gets its physics body ([`Explosive::m_PfxInstance`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Explosive##field-m_PfxInstance)) on its first post-simulation update, one update after the spawn. `Explosive::PropelToward` and [`Explosive::SetPhysicsTransform`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::explosive::Explosive##func-SetPhysicsTransform) do nothing before then. Both only queue their effect for the body's next update, the transform first, so a later `SetPhysicsTransform` replaces an earlier one. [`ThrownGrenadeWeapon::CancelPrimedGrenade`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::ThrownGrenadeWeapon##func-CancelPrimedGrenade) removes a primed grenade and returns it to the inventory; the disassembler's label of that name sits on an unrelated hash-table clear. The grenade permission ([`Inventory::m_DoesAnimationAllowGrenades`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_DoesAnimationAllowGrenades)) gates only the throw input; neither request checks it, nor the ammunition ([`WeaponBase::GetTotalAmmo`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-GetTotalAmmo)).

## Vehicle, turret, mounted, wingsuit, and mech weapons

Vehicle built-in weapons. [`Vehicle::SetAimTargetPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##func-SetAimTargetPosition) writes the vehicle's [`Vehicle::m_AimingTargetPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##field-m_AimingTargetPosition) and sets [`Vehicle::m_AIVehicleWeaponAimTimeout`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##field-m_AIVehicleWeaponAimTimeout) to -1 for the driver seat or 2 s otherwise. `CPlayer::UpdatePostCamera` only calls it when the vehicle's [`Vehicle::m_LocalPlayerSeat`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##field-m_LocalPlayerSeat) is the driver seat. `CVehicle::UpdatePostCamera_Weapons_Parallel` then passes that point to every built-in weapon that has a user through `UpdateFromUserPostSim_Parallel`, substituting the position of `m_AimingTargetObject` when a lock-on target is set. For AI drivers the point decays to 10 m ahead of the vehicle when the timeout lapses.

Turrets. [`TurretWeaponComponent::UpdateTurretAiming`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::TurretWeaponComponent##func-UpdateTurretAiming) rotates the turret toward the owning weapon's aim target at a rate-limited speed, so the barrel lags the point.

Mounted guns and the wingsuit. A mounted gun is in the heavy slot ([`WeaponSlot::E_SLOT_HEAVY`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_HEAVY)) and each wingsuit gun is in `m_Wingsuit->m_WingsuitWeapons[]`; both receive the character's shared `m_AimTargetPositionWeapons` in the inventory fan-out above.

Mech gravity gun. The mech is a vehicle; its gravity gun is the second built-in weapon, with a `CMagnetWeaponComponent`, and its upper body turns with [`Vehicle::GetWeaponTurretCurrentYawAngle`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##func-GetWeaponTurretCurrentYawAngle). For the player it is aimed by the vehicle aim point like any other built-in weapon. This is medium confidence: the AI path [`AIMechFireGravityGun`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/ai::ai##func-AIMechFireGravityGun) was read, and the player path was inferred from the built-in weapon loop.

## Precision aim and sniper zoom

[`Action::PRECISION_AIM`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-PRECISION_AIM) is one of the weapon inputs. When the input is present, [`Character::CanPrecisionAim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-CanPrecisionAim) holds (the `precision_aim` upgrade, or a weapon with a precision camera hash), and the animation allows it, `Inventory` toggles [`Player::SetAimMode`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::Player##func-SetAimMode). [`Player::UpdateAimMode`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::Player##func-UpdateAimMode) drops back to mode 0 when precision aim stops being possible. `SetAimMode`:

- refuses mode 1 while falling or freefalling outside a parachute, or with no weapon in the [`E_SLOT_DUAL_WIELD`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_DUAL_WIELD), [`E_SLOT_TWO_HANDED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_TWO_HANDED), [`E_SLOT_TWO_HANDED_SPECIAL`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_TWO_HANDED_SPECIAL), or [`E_SLOT_PLANTED_EXPLOSIVE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_PLANTED_EXPLOSIVE) slots;
- writes [`Player::m_AimMode`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::Player##field-m_AimMode) and a timestamp ([`Player::m_AimModeChangeTime`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::Player##field-m_AimModeChangeTime));
- in mode 1 adds the camera hint [`GameCameraManager::PRECISION_AIM_HINT_ID`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/camera::game_camera_manager::GameCameraManager::PRECISION_AIM_HINT_ID) through [`GameCameraManager::AddHint`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/camera::game_camera_manager::GameCameraManager##func-AddHint), and removes it in mode 0; any zoom is in that camera state's data;
- sets the aim control's [`PlayerAimControl::m_AimType`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_AimType) to [`AimType::ENormal`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::AimType##variant-ENormal) (assist off) in mode 1 unless the weapon enables auto-aim in precision mode ([`WeaponBase::m_IsAutoAimInPrecisionAimEnabled`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_IsAutoAimInPrecisionAimEnabled)), and to [`AimType::EAuto`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::AimType##variant-EAuto) in mode 0, subject to the aim-assist setting;
- calls the weapon's virtual [`WeaponBase::SetAimMode`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-SetAimMode).

[`SniperWeapon::SetAimMode`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::SniperWeapon##func-SetAimMode) shows the HUD sniper overlay ([`HUDUI::ShowSniperOverlay`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##func-ShowSniperOverlay)) and hides the player character (`CCharacter::SetVisible(0)`) in mode 1, and reverses both in mode 0 ([`HUDUI::HideSniperOverlay`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##func-HideSniperOverlay)). A bolt-action sniper can drop out of precision aim to cycle and return to it afterwards (`m_ShouldgoBackToPrecisionAim`).

Mode 1 is requested from three places, all through `SetAimMode`: the inventory's weapon handling on the precision-aim input, only for a weapon with [`WeaponBase::m_SupportsPrecisionAim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_SupportsPrecisionAim); `CSniperWeapon::UpdateFromUserPostSim_Parallel`, returning after a bolt-action cycle it left precision aim for; and `CRPGBloodhoundWeapon::Fire_Projectile`, which enters precision aim on every shot of the guided rocket launcher. Every other caller passes mode 0. A scoped rifle is a weapon of class [`WeaponClass::E_WEAPON_CLASS_SNIPER`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponClass##variant-E_WEAPON_CLASS_SNIPER) ([`WeaponBase::m_Class`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_Class)), a `CSniperWeapon`. The engine has no second scene view to render a scope through: the zoom is the main camera's hint, and the only render-to-texture class is the Scaleform UI's.

## Fire-point bookkeeping

### Dual-wield barrel bookkeeping

[`Vehicle::IsRocketBoat`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##func-IsRocketBoat), which IDA labels `CWeaponBase::MarkNextWeaponComponentForFire`, does not alternate the akimbo fire points. It is a const predicate on the holder's vehicle: it mutates nothing and returns whether [`Vehicle::m_VehicleTypeNameHash`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##field-m_VehicleTypeNameHash) equals `HashString("v1706_boat_na_rocketboat")`. In `Fire_Projectile` it is called only inside the `IsHolderVehicle` branch, to select which pair of `CPlayerActionObserver::OnAction` actions to post for the rocket boat. It has nothing to do with akimbo pistols.

The actual barrel and fire-point alternation (`MarkNextWeaponComponentForFire`) is inlined at the tail of [`WeaponBase::Fire_ProjectileBase`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-Fire_ProjectileBase):

- [`WeaponBase::m_NextWeaponToFire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_NextWeaponToFire) is the index of the current gun in [`WeaponBase::m_lWeaponData`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_lWeaponData). [`WeaponBase::m_LastWeaponToFire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_LastWeaponToFire) is set to that index before it advances, so it records the last-fired gun.
- `m_lWeaponData` is a [`WeaponDataArray`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponDataArray) of `WeaponData` pointers; the gun count is the span from [`WeaponDataArray::m_Begin`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponDataArray##field-m_Begin) to [`WeaponDataArray::m_End`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponDataArray##field-m_End).
- Within the current gun, its fire-point cursor [`WeaponData::m_InternalFirePositionCurrentIndex`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##field-m_InternalFirePositionCurrentIndex) advances: `cursor = (cursor + 1) % nFirePositions`, where `nFirePositions` is the length of [`WeaponData::m_InternalFirePositions`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##field-m_InternalFirePositions), an array of [`InternalFireInformation`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::InternalFireInformation). First, the selected fire point's [`InternalFireInformation::m_TimeSinceLastFire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::InternalFireInformation##field-m_TimeSinceLastFire) is reset to zero.
- Then `m_NextWeaponToFire = (m_NextWeaponToFire + 1) % count`, with a special-case reset to 0 when the weapon's [`WeaponBase::m_EquipSlot`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_EquipSlot) is `E_SLOT_DUAL_WIELD` and its [`WeaponBase::m_State`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_State) is [`WeaponState::E_WS_WIELDING`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponState##variant-E_WS_WIELDING).
- [`WeaponBase::GetFireFromPositionBase`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-GetFireFromPositionBase) reads the cursor to pick which `m_InternalFirePositions[cursor]` is the muzzle. The barrel for the current shot is therefore the gun index plus that gun's cursor as they stand when the shot is built; the tail advance sets up the next shot.

### Per-shot bookkeeping and the barrel index

Nothing double-counts. All the per-shot bookkeeping runs once per `Fire_Projectile` call, keyed off the weapon (`this`) and the `WeaponData` gun passed as `weapon_data`, not off the barrel or fire-point index:

- Ammunition: the [`WeaponBase::ConsumeAmmo`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-ConsumeAmmo) virtual deducts rounds once per call. The forced-fire shot count [`WeaponBase::m_ForceFireCount`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_ForceFireCount) and the projectile-offset shot count [`WeaponBase::m_ProjectileOffsetFireCount`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_ProjectileOffsetFireCount) each decrement once per call.
- The recoil and scatter accumulators ([`WeaponBase::m_CurrentScatterValue`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_CurrentScatterValue), [`WeaponBase::m_CurrentRecoilPitchValueToRecover`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_CurrentRecoilPitchValueToRecover), [`WeaponBase::m_RecoilYaw`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_RecoilYaw), and [`WeaponBase::m_RecoilPitch`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_RecoilPitch)) advance once per call.
- Effects, heat, and stats: `CWeaponData::PlayFireEffect(weapon_data, ...)`, `RumbleFire`, `CameraShakeFire`, `AddHeatPoints`, and `Fire_Projectile_Log_Statistics` each run once per call.

The gun index ([`WeaponBase::m_NextWeaponToFire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_NextWeaponToFire) and [`WeaponBase::m_LastWeaponToFire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_LastWeaponToFire)) and the fire-point cursor ([`WeaponData::m_InternalFirePositionCurrentIndex`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##field-m_InternalFirePositionCurrentIndex)) only select a position. They choose the muzzle origin (`GetFireFromPosition` reads the cursor), where the muzzle flash plays (the `weapon_data` gun), and which fire point's [`InternalFireInformation::m_TimeSinceLastFire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::InternalFireInformation##field-m_TimeSinceLastFire) is reset. Forcing the same barrel repeats the same muzzle bone and resets the same fire point's timer; it neither adds nor skips an ammunition deduction or a recoil kick.

The muzzle origin and the fire effects come from two separate sources. `GetFireFromPosition` picks the muzzle from the current gun index (`m_NextWeaponToFire`) and that gun's cursor. `PlayFireEffect` uses the `WeaponData` gun passed as `weapon_data`, which the inventory fire dispatch chooses upstream. The cursor advance and the timer reset apply to the gun at `m_NextWeaponToFire`, not to `weapon_data`. When `m_NextWeaponToFire` and `weapon_data` refer to different guns, the muzzle origin and the flash come from different barrels. `m_LastWeaponToFire` records the last-fired gun.

JC3 barrel alternation has no ammunition, recoil, or heat coupling. The barrel choice affects only the muzzle origin and the placement of the fire effects.
