# The animation graph and the weapon

A character's animation layers ([animation-layers.md](animation-layers.md)) are state machines loaded from `.afsmb` files, with each state's clips in a matching animation set (`.asb`). Rico's graphs and sets are in `animations/jc_statemachine/main_characters/rico/` (`patch_win64/game1`); the decoder is [`tools/anim_graph`](../../../tools/anim_graph). Related: [weapon-attachment-and-arm-ik.md](weapon-attachment-and-arm-ik.md) (the attach bones and the bone tasks) and [aim-state.md](../gameplay/aim-state.md) (the aim flags and the inventory permissions).

## The state machine format

An `.afsmb` is an RTPC property container whose root holds one object, the state machine, read by `NAnimationSystem::CStateMachine::Load`, `CStateMachine::LoadStateTransitions`, and `CTransition::Load` (the property name hashes are in `tools/anim_graph/afsmb.py`).

- The state machine's children are the lists of conditions, states, transitions, state tasks, and transition event names. Everything refers to an entry by its list position, so the lists must be read in stored order (the Gibbed converter's XML sorts children by name and scrambles them, so the decoder parses the binary).
- Condition classes, state classes (`CState`, `CAnimationState`, `CVariableSpeedState`, `CControlTimePerSamplerState`, `CVerticalAimBlendState`, and others), and task types are parallel tables, one hash per entry; the condition table has a second table of (class, count) pairs. A class hash is `HashString` of the class name (`hashlittle` with a zero seed); hashing every class name in the symbol dump resolves every class in Rico's graphs. A task type's hash is not of its name: the engine's state-task registration table pairs it with its `CStateTask_<NAME>` string and entry points. Each condition object carries its name (`C_WEAPON_WIELDED`) and its settings (a slot, a weapon id, a segment name, a distance); condition, state, and act names are stored as strings.
- A state carries a (first, count) range into the transition-pointer table (its outgoing transitions) and its task indices.
- A transition carries a (first, count, valid-on mask) range into the condition-pointer table and an all-of or any-of evaluation method. Bit *j* of the mask is the value the *j*-th condition must have, so a condition can be required false. Two per-transition tables give the destination state and the firing event, an index into the event names (an act such as `ACT_STOP`, or `ACT_UPDATE`, evaluated every update).
- The state machine carries the ranges of its global transitions (taken from any state) and its external transitions, and the index of its initial state.

The index tables are byte arrays of big-endian 16-bit indices.

## The on-foot idle

### The idle's clip variants

Rico's on-foot idle is one base-graph state, `S_IDLE`, whose clip is chosen by animation modifiers. Its node in `rico_base.asb`, `ANIM_IDLE`, plays the unarmed relaxed idle (`locomotion/idle/rico_loco_idle_noncombat.ban`, a full-body clip) and lists one variant node per combination of active modifiers; those that matter on foot:

| Active modifiers | Lower body | Upper body |
|---|---|---|
| none of the below | the unarmed relaxed idle (full body) | the same clip |
| a weapon's held modifier (`WEAPON_MODIFIER_ASSAULT`, `_REV`, `_RPG`) | `rico_loco_idle_rifle_noaim_lower` | the weapon class's held arms and head-torso, and its hand pose |
| a weapon's aim modifier (`WEAPON_MODIFIER_AIM_ASSAULT`, `_AIM_REV`, `_AIM_RPG`) | `rico_loco_idle_rifle_aim0_lower` | the aimed arms or upper body |
| the explosive's modifier (`WEAPON_MODIFIER_C4`) | `rico_loco_idle_rifle_aim0_lower` | the explosive priming arms |
| `GRAPPLE_MODIFIER`, alone or with an equipped modifier | `rico_loco_idle_rifle_aim0_lower` | the grapple arm |
| `STUNT_COMBAT_MODIFIER` or `STUNT_NONCOMBAT_MODIFIER` | the stunt idles | the stunt idles |

So every armed idle is a combat stance. Nearly every base-graph node has such variants, per weapon class rather than weapon: every rifle, submachine gun, shotgun, and sniper rifle shares the `ASSAULT` set (with its `AIM_` and `EQUIPPED_` forms), and the pistols and revolvers the `REV` set. A variant swaps the node's lower, arms, head-torso, and hand clips together.

Measured from its keyframes, the unarmed `rico_loco_idle_noncombat` stands bladed too: the ankles are 46 cm apart on a line turned 42 degrees from the root's facing, the left foot 31 cm ahead of the right, the right toe turned 51 degrees out, the hips 24 degrees and the shoulders 16 to 19 degrees right of the root. No idle in Rico's set stands square; the game's one neutral idle is the civilians' `civ_male_loco_idle_observe_loop`: the ankles 29 cm apart, the left foot 8 cm ahead, the toes 14 and 8 degrees out, the hips 1 degree and the shoulders 2 degrees off the root.

The foot IK keeps that stance: the locomotion IK task ([`NLocoIKTask_Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/animation::arm_aim_ik##func-NLocoIKTask_Update)) casts a ray down under each foot and queues ankle, toe, and hip targets at the clip's own joints moved only up or down to the ground.

`S_IDLE_AIM_FOCUS` (node `ANIM_IDLE_AIM_FOCUS`, no variants) plays only the minigun's idle; other weapons' aimed idle is `S_IDLE` with an aim modifier.

### What sets the modifiers

[`Character::SetCharacterModifiers`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-SetCharacterModifiers) runs once per tick from `CCharacter::UpdatePassPreStateMachines_Parallel`, after the aim input and before the state tasks, setting every modifier frame-bound ([`AnimationModifierType::FRAME_BOUND`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::rule_system::AnimationModifierType##variant-FRAME_BOUND)), so the set is rebuilt each tick:

- `GRAPPLE_MODIFIER` while the hook is in its aiming state ([`GrapplingHook::IsHookAimingState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-IsHookAimingState), a live tether).
- For the wielded weapon (the planted explosive while planting; otherwise the selected slot's weapon while it is wielded, dual-wielded, or mounted; otherwise the weapon being switched to or drawn), through [`Character::SetModifier`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-SetModifier): the weapon's [`WeaponBase::m_AimAnimationModifier`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_AimAnimationModifier) when [`Character::IsTryingToAim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsTryingToAim) holds and the hook is not aiming, its [`WeaponBase::m_AnimationModifier`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_AnimationModifier) otherwise, and always its [`WeaponBase::m_EquippedAnimationModifier`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_EquippedAnimationModifier).
- For characters other than the player, a faction or ghost modifier.
- `RELAX_MODIFIER` while the avatar's mental state is [`MentalState::E_RELAXED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::avatar::MentalState##variant-E_RELAXED). `ANIM_IDLE` lists no variant for it.
- A stunt modifier, combat with a weapon and non-combat without, while attached to a vehicle or while stunt mode is forced.

`Character::SetModifier` forwards to [`AnimationRuleSystem::SetModifier`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::rule_system::AnimationRuleSystem##func-SetModifier) for every rule system of the animated model ([`AnimatedModel::m_RuleSystems`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AnimatedModel##field-m_RuleSystems), the body's first), which sets the type's bit in its modifier map; the grapple, relaxed, and stunt modifiers go to the rule systems directly. `IsTryingToAim` follows the aim flag and the trigger ([aim-state.md, "Related queries"](../gameplay/aim-state.md#related-queries)), not the lower body's state family.

### Reaching the idle

When the stick is released, the on-foot movement task's stop branch queues the aim-relative stop turns while the aim flags report aiming and the plain stops otherwise; with a weapon wielded both queue a stop-turn act. From the move states (`S_MOVE_NO_AIM`, `S_MOVE_NON_COMBAT`, and `S_MOVE_STRAFE`), `ACT_STOP` leads to `S_WALK_STOP` while walking and `S_RUN_STOP` otherwise, and the stop turns (`ACT_STOP_TURN_0`, `_90L`, and `_90R`) to `S_WALK_TO_STOP_TURN_0` or `S_RUN_TO_STOP_TURN_0`. Each leaves on `ACT_UPDATE` once its clip has finished (`C_WAIT_FOR_ANIM_TO_FINISH`): to `S_IDLE`, or to `S_IDLE_AIM_FOCUS` with a heavy weapon selected and the grapple inactive. Until then they check the move states' fall, water, and stunt exits, and a flick act during the run's stop turn plays a flick turn instead (the unarmed one with nothing wielded, the `_NO_AIM` one with a weapon and no aim).

In `S_IDLE` the idle task ([`NStateTask_InputLocoIdleTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_InputLocoIdleTask##func-Update)) only runs the idle variation countdown while standing still with the aim flags clear, outside precision aim, and without a heavy weapon; with the aim flags it queues the reset rotate-on-spot acts toward the aim, and with a heavy weapon the aim-relative on-spot acts.

The relaxed clip plays only with nothing wielded, which normal play reaches by auto-holstering once the mental state turns relaxed ([aim-state.md, "The mental state"](../gameplay/aim-state.md#the-mental-state)).

## Conditions that read the weapon

Every weapon condition in Rico's graphs reads the character's selected slot ([`Character::m_SelectedWeaponSlot`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_SelectedWeaponSlot)) through [`Character::GetWeaponInInventory`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-GetWeaponInInventory), not the weapon a hand holds. "Wielded" means a weapon state of [`E_WS_WIELDING`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponState##variant-E_WS_WIELDING), [`E_WS_DUAL_WIELDING`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponState##variant-E_WS_DUAL_WIELDING), or [`E_WS_MOUNTED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponState##variant-E_WS_MOUNTED), and the planted explosive counts while [`Character::IsPlantingExplosive`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsPlantingExplosive) holds.

| Class | Rico's conditions | True when |
|---|---|---|
| [`WeaponWieldedCondition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon_animation::WeaponWieldedCondition##func-Evaluate) | `C_WEAPON_WIELDED` (any slot), `C_PLANTED_EXPLOSIVE_WIELDED` | for any slot, [`Character::GetWieldingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-GetWieldingWeapon) is not empty; for a slot, the selected weapon is wielded and belongs to it |
| [`WeaponSelectedCondition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon_animation::WeaponSelectedCondition##func-Evaluate) | `C_DUAL_WIELD_WEAPON`, `C_TWO_HANDED_WEAPON`, `C_HEAVY_WEAPON`, `C_PLANTED_EXPLOSIVE` and `C_PLANTED_EXPLOSIVE_WEAPON`, `C_TWO_HANDED_SPECIAL_WEAPON` | the selected slot's weapon belongs to the slot, in any state, so a holstered weapon counts |
| [`WeaponTypeCondition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon_animation::WeaponTypeCondition##func-Evaluate) | one `C_<WEAPON>` per weapon in the partial global graph; `C_RPG_GUITAR_CASE` and `C_STUPKA_210` in the base graph | the selected slot's weapon, in any state, has the weapon id |
| [`WeaponWieldedInLeftHand`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon_animation::WeaponWieldedInLeftHand##func-Evaluate) | `C_LEFT_HAND_WIELD` (partial global only) | the wielded weapon's first gun sits on the left hand ([`WeaponBase::IsWieldedInLeftHand`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-IsWieldedInLeftHand)) |
| [`WeapoIsTryingToFireCondition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeapoIsTryingToFireCondition##func-Evaluate) | `C_IS_TRYING_TO_FIRE` | a wielded weapon and a fire input the animation allows |

`IsWieldedInLeftHand` compares the first gun's current attach bone ([`WeaponData::m_lBoneAttachementPerWeaponState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##field-m_lBoneAttachementPerWeaponState)) with the left hand's. It holds after a `clear_right_hand` bone task and never looks at the dual-wield pair's second pistol.

The graphs also use `CWeaponNextSelectedCondition` (`C_NEXT_SELECTED_*`, the slot being switched or drawn to), `CWeaponMagazineEmptyCondition` (`C_AMMO_IN_MAGAZINE`), `CWeaponHasMagazineInsertedCondition` (`C_HAS_MAGAZINE_INSERTED`), and `CAimingCondition` (`C_IS_AIMING`, `C_IS_AIMING_WEAPONS`); what they test is unverified. `CWeaponEquippedCondition` exists but no Rico graph uses it. The partial sync and additive graphs have no weapon conditions.

## What the weapon conditions select in the base graph

- `C_WEAPON_WIELDED` splits every on-foot family into combat and non-combat: `S_MOVE_NO_AIM` against `S_MOVE_NON_COMBAT`, the combat walk starts against the `_NON_COMBAT` ones, the start-to-move exits, the `_NO_AIM` flick turns against the unarmed ones, and the stunt turns. The no-aim strafe (`S_MOVE_STRAFE`) is entered only unarmed, and the motorbike's aim states (`S_AIM_*_RIDING_MOTORBIKE`) need a wielded weapon. The move states swap families on the next move act (`S_MOVE_NON_COMBAT` takes `ACT_MOVE_NO_AIM` to `S_MOVE_NO_AIM` while it holds, and the reverse); the idle changes clips through the modifiers only.
- The combat states' default clips are themselves armed: `ANIM_WALK_START_0` plays the rifle no-aim walk start's lower, head-torso, and arms clips with no modifier active, `ANIM_FLICK_120L_NO_AIM` the rifle no-aim flick, and `ANIM_MOVE_NO_AIM` and the walk starts the rifle hand pose; so with any weapon wielded the walk starts and flick turns, root motion included, are rifle clips.
- `C_HEAVY_WEAPON` (the selected slot is the heavy slot, in any state) replaces the idle with `S_IDLE_AIM_FOCUS`, takes the aim-strafe moves to `S_MOVE_AIM_FOCUS*`, and blocks the idle's equip and unequip transitions: `ACT_ON_EQUIP_WEAPON` from `S_IDLE` and its no-aim transitions to `S_IDLE_TRANS_TO_AIM` need it false.
- `C_PLANTED_EXPLOSIVE_WIELDED` swaps the grapple-attach and upside-down stunt states for their planted-explosive variants, and blocks the upside-down rotations, the reel to a helicopter, and some stunt-to-driver moves.
- `C_RPG_GUITAR_CASE` and `C_STUPKA_210` gate the mortar states.
- No weapon condition guards a transition into the ledge climbs, the parachute, the wingsuit, swimming, or a vehicle entry.

## The base layer's weapon tasks

These base-graph tasks act on the inventory on entering their state; no other graph carries them.

- `NWeaponUnequipTask` ([`NWeaponUnequipTask_OnEnter`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon_animation::NWeaponUnequipTask_OnEnter)) acts on the wielded weapon, in 220 states. The 208 with `Instant` set unequip a player's weapon at once ([`WeaponBase::OnUnequip`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-OnUnequip)): every vehicle entry, seat, and seat change, every grapple reel into a seat, onto a motorcycle, or into a helicopter, the vehicle exits that roll out or hang, the motorbike, pogostick, and cow rides, the mounted-gun pickups and seats, the stunt positions' entries and melee, the wingsuit openings (including the one from the parachute, the only parachute state to carry it) and its boost, barrel-roll, evade, and flinch states, free fall and fast fall (`S_FALL_TO_FREEFALL`, `S_FREE_FALLING`, `S_FAST_FALLING`, `S_JC_SEQUENCE_TO_FREEFALL`, `S_RAGDOLL_TO_FREEFALL`), the dives under water, the hit-reaction flights, the ragdoll, the get-up, dying, and the guitar case's exit. The 12 without it queue `UB_ACT_HOLSTER` instead: the mounted-gun entries, the pogostick and cow rides, the crawl, and the three surface-swim starts. Both return the player to normal aim ([`Player::SetAimMode`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::Player##func-SetAimMode)). Opening the parachute itself puts nothing away.
- `NDropWeaponStateTask` ([`NDropWeaponStateTask_OnEnter`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon_animation::NDropWeaponStateTask_OnEnter)) is configured for the heavy slot ([`E_SLOT_HEAVY`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_HEAVY)) and drops its weapon in any state through [`Inventory::DropWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-DropWeapon), in 133 states, 69 of which also unequip: every grapple and tether fire, grenade throw, fall, free fall and fast fall, parachute opening and parachute-to-fall, wingsuit opening, boost, and fall, reel-in to a fall, vehicle and motorbike entry, surface swim, crawl, and hit-reaction flight and stumble. That it takes a holstered heavy weapon too is read from the code, not seen in game.
- `NStopUsingWeaponStateTask` ([`NStopUsingWeaponStateTask_OnEnter`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon_animation::NStopUsingWeaponStateTask_OnEnter)) stops using the selected weapon in the 19 ragdoll, crash, dying, drowning, and get-up states.
- `NWeaponHideInVehicleTask` ([`NWeaponHideInVehicleTask_OnEnter`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon_animation::NWeaponHideInVehicleTask_OnEnter)) has two instances, one for the two-handed slot and one for the special slot, in the same 63 states, every one a seat, a seat change, or a seat's entry or exit. In a vehicle with [`Vehicle::m_HideCharacterWeapons`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##field-m_HideCharacterWeapons) set it makes that slot's holstered weapon holstered-invisible until the state exits.
- `NSetWeaponStateTask` runs in `S_GUITAR_CASE_EXIT` alone.
- `NSetWeaponPredefinedBoneTask` moves guns between hand and holster bones (modes and states in [weapon-attachment-and-arm-ik.md, "The attach-bone table is rewritten every pass"](weapon-attachment-and-arm-ik.md#the-attach-bone-table-is-rewritten-every-pass)).
- `NWeaponOffhandIKTask`, `NAimIKTask`, and `NStateTask_InputWeaponTask` (the base layer's weapon input) run in many states each.

`NWeaponEquipTask` ([`NWeaponEquipTask_OnEnter`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon_animation::NWeaponEquipTask_OnEnter)) and `NInventorySelect` occur in none of Rico's graphs, so the player's graph never equips a weapon itself. The inventory permission tasks (`NSetInventoryPermissions`) are its other inventory effect ([aim-state.md](../gameplay/aim-state.md)).

## The upper-body actions

`rico_partial_global` holds the upper-body actions: the `S_UB_*` draw, holster, and switch states (per source and destination slot, with parachute variants), the reloads (per weapon family, with `_LEFT` variants), the shotgun pump, the sniper bolt, the pickups (per weapon id), the grenade throws, the explosives, and the parachute's arm states. Its initial state, `S_GLOBAL_PARTIAL_NULL`, is its idle; its transitions key on the per-weapon `C_<WEAPON>` conditions, `C_WEAPON_WIELDED`, the next-selected and magazine conditions, and `C_LEFT_HAND_WIELD`, which selects the left-handed reload and pump states (`S_UB_RELOAD_RIFLE_LEFT`, `S_UB_RELOAD_RIFLE_BACK_LEFT`, `S_UB_RELOAD_SHOTGUN_START_LEFT`, `S_UB_RELOAD_MACHINE_GUN_VDOVA_89_LEFT`, `S_UB_RELOAD_GRENADE_LAUNCHER_UPU210_LEFT`, and `S_UB_SHOTGUN_PUMP_LEFT`). Per-weapon clips exist only in this layer, keyed by weapon id.

Every `S_UB_*` state has an unconditional transition on `ACT_ABORT_WEAPON_PARTIAL` back to `S_GLOBAL_PARTIAL_NULL`; the parachute arm states, the detonations, and the explosive reloads (`S_JC_UB_*`) do not. Their effects on the weapon are their clips' track messages, which [`WeaponBase::HandleTrackMessage`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-HandleTrackMessage) answers: the draw clip's equip message calls the equip virtual ([`OnEquip`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-OnEquip)) and the holster clip's unequip message the unequip virtual; others refill the magazine (`CWeaponBase::Reload`), eject magazines, fire attached effects, complete pickups, and detach mounted guns. The reload states' exit task (`NWeaponReloadFinishedTask`) ends the reload sequence, so a reload whose clip does not play never refills. A message's target picks its weapon: a fixed slot, the selected slot, the wielded weapon, the grenade slot, or the interaction's weapon (unverified). A playing clip therefore equips or unequips its slot's weapon when the message fires, whatever happened since.

The draw act ([`Character::DrawWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-DrawWeapon) queues `UB_ACT_DRAW`) adds the `S_UB_DRAW_*` state's visual, the drawing state bit for the state's length, permission blocks for the draw, a bone task on the two-handed draws, and `ACT_ON_EQUIP_WEAPON` to the base layer, which from `S_IDLE` plays `S_IDLE_TRANS_TO_AIM` and which no other base state listens for. None of it is a precondition of a later state; selecting a slot alone ([`Character::SetSelectedWeaponSlot`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-SetSelectedWeaponSlot)) plays nothing and equips nothing.

The layer's animation set, `rico_partial_global.asb`, is in no archive's file table under that name (the tables hold `rico_base.asb` and `rico_partial_sync.asb` only), appearing only in a resource dependency list; unrecovered, so which bones its clips drive is unverified.

## Recoil and the vertical aim blend

The firing kick is an additive, not a state. Rico's additive graph is almost entirely vertical aim blend states (`CVerticalAimBlendState`), and its aim nodes in `rico_additive_sync.asb` carry one recoil clip per gun: `rico_loco_idle_rev_aim0_recoil_rarm_add` and `rico_loco_idle_rev_aim0_recoil_larm_add` for the pistols' modifier, `rico_loco_idle_rifle_aim0_recoil_add` and its run variant for rifles, `rico_loco_run_rpg_aim0_recoil_add` for launchers, and parachute and motorbike variants.

[`VerticalAimBlendState::UpdateSamplers`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::VerticalAimBlendState##func-UpdateSamplers) drives them: with the state's recoil flag set and a weapon wielded it runs one recoil sampler per gun of the wielded weapon ([`WeaponBase::GetNumRecoilAnimationNeeded`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-GetNumRecoilAnimationNeeded)), each at its gun's own time since its last shot ([`WeaponData::m_TimeSinceLastFire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##field-m_TimeSinceLastFire)) and at the weapon's maximum recoil weight until the clip ends. The aim's yaw and pitch are measured from the left arm when the wielded weapon sits in the left hand, from the right arm for a heavy weapon and the grapple fire, and from the head otherwise. So recoil is per gun but follows the one wielded weapon and plays only inside the aim states.

## Clips, body parts, and the hand poses

An animation node in an `.asb` lists up to about a dozen clip slots, each a separate Havok spline-compressed clip with a binding naming the bones it drives. The body is split by clip, not bone mask: Rico's on-foot nodes play a lower-body clip, a head-torso clip, an arms clip, and a hand-pose clip from `hands_bank/`, and some nodes use `noarms`, `larm`, `rarm`, `upper`, `torso`, or `head` splits instead. The splits are inferred from the clip names; only the hand-pose clip's binding was read.

`hands_bank/hands/pose_hands_rico_rifle_right_hands.ban` binds every finger bone of both hands (the thumb, index, middle, ring, and pinky chains, with the ring's and pinky's in-hand bones) and nothing else. The hand poses are one clip per weapon class, both hands together: `rifle_right`, `rifle_left` (used once, in a grapple-attach state that moves the rifle to the left hand), `rev` (the pistols), `rpg`, `expl_prime`, `noncombat`, and grapple variants. 

## Playing a clip from code

[`AnimationController::PlayCustomAnimation`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AnimationController##func-PlayCustomAnimation) plays a clip by path on a layer: it acquires the clip resource, builds an [`AnimationInstance`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::pose_producer::AnimationInstance##func-Construct) of it over the controller's skeleton, and hands it to the layer's driver ([`AnimationDriverTransition::PlayCustomAnimation`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::pose_producer::AnimationDriverTransition##func-PlayCustomAnimation)) with a blend time. The instance's creation context carries its easing, start and finish trims, speed, mirror flag (which binds the clip mirrored), and loop mode. (The acquiring call is labelled `CAnimationTrack::GetHandle` by the disassembler, which does not fit; what it is beyond this is unverified.) A path's clip resource also comes from [`AquireAnimation`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::pose_producer::AquireAnimation), from the global resource cache by the hash of the path's compiled name, or from [`AquireAnimationFromCache`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::pose_producer::AquireAnimationFromCache) with an explicit cache.

A layer's blender ([`Blender`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::pose_producer::Blender)) samples its instances: [`Blender::AddSampler`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::pose_producer::Blender##func-AddSampler) registers an instance's Havok animation control with the blender's animated skeleton and keeps a reference, [`Blender::ClearSamplers`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::pose_producer::Blender##func-ClearSamplers) removes them all, and [`Blender::UpdatePose`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::pose_producer::Blender##func-UpdatePose) samples them into a pose. The disassembler's blender constructor and time update are something else (one builds a Havok animated skeleton into a shared pointer, the other computes a bone's model-space transform on demand), and the instance's time, weight, and duration accessors carry their names only in the disassembler. Whether a blender can sample outside the pose job, which supplies the reference pose and the buffers, is unverified.
