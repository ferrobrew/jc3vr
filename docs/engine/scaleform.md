# The Scaleform runtime

The Scaleform build Just Cause 3 links, the one loader every movie comes through and what that loader installs, how files reach it, the standalone movies the engine hosts outside the root movie, and what the shipped movies offer to other movies (fonts, widgets, and localisation). How the screens share the root movie and talk to native code is in [pause-menu.md](pause-menu.md#screens-and-the-root-movie); how the UI is captured and drawn each frame is in [rendering/ui-rendering.md](rendering/ui-rendering.md). The addresses are in the pyxis module [`ui::scaleform`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/ui::scaleform).

Statements marked as resting on Scaleform's source are Scaleform 4 behaviour read from its source code and not verified in the IDB.

## Version and language

Every shipped movie carries an ExporterInfo tag from Scaleform's 4.1 exporter, with SWF version 12 (`root`, `dyn_root`) or 15 (all others). The binary holds no version string. The runtime contains classes that arrived after 4.1 (`AppLifecycleEvent`, `AccelerometerEvent`, `ASIMEManager`), so it is a GFx 4.x build later than the exporter; that it is of the 4.2 to 4.4 era is inferred from those classes. The renderer is the D3D1x HAL, [`RenderHAL`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::RenderHAL).

Every movie's FileAttributes tag sets the AS3 flag. The UI manager installs AS3 support on the loader and no AS2 support, so AS2 content does not run although AS2 code is linked (unverified). Application domains are disabled, with the consequences described in [pause-menu.md](pause-menu.md#screens-and-the-root-movie).

## The loader

`CUIManager::InitializeSystem` builds one `GFx::Loader`, [`UIManager::m_Loader`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_manager::UIManager##field-m_Loader), and installs its states: zlib support, the file opener [`ScaleformFileOpener`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::ScaleformFileOpener), AS3 support, an FSCommand handler that only logs an error, the ExternalInterface handler [`ScaleformEIHandler`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::ScaleformEIHandler), a font map, a font library, the translator `CScaleformTranslator`, a threaded task manager, and a DDS image handler. It then loads the fonts, loads `ui/root.gfx` with [`Loader::CreateMovie`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::Loader##func-CreateMovie), creates the root movie instance, and initialises every registered screen. The function is located in the IDB; the list of states is unverified. Because states belong to the loader, every movie created through `m_Loader` shares all of them.

The loader accepts the signatures `FWS`, `CWS`, `GFX`, and `CFX`, and not the LZMA `ZWS`. A `GFX` or `CFX` signature marks the movie as stripped, and for a stripped movie an import URL ending in `.swf` is retried as `.gfx` relative to the movie's own path; this is how the shipped movies import `shared_lib.swf` and load `ui/shared_lib.gfx`. A plain `FWS` or `CWS` movie loads, but its imports are resolved literally. All of this rests on Scaleform's source (`SWFProcessInfo`, `MovieBindProcess`).

## Files

[`ScaleformFileOpener::OpenFile`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::ScaleformFileOpener##func-OpenFile) serves every file a movie loads. It returns the UI manager's file-cache entry when there is one; otherwise it reads the file from the game's virtual file system into a `CScaleformCachedFile` and offers that to the cache. The cache keeps only the movies on a fixed list built in its constructor (among them `ui/pause.gfx`, `ui/comm_link.gfx`, and `ui/dyn_root.gfx`), so an entry for another file cannot be seeded without also editing that list (the list's contents are unverified). Supplying a file from memory therefore means answering its URL in `OpenFile`; the engine already builds a `Scaleform::MemoryFile` elsewhere, for its avatar fallback.

The virtual file system takes `--vfs-fs` and `--vfs-archive` from the command line and mounts each path in order, each with a higher priority than the last. A path containing `dropzone` is mounted under that name, the convention the community's loose-file "dropzone" folders use; `DestroyVfs` unmounts `dropzone`. The option strings and the unmount are in the IDB; the parsing is unverified.

## Standalone movies: CRenderToTextureUI

The engine's in-world screens, the `CDynUI` game objects (the front-end start screen, the ROM posters, the video players), each own a separate movie, a `CRenderToTextureUI`, rather than a clip in the root movie. None of its members is bound in pyxis; the sequence below is verified in the IDB.

- `CRenderToTextureUI::InitMovie` loads `ui/dyn_root.gfx` through `m_Loader` with the same load flags as the root movie, creates an instance with the UI thread's command queue, gives it one mouse cursor and one controller, sets its view alignment, makes the main thread its capture thread, and advances it once.
- `InitCodeInterface` attaches a non-static screen object (`CDefaultDynUI`, `CFrontEndUI`, and others) as the movie's user data, so the movie's ExternalInterface calls reach that screen. `CRenderToTextureUI::Activate` then calls `root.ActivateDyn(<movie name>)`, and `dyn_root.gfx` loads any `<name>.gfx` with no table lookup, unlike `root.gfx`'s `Activate`.
- `InitRenderTarget` creates a colour texture, a D24S8 depth texture, and a render setup, and sets the movie viewport to the texture size.
- `UIManager::AddRenderToTextureUI` puts it on the manager's render-to-texture list. From then on the manager advances it in `PreRender` and draws it in [`RenderOffScreenTexturesImpl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_manager::UIManager##func-RenderOffScreenTexturesImpl), as described in [ui-rendering.md](rendering/ui-rendering.md#off-screen-movies), and releases it through the dying-movie list.

A movie that is not a registered screen has no input priority: [`UIManager::PreUpdate`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_manager::UIManager##func-PreUpdate) dispatches input only to the active registered screen with the highest priority, and [`SendMouseEvents`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_manager::UIManager##func-SendMouseEvents) feeds only the root movie. A new static screen inside the root movie would need an entry in `root.gfx`'s class-to-file table, which is hard-coded in its ActionScript.

## Native access to a movie

The value API ([`ValueObjectInterface`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::ValueObjectInterface)) and the object constructors on [`MovieImpl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::MovieImpl) are described in [pause-menu.md](pause-menu.md#calls-from-native-code-to-the-movie). [`MovieImpl::CreateFunction`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::MovieImpl##func-CreateFunction) wraps a native handler in an AS3 function object, adds a reference to the handler, and keeps the user data beside it. Per Scaleform's source, the handler is a reference-counted object whose one virtual besides the destructor, `Call`, receives a parameter block holding the return value, the movie, `this`, the arguments and their count, and the user data. `CreateObject` with a class name instantiates any class in the shared application domain, display classes included, so native code can build display objects and add them with an `addChild` invoke. `AttachMovie`, `CreateEmptyMovieClip`, and `GotoAndPlay` are present on the value object interface by name, match the GFx 4 API, and are not bound.

ExternalInterface calls from a movie with no user data and an unknown screen prefix are dropped by [`ScaleformEIHandler::Callback`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::ScaleformEIHandler##func-Callback), so a function object made with `CreateFunction` is the only way such a movie can call native code without a detour.

## Fonts, widgets, and localisation

`ui/font_en.gfx` defines `FranklinGothicMediumITC` and `FranklinGothicHeavyITC` and exports them as `$MainFont` and `$SecondaryFont`; `font_ara`, `font_jp`, `font_pl`, and `font_ru` are the per-language variants. `CUIManager::LoadFont` loads the language's font movie and adds its fonts to the loader's font library, and the font map is filled from a language map file. Per Scaleform's source, an import of the font library's name is resolved from the font library instead of from a file. Every game screen imports `font_en.swf` with no symbols, so a movie loaded through `m_Loader` that does the same and sets `$MainFont` or `$SecondaryFont` on its text fields should get the game's fonts in every language; this has not been tested.

`ui/shared_lib.gfx` is the shared widget library, with several hundred SymbolClass entries: `shared.menu`, `shared.menu_button`, `shared.generic_button`, `shared.button_hint_bar` and `button_hint_item`, the scrollbar managers, `shared.checkbox_manager`, `shared.picker`, `shared.progress_bar`, the message box `shared.msg.c_msgbox_base`, the context menu and filter packages, the backgrounds and title classes, and every controller button glyph. Game screens bring it in with a symbol-less `ImportAssets2` tag for `shared_lib.swf`. The settings slider is not in it: `pause_code.slider` belongs to `pause.gfx`, which exports nothing (see [pause-menu.md](pause-menu.md#row-objects-and-widgets)). `root.gfx`'s `uibase` class holds the palette and text helpers (`COLOR_TEXT_SELECTED`, `COLOR_TEXT_DEFAULT`, the `TM_*` tween modes, `SetTextFieldText`, `SetTextAutoSize`).

`CScaleformTranslator::Translate` rewrites a text field's text when it is set. Text beginning with `&` is looked up as a string key (the pause movie uses keys such as `&settings_yes`), and text beginning with `#` and digits is looked up by hash. Anything else passes through unchanged, except that in keyboard mode action-key placeholders are substituted. `TextFieldEx.setNoTranslate` opts a field out. The class is present in the IDB; its behaviour is unverified.

## The movie files

The Gibbed file lists name 31 `ui/*.gfx` movies. The patch archives hold copies of `root`, `shared_lib`, `pause`, `hud`, `overlay`, the `comm_*` screens, the `dyn_*` movies, and most fonts, and the game loads the patch copy where one exists. `dyn_root` is only in the base archives. All of them are `CFX` files. Extracting and decompiling them is described in [pause-menu.md](pause-menu.md#reading-the-movies).

## Building a movie the loader accepts

A movie for this runtime can be built on Linux without Scaleform's exporter, which is Windows-only and proprietary. The Apache Flex SDK's `mxmlc` (nixpkgs `apache-flex-sdk`) builds a `CWS` SWF with an AS3 FileAttributes tag, a `DoABC` tag, and a SymbolClass tag, the same shape as the game's movies, with `-swf-version=15 -static-link-runtime-shared-libraries=true` and the stage size given by `-default-size`. Its only `playerglobal.swc` targets a Flash Player release whose APIs are a superset of Scaleform's, so the compiler does not catch calls Scaleform lacks; staying within the `flash.display`, `flash.text`, and `flash.events` core and the `scaleform.gfx.*` extensions avoids them. Haxe's SWF target is an alternative that can type against an existing library's classes; it has not been tried.

Two post-build steps make such a movie behave like a shipped one: renaming the signature from `CWS` to `CFX`, so that the loader treats it as stripped and resolves its `.swf` imports to the shipped `.gfx` files, and appending symbol-less `ImportAssets2` tags for `font_en.swf` and `shared_lib.swf`, which `mxmlc` does not emit. JPEXS FFDec can add the tags; so can a small tool that reuses the tag parser in `tools/scaleform-gfx-examine`.

None of this has been loaded in the game. Open questions: whether a Flex-built movie runs cleanly under Scaleform's AVM2, whether it needs an ExporterInfo tag (the loader appears to key the stripped flag off the signature alone), whether the `font_en` and `shared_lib` imports resolve from a movie outside the game's own set, and whether `shared.*` classes work without `root.gfx`'s `uibase` context.
