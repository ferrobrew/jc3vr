# Inventory debug UI

The debug UI's view of the [two-handed inventory](two-handed-inventory.md)'s loadout table, the gives it can make, and the docked guns' visualization.

## The inventory view

The inventory view (Weapons > Inventory and body slots, `crates/jc3vr-ui/src/ui/controllers/inventory/`) reads only publications, never the game's memory. The inventory publishes its readout through `inventory::peek_status`, with the game's own inventory captured on the input tick (`weapons::inventory::game_view`). The view opens with the `Inventory` status rows ([status rows](../debug-ui.md#status-rows)), then shows the loadout (each hand and socket with what is there, the grenade and C4 rows, the weapons lying in the world, and the latest transitions and refusals) and the game's inventory (each slot's weapon beside what the table projects into it, the selected slot, and the wielded weapon). A slot that does not hold what the table projects, or a wielded weapon that is not the primary hand's, is marked as a mismatch, except while a spawn is on its way, a mounted gun is manned, or the game's weapon update skips the wielded weapon. The table's snapshot and the game's capture are separate publications, so a mismatch for a single frame can be the two a tick apart; one that persists is a fault. A weapon's display name is the HUD's: its name hash ([`m_WeaponNameHash`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_WeaponNameHash)) through the menu's lookup ([`UIMenu::GetWeaponNameById`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_menu::UIMenu##func-GetWeaponNameById)), falling back to the definition's name where the store has none or the debug UI's fonts cannot draw the language.

## Giving weapons

The loadout is a live view to edit (`crates/jc3vr-ui/src/ui/controllers/inventory/loadout.rs`): each hand's and socket's dropdown offers nothing and the hand weapons the game ships that fit it, from the spawn definition table (`jc3vr_weapons::controllers::spawn`): for a hip the one-handed weapons, for a shoulder the rest, and for a hand all of them. Choosing a weapon gives it there; choosing nothing clears the socket, or lets go of the hand's weapon as opening the grip away from the body would. The requests are carried out at the next input tick (`weapons::inventory::restore::give`).

A give takes the restore's path for a carried weapon: the definition's tag set names its unique spawn tag ([`SpawnSystem::GetUniqueTag`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/spawn_system::SpawnSystem##func-GetUniqueTag)), the spawn system spawns it at the player ([`SpawnSystem::SpawnTagIndex`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/spawn_system::SpawnSystem##func-SpawnTagIndex)), and the next input tick carries the weapon onto the socket through the table's restore admission, which takes the next free socket that fits when the chosen one does not. A taken socket is cleared first, its weapon falling clear as a swap's does. A give to a hand comes onto a fitting socket the same way, and the hand draws it off at the next tick through the ordinary draw, but only while its grip is closed and it is empty. A pistol given while the table runs is one pistol.

Nothing in the spawn path locks a definition: the game's completion reward gives its golden pistol through the same unique tag. What can stop a give is the definition's exported entity ([`SpawnResourceDef::m_Status`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/spawn_system::SpawnResourceDef##field-m_Status), read through [`SpawnSystem::GetResourceDefFromTagHash`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/spawn_system::SpawnSystem##func-GetResourceDefFromTagHash)): one not loaded streams in first, and one whose load hits a file error is dropped from the request, which the spawn system then removes without calling back. A give waits `restore.give_wait_s`, or up to `restore.give_wait_loading_s` while the entity streams, then withdraws its request ([`SpawnSystem::CancelSpawn`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/spawn_system::SpawnSystem##func-CancelSpawn)) so that a late spawn cannot leave a stray weapon at the player, and logs why. A definition that failed is remembered for the session, and the dropdowns grey it with the reason.

The grenade row sets the stock through the game's own setters ([grenades.md](grenades.md)). The game keeps no stock of C4, only a cap on the charges placed at once, so the C4 row shows the charges placed against that cap ([`MaxActiveExplosives`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::PlantedExplosiveWeapon##func-MaxActiveExplosives)); choosing none placed removes every placed charge without detonating it through the weapon's own removal ([`RemoveAllExplosives`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::PlantedExplosiveWeapon##func-RemoveAllExplosives)), which also takes their HUD hints down. A charge in a hand is primed rather than placed and stays.

## The docked guns' view

The `Docked guns` visualization (`controllers.overlay.docked_guns`, on by default, `weapons::inventory::docked_view`) marks each gun the table has docked on a socket with a ring where its last placement put it and a short line along its barrel, drawn through the body: green while the gun's model is shown and red while it is hidden, so a docked gun that renders nothing says whether the game hides it or the placement puts it off the body or into it.
