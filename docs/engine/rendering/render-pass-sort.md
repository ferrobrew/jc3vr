# The render-pass sort and depth buckets

How each render pass orders its draw list before drawing, and how the sort can split a list by distance from the camera. The list rotation and the draw walk around it are in [rendering.md §11](rendering.md#11-render-block--draw-list-lifecycle-across-dispatches). The layouts and the constants are in the pyxis modules [`graphics_engine::render_pass`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::render_pass) and [`graphics_engine::render_engine`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::render_engine).

## The sort

A pass's draw list is an array of [`RenderInstance`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderInstance) entries (`SRenderInstance`), each holding a sort ID, the render block, its instance info, the render-block type, and a depth key. Once per list rotation, [`RenderPass::SortList`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass##func-SortList) (labelled `CRigidObject::Destruct` in the IDB):

1. Recomputes each entry's keys through the block's virtuals: [`RenderBlock::GetSortID`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderBlock##vfunc-GetSortID) and [`RenderBlock::GetSqDistanceToCamera`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderBlock##vfunc-GetSqDistanceToCamera), the squared distance from the instance's buffered world translation to the sort camera. Only `CRenderBlockWindow` and the particle blocks override the distance.
2. Sorts by `(m_Depth, m_RenderBlockType, m_SortID)` with `std::sort`, as the pass's [`RenderPass::m_SortMethod`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass##field-m_SortMethod) says: by sort ID with no depth key, back to front by raw distance, front to back by raw distance, or front to back by bucket index.
3. Latches [`RenderPassSortState::m_Sorted`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPassSortState##flag-m_Sorted) in [`RenderPass::m_SortStateFlags`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass##field-m_SortStateFlags) under [`RenderPass::m_SortLock`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass##field-m_SortLock). [`RenderPass::SaveRenderFrameData`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass##func-SaveRenderFrameData) clears it at the rotation, so a list is sorted at most once per rotation, and every draw of that list in the frame sees the same order.

Two callers reach it: the render thread's sort task, [`RenderEngine::SortRenderPasses`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_engine::RenderEngine##func-SortRenderPasses), which takes the pass's external camera as the sort camera when it has one and the render camera otherwise, and a lazy call at the top of [`RenderPass::DoDraw`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass##func-DoDraw). `DoDraw` walks `min(m_ListSize, m_NumElements)` entries from `m_List` and never writes the list, so narrowing the walk to a window of it is safe and a list can be walked more than once.

The distance is the instance centre's, not the nearest point of its bounds: a large object whose centre is far away sorts as far even where its extent reaches the camera. [`RenderBlock::GetBoundingBox`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderBlock##vfunc-GetBoundingBox) gives the extent.

## Depth buckets

`m_SortMethod` defaults to `Auto`, which resolves to front to back by bucket, or back to front for alpha-blended passes. Bucketed sorting quantizes the squared distance through the pass's [`RenderPass::m_DepthSqTable`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass##field-m_DepthSqTable), a fixed-capacity table of ascending squared boundaries with its live count in [`RenderPass::m_NumDepthBuckets`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass##field-m_NumDepthBuckets), and stores the bucket index in `m_Depth`. With one bucket, the constructor's default, no depth key is computed and the sort is by type, then sort ID. Adding a boundary (the engine's `AddDepthBucket` is inlined: append to the table, keep it sorted, and raise the count) turns the sorted list into one contiguous, type-batched run per bucket, with `m_Depth` monotonic along it. Back-to-front passes keep raw distances in `m_Depth`, so a distance splits them too, in the reverse order.

The only stock pass with more than one bucket is the Z-and-velocity pass, [`RenderPassId::RP_Z_AND_VELOCITY_PASS`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_engine::RenderPassId##variant-RP_Z_AND_VELOCITY_PASS), whose two boundaries are [`RenderPass::Z_AND_VELOCITY_DEPTH_SQ_NEAR`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass::Z_AND_VELOCITY_DEPTH_SQ_NEAR) and [`RenderPass::Z_AND_VELOCITY_DEPTH_SQ_FAR`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass::Z_AND_VELOCITY_DEPTH_SQ_FAR), registered inline in [`RenderEngine::InitializeSystem`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_engine::RenderEngine##func-InitializeSystem). The extra block-type switches a boundary costs are the ones the engine already pays on that pass.

Some content does not split by distance at all, because whole block types are near or far: the distant terrain, distant trees, and occluders are their own block types ([terrain.md](terrain.md#which-blocks-draw-the-visible-terrain)).
