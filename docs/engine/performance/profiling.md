# Performance-profiling machinery

The Apex engine ships several timing systems; some are live, others compiled out. The bound items are in the pyxis modules [`cpu_profiler`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/cpu_profiler), [`graphics_engine::gpu_profiler`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::gpu_profiler), and [`steering_frame_profiler`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/steering_frame_profiler). Claims resting on indirect evidence are marked unverified.

## Summary: live versus dead

| Machinery | Status | What it provides |
|---|---|---|
| `CpuProfiler` (the `cpu_profiler` object, fixed frame phases) | Dead: `Update` is an empty function and nothing writes the counters (§1.1) | — |
| `Graphics::BeginScopeMarker` / `EndScopeMarker` | Compiled out, but about 72 call sites and their name strings survive (§1.5) | Named scope pairs across the draw thread, called into empty functions |
| `SProfiler` scope primitives | Compiled out; the IDB symbols with these names are mislabelled (§1.2) | — |
| `Graphics::*TimeStamp*` / `*Disjoint*` query wrappers | Live, thin D3D11 wrappers (§2.1) | GPU timestamp and frequency queries |
| `CGPUBufferedQuery` | Live (§2.2) | N-frame-latency timestamp, occlusion, and frequency read-back |
| `CRenderPassGpuTimingQuery` | Live, wired to the particle pass only (§2.3) | Adaptive particle quality |
| `CProfilerUtil` (budget store) | Not located; the IDB symbols with its names are mislabelled (§1.3) | — |
| `CFrameProfiler` (on-screen frame graph) | Dead: no methods present (§1.4) | — |
| The `debug_DumpProfilerTrace`, `debug_fprof`, and `frame_profiler` commands and the `Dev\|Performance\|*` menu | Dead: strings and handlers stripped | — |
| `CSteeringFrameProfiler` | Live, but it only binds the frame profiler's input actions (§1.6) | The `"frameprofiler"` action map |

## 1. CPU side

### 1.1 `CpuProfiler` — the fixed frame-phase breakdown (dead)

`CpuProfiler` (`g_CpuProfiler`) is the statically allocated object [`cpu_profiler`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/cpu_profiler::cpu_profiler), located by the `this` passed to `GetScopeName` in `BorkReport::WriteMetrics` and by the direct `m_Time` reads in `CBorkReport::UpdateMetricsData`. It would accumulate wall-clock time per frame phase, the [`CpuScopeId`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/cpu_profiler::CpuScopeId) enum:

```
CPU_SCOPE_ID_FRAME, DRAW, UPDATE_ALL, RENDER_ALL, PREUPDATE,
PRESIM_SYSTEMS, PRESIM_OBJECTS, PHYSICS_UPDATE, POSTSIM_UPDATE, POSTSIM_SYSTEMS,
WAIT_FRAME, RENDER_UPDATE, RENDER_SYSTEMS, WAIT_FLIP, WAIT_UI
```

The layout ([`CpuProfiler`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/cpu_profiler::CpuProfiler)) holds the last frame's milliseconds per phase (`m_Time[]`), a rolling peak per phase (`m_Peak[]`), the ring position, the triple-buffered QPC begin and end counters, and the running local peak. The phases run in `Game::Update`, [`Game::UpdateGame`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/game::Game##func-UpdateGame), [`Game::UpdateRender`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/game::Game##func-UpdateRender), [`Game::Draw`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/game::Game##func-Draw), and [`GraphicsEngine::WaitForCPUDrawToFinish`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::graphics_engine::GraphicsEngine##func-WaitForCPUDrawToFinish) on the main thread, and in the draw-thread seams.

It is dead. [`CpuProfiler::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/cpu_profiler::CpuProfiler##func-Update), which would convert the QPC deltas to milliseconds and roll the peaks, is an empty function, still called at the top of [`Game::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/game::Game##func-Update). Nothing writes [`CpuProfiler::m_Counters`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/cpu_profiler::CpuProfiler##field-m_Counters): the phase brackets `CGame::UpdateCPUProfiler` and the game states would place are compiled out. The only interior reference is [`GraphicsEngine::DispatchDraw`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::graphics_engine::GraphicsEngine##func-DispatchDraw), which forwards the never-incremented [`CpuProfiler::m_Index`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/cpu_profiler::CpuProfiler##field-m_Index) to the draw task. [`CpuProfiler::GetScopeName`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/cpu_profiler::CpuProfiler##func-GetScopeName) survives, returning the phase's entry in a static name table, and its consumers, [`BorkReport::WriteMetrics`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/bork_report::BorkReport##func-WriteMetrics) and [`BorkReport::WriteTotalEntry`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/bork_report::BorkReport##func-WriteTotalEntry) in Avalanche's crash and telemetry report ([`BorkReport`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/bork_report::BorkReport)), serialise all-zero per-phase times. `CGame::UpdateCPUProfiler` is not located (unverified); it is reachable from `Game::Update` and the `GetScopeName` call sites.

### 1.2 `SProfiler` scope primitives (compiled out)

Under `CpuProfiler` sits the general Apex scope profiler `SProfiler`, a per-thread, hierarchical enter and leave timer with named entries (`SProfilerEntryData { volatile int m_ID; float m_Budget; const char* m_Name; }`) lazily allocated and registered per module. Its entry points are `ProfilerThreadEnter(entryId, startQPC)` (push a scope), `ProfilerThreadLeave(entryId, endQPC)` (pop it), `ProfilerThreadAdd(entryId, deltaQPC)` (add a raw duration), `ProfilerThreadAddBudget(entryId, deltaQPC, budget)` (add with a budget comparison), `ProfilerGetProfilerThreadID()`, and `ProfilerInitThread(name)`.

They are compiled out. The IDB puts each name on an unrelated body (a sound-resource critical section, a pose-producer blender update, an AI event ring, and similar), and two symbols that look like identical-code-folded copies of `ProfilerThreadLeave` and `ProfilerThreadAddBudget` are mislabelled too. None is bound, and none may be called as a profiler entry point. The strings `"CGame::UpdateCPUProfiler"` and `"ProfilerInitThread"` survive in `.data` records that do not match the `SProfilerEntryData` layout and that nothing references; their purpose is unverified.

### 1.3 `CProfilerUtil` — not located

`CProfilerUtil` is the `Base::CSingle<CProfilerUtil>` singleton for the developer performance UI: a budget table (`SBudgetEntry m_Budget[]`, from `settings/budgetscopes.txt`), an on-screen budget and hitch display, a trace writer to `budget_violations.json`, a `CFrameProfiler` pointer, and a `CDumpProfilerTraceCmd` console command, with `PreUpdate`, `Update`, `Render`, and `SetDisplayBudgetScopes` called from `CGame`.

No part of it is confirmed (unverified). The three IDB functions bearing its names are mislabelled: `CProfilerUtil::LoadBudget` is a recursive runtime-container walk that builds objects, called from [`resource_loader::CreateObjectsAsync`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/resource_loader##func-CreateObjectsAsync); `~CProfilerUtil`, called from [`Game::Destructor`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/game::Game##func-Destructor), unsubscribes eight `NEvent` handlers of an unrelated singleton; and `Base::CSingle<CProfilerUtil>::Release` releases that singleton. `PreUpdate`, `Update`, `Render`, `UpdateBudgetsOnScreen[QA]`, `HandleUserInput`, `SetDisplayBudgetScopes`, `DoCapture`, `HitchCallback`, and the `CDumpProfilerTraceCmd` handler are absent, and so are the strings `"Dev|Performance|Main Thread Budgets"`, `"Dev|Performance|Show Budget Scopes"`, `"debug_DumpProfilerTrace"`, `"debug_fprof"`, `"frame_profiler"`, and `"settings/budgetscopes.txt"`, while `"CGame::UpdateCPUProfiler"`, `"ProfilerInitThread"`, and the `PROFILER_*` input-action names remain. The game has no budget table, budget comparison, interactive display, console command, or debug menu.

### 1.4 `CFrameProfiler` and the dev console — dead

`CFrameProfiler`, the on-screen frame-time graph (category rows, history, sort modes, an `m_AsyncGPUContext` GPU lane), has no methods in the binary, and the console commands that would toggle it are gone. Nothing brings the frame graph back.

### 1.5 `Graphics::BeginScopeMarker` / `EndScopeMarker` — compiled out, call sites intact

[`BeginScopeMarker`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::graphics_engine##func-BeginScopeMarker) (`Graphics::BeginScopeMarker(HContext_t*, const char*)`) opens a named scope on a graphics context and [`EndScopeMarker`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::graphics_engine##func-EndScopeMarker) closes the innermost; the RAII [`ScopeMarker`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::gpu_profiler::ScopeMarker) (`Graphics::CScopeMarker`) calls them from its [constructor](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::gpu_profiler::ScopeMarker##func-Constructor) and [destructor](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::gpu_profiler::ScopeMarker##func-Destructor). Both are empty functions, but their call sites and name strings survive and still run every frame: about 72 sites covering `CGraphicsEngine::HandleDrawThreadTask`'s stages ("Frame setup", "CopyEffectTextures", "Debug UI"), the post-effect stack (SMAA and FXAA, depth of field, motion blur, lens flare, glare, the tone-mapping histogram), deferred lighting, SSAO, SSR, environment reflections, water, terrain restores, and UI and video off-screen rendering, plus the per-render-block-type runs in every pass: [`RenderPass::ChangeRenderBlockType`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass##func-ChangeRenderBlockType) closes the previous type's scope and opens one named by the next type's `GetTypeName()`, and [`RenderPass::DoDraw`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass##func-DoDraw) closes the last.

### 1.6 `CSteeringFrameProfiler` — the frame profiler's input steering

[`SteeringFrameProfiler`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/steering_frame_profiler::SteeringFrameProfiler) (`CSteeringFrameProfiler`) is an input steering, not a timer: it binds the `"frameprofiler"` action map that would navigate, sort, pause, and close the frame profiler. [`SteeringFrameProfiler::LoadActionMap`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/steering_frame_profiler::SteeringFrameProfiler##func-LoadActionMap) (the string's sole reference), [`GetFrameProfilerInputs`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/steering_frame_profiler##func-GetFrameProfilerInputs), [`FrameProfilerOverridePlayerInputs`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/steering_frame_profiler##func-FrameProfilerOverridePlayerInputs), and the [constructor](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/steering_frame_profiler::SteeringFrameProfiler##func-Constructor) are present; the display that would consume the inputs is stripped (§1.4).

## 2. GPU side

### 2.1 `Graphics::*` timestamp and disjoint-query wrappers (live)

Thin live wrappers over D3D11 queries, in the [`graphics_engine::graphics_engine`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::graphics_engine) module: [`CreateTimeStampQuery`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::graphics_engine##func-CreateTimeStampQuery) (a `D3D11_QUERY_DESC` with `D3D11_QUERY_TIMESTAMP` through the device's `CreateQuery`, vtable `+192`), [`DestroyTimeStampQuery`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::graphics_engine##func-DestroyTimeStampQuery), [`SetTimeStampQuery`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::graphics_engine##func-SetTimeStampQuery) (records a timestamp on a context), [`QueryTimeStamp`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::graphics_engine##func-QueryTimeStamp) (reads the u64 tick), [`CreateTimeStampDisjointQuery`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::graphics_engine##func-CreateTimeStampDisjointQuery) (`D3D11_QUERY_TIMESTAMP_DISJOINT`), [`DestroyTimeStampDisjointQuery`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::graphics_engine##func-DestroyTimeStampDisjointQuery), [`BeginTimeStampDisjointQuery`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::graphics_engine##func-BeginTimeStampDisjointQuery), [`EndTimeStampDisjointQuery`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::graphics_engine##func-EndTimeStampDisjointQuery), and [`QueryTimeStampFrequency`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::graphics_engine##func-QueryTimeStampFrequency) (the frequency and the `Disjoint` flag). `EndTimeStampDisjointQuery` is identical-code-folded with `SetTimeStampQuery` (both are `ID3D11DeviceContext::End` under the context mutex) and shares its address; the IDB puts its name on an unrelated three-byte stub that must not be called.

### 2.2 `CGPUBufferedQuery` — ring-buffered GPU queries (live)

[`GPUBufferedQuery`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::gpu_profiler::GPUBufferedQuery) (`NGraphicsEngine::CGPUBufferedQuery`) is the engine's N-frame-latency query ring over those wrappers, fully present: `Create`, `Destroy`, `SetTimestamp`, `SetFence`, `SetOcclusionBegin`, `SetOcclusionEnd`, `SetFrequencyBegin`, `GetOcclusionResult`, and `GetFrequencyResult` are bound. Its `m_Timestamps[]` and `m_Frequency[]` are sized `m_NumBuffers * m_NumTimestamps`, so many timestamps a frame read back `m_NumBuffers` frames later without a stall.

The engine's own ring belongs to `NGraphicsEngine::CGPUProfiler`, the singleton [`GPUProfiler`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::gpu_profiler::GPUProfiler), the full developer GPU profiler (per-scope GPU and CPU time, occlusion, and draw counts; frame, render-pass, render-block, and user scopes; a rolling capture mode; per-category results over the `ERenderPassCategory` groups). What survives is the [constructor](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::gpu_profiler::GPUProfiler##func-Constructor), called from [`GraphicsEngine::InitializeSystem`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::graphics_engine::GraphicsEngine##func-InitializeSystem), [`GPUProfiler::GetScopeResultCount`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::gpu_profiler::GPUProfiler##func-GetScopeResultCount), and a frame-level disjoint-query begin and end in `HandleDrawThreadTask`. The per-scope `BeginScope` and `EndScope` call sites (the scope markers of §1.5 are their entry points), the results processing, and the read-back are stripped: [`GPUProfiler::GetScopeResult`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::gpu_profiler::GPUProfiler##func-GetScopeResult) is `xor eax, eax; ret`, so `CBorkReport`'s per-category GPU loop exits at once, and no state flip revives the class. `CGPUProfiler::Init` is not located; the function the IDB gives that name is [`ShadowManager::InitializeSystem`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::shadow_manager::ShadowManager##func-InitializeSystem). Identical-code folding misplaces other names here: the body labelled `BeginScope` is [`CopySurfaceToTexture`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/graphics_engine::draw##func-CopySurfaceToTexture) ([rendering §12](../rendering/rendering.md#12-there-is-no-final-resolve)), and the one labelled `EndScope` is [`SkinningPaletteData::UpdateDeleteQueue`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::skinning_palette::SkinningPaletteData##func-UpdateDeleteQueue), the skinning palette's deferred vertex-buffer delete queue.

### 2.3 `CRenderPassGpuTimingQuery` — live, but a single-pass adaptive-quality timer

[`RenderPassGpuTimingQuery`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::gpu_profiler::RenderPassGpuTimingQuery) (`NGraphicsEngine::CRenderPassGpuTimingQuery`) multi-buffers timestamp start, end, and frequency queries and keeps a rolling average (`m_ParticleGPUTimingHistory`); `Create`, `Destroy`, `BeginGPUTimingQuery`, `EndGPUTimingQuery`, and `GetAverageGpuTiming` are bound. The engine owns one instance, [`RenderEngine::m_ParticlePassGpuTimingQuery`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_engine::RenderEngine##field-m_ParticlePassGpuTimingQuery), begun by [`RenderEngine::BeginParticlePassGpuTimingQuery`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_engine::RenderEngine##func-BeginParticlePassGpuTimingQuery) from [`RenderPass::DoDraw`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_pass::RenderPass##func-DoDraw) and ended at the tail of the particle draw. Its average adapts [`RenderEngine::m_TessFactorScale`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_engine::RenderEngine##field-m_TessFactorScale) and sets [`RenderEngine::m_ParticlePassGpuIntense`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/graphics_engine::render_engine::RenderEngine##field-m_ParticlePassGpuIntense) against the thresholds those fields document: an adaptive particle-quality system measuring only particles, not a profiler. Timing another pass needs a new instance and new begin and end call sites.

## 3. Per-pass structure

The passes and their groups are in [rendering §3](../rendering/rendering.md#3-render-passes--stages-ordered), and the calls that draw each group (`DrawGBuffer`, `Draw`, `DrawPosteffects`, and `PostDraw`) in [rendering §1.4](../rendering/rendering.md#14-body-of-handledrawthreadtask--per-dispatch). There is no live general per-pass GPU or CPU bookkeeping to read; the only per-pass GPU timer is the particle one (§2.3).
