## Run record

Before each run, record the exact payload/build provenance, effective settings and defaults, scenario path and revision, headset/controller and tracking setup, game context, and operator timestamp. Record changed settings and restore them after a comparative run. Use the existing scenario runner and existing paths. Extend the relevant scenario in place; do not replace it with a second runner or create an unapproved scenario path. Existing paths referenced here include `testing/scenarios/recenter.toml`, `physical_actions.toml`, `parachute_handles.toml`, `door_by_handle.toml`, `vehicle_doors.toml`, `grenade_pin_and_catch.toml`, `physical_guns.toml`, `grip_targets.toml`, and `procedural_full_body.toml`.

The Physical hands and held objects Status section exposes Grip acquisition evidence with bounded scans, resolver candidates and losses, controller publication sequence, input-observation ordinal, grip episode, request identity, consumer outcomes, and carried-body write observations. The body-IK controls expose separate raw tracking, native pre-IK, and completed-movement evidence. These readouts are retained snapshots, not a synchronized recording or proof of a completed checked body observation. A drive command or successful write is not a post-step result. Record omitted and evicted counts, and treat missing provider data separately from an observed miss.

For a real grip-acquisition attempt, use "Save grip acquisition evidence" under that readout while editing is enabled. Save promptly after the attempt, before further presses or requests replace the bounded records. Preserve the resulting `sessions/<session>/grip_acquisition/grip-acquisition-NNN.json` file and record its exact path, size, build stamp, and session identity with the run. The button is disabled in the read-only overlay and does not provide a new edit route. The button only enqueues one already-copied snapshot without new engine reads or recording. A second pending click is explicitly rejected without replacing that snapshot. The game-thread update takes the request and writes it synchronously after the UI layout and `EguiState` guards are released; no pending-request or save-result guard covers file I/O. Check the save result on the following UI update and parse the file before linking it; an I/O error or an incomplete file is not a capture. Record the exact retained controller sequence, input-observation ordinal, grip episode, request ordinal, and target identities, with the omitted and evicted counts. The versioned envelope retains nested facts as build-specific Rust Debug text. An absent scan or provider identity is unavailable evidence. The artifact-export timestamp and session folder do not identify an input time, physics step, or video frame. Link a video only as separately verified run evidence unless a real shared sample identity exists; do not infer cross-video timing from this export. No actual failed acquisition or headset result is established by fixture files or source tests.

Every trace must carry this shared header: run and build identity; scenario path; timestamp and clock domain; effective settings and input scheme; headset, controllers, dominance choice, and tracking validity; game state and focus; action sequence; source and episode identity; frame/sample identity and age; requested and effective owner; selected candidate or explicit absence; output or refusal reason; and any linked capture filename, size, and provenance. Preserve event ordering and link log rows, screenshots, and video to the same run and sample identities. Never infer timing, physical motion, collision, or ownership from an unsynchronized image.

The required fields in each row below are additional to that shared header. A row passes only when every stated positive condition holds and no stated failure occurs. Missing required telemetry makes the run inconclusive, not passed. Stop a run if it requires an unavailable or blocked adapter.

## Immediate headset checklist

Run only on a frozen build with the required safe paths available. Keep an operator beside the user, use a clear area, and stop on discomfort, unsafe motion, or unexpected game input. Record actual outcomes; leave unavailable checks pending.

1. Before each feature, check the running build, effective settings, source/candidate availability, status readout, and required trace fields. Test only the connected route shown by the current runtime state. Stop and record `blocked` or `inconclusive` if a required source, owner, consumer, or readback is unavailable. Do not infer a successful operation from target presence or a setter return.
2. Input chords: test both dominance choices, each chord order, a short press, a late press, a held constituent, and release to real neutral. Confirm recenter or panel behavior and verify that reserved constituents produce no detonation, horn, boost, pointer, or other gameplay output. Include one independent native-gamepad action.
3. Read-only overlay: open the existing panel route, keep the overlay visible while walking, firing, grabbing, and driving, and attempt pointer, grip-drag, keyboard, text, and scroll input. Hide and reopen through the existing route. Confirm gameplay ownership remains effective, the overlay does not edit, held inputs do not leak, and a previously disabled game input device stays disabled. Do not add an edit shortcut.
4. Flight and canopy: use an empty hand, then an occupied hand. Check the approved physical LT gun, RT rockets, upper-right B boost, and lower-right A contextual parachute mapping. Check fresh T-pose deploy, palms-forward brake, and interaction-aware arm closure. Acquire and release both free canopy handles only while native rest observations are current. Confirm UI, tracking loss, and hand manipulation do not become withdrawal gestures.
5. Held guns and action parts: in suit, swimming, and supported vehicle contexts, acquire a gun, hold and release its trigger, and attempt transfer, support, reload, and action work with the other hand. Check neutral ownership transfer and the game animation permission. Repeat slide, bolt, and pump with the free hand, and compare part-local and parent transforms while stationary and seated in motion.
6. Direct acquisition and snatch: try isolated and clustered eligible weapons with a close direct grip before remote snatch or transfer. Then test brief aim misses, occlusion, held fists, source changes, and floor approaches. Record the selected and armed identities, gesture samples, take result, and refusal stage. Confirm a direct candidate is not displaced by a remote offer.
7. Doors and props: approach closed vehicle doors by each handle, open the door, retain and move the loose panel, then release, push, close, and reacquire it with both hands. Grip both sides of a loose barrel, lift and turn it, add and release the second hand, then set down or throw it. Record unsupported or excluded prop cases as such.
8. Magazine, belt, and fingertip paths: check the runtime extraction route before testing loaded and empty magazines, chamber state, pull abort/reinsert, drop, weapon switch, and button eject. Test tactical and dry belt reloads, fast and sideways insertion, source gaps, and pending weapon changes. Compare the actual detonation point with the visible fingertip in tracked and fallback branches.
9. Support, throws, and heavy weapons: test both hands and both available pose paths. Hold support through sliding and action-part travel, transfer and release the gun, and compare one-handed heavy droop with two-handed support. For release throws, compare deliberate and slow releases, rotation, moving supports, post-disarm state, and the next-step body result when an authorized readback exists. Do not treat a missing readback as a pass.
10. Grenade displays and paired racks: verify an exact visible native grenade source or qualifying paired rack before attempting a draw. Test both hands, occupied holsters, source changes, stock, transfer, stow, incidental release, deliberate throw, and reset. A static shelf without a verified native owner is unavailable; do not substitute a body pouch or another source.
11. Moving platform and body: compare hand, gun, attachment, and part transforms while standing on a platform through translation, acceleration, braking, and turning. Test seated travel separately. Exercise body fit with walking, bend, crouch, turns, asymmetric reach, stairs, support loss, and recovery while recording source and support status.
12. Hull restoration: check the physical-hands switch, adapter state, body inventory, clearance reason, and restore status. Request restoration only in a clear area with the current path available. Include an obstruction/deferred case and confirm gameplay remains responsive. A deferred restore is not a pass; do not use teleportation or process restart as evidence of restoration.
13. Recording: verify the effective recording setting, full-joint selection, build provenance, and output path before capture. Exercise sustained recording, queue saturation, interruption, drain, and replay. Compare exact replay, bytes, memory, backlog, and drops. Keep measured compression and runtime acceptance pending until a real provenance-checked capture supports them.
