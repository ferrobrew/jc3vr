# Controls summary

The controller scheme hides the game's context button hints because their gamepad glyphs do not describe the controller bindings. A separate panel on the off-hand wrist shows current usable controls. The complete binding reference remains available through `summary::published().summary` for Input/bindings > Context and binding reference. The wrist uses `Published::current`, not that reference inventory. The implementation is in `payload/src/controllers/summary/` and `payload/src/hud/summary_panel.rs`. The engine hint and localisation behavior is described in [button-hints-and-localisation.md](../../engine/button-hints-and-localisation.md).

## Sources and eligibility

`describe_bound` and `SourceTable` remain the source of the full reference. It retains unbound rows and default fallbacks when runtime enumeration is unavailable. The wrist describes the same declarations with a source-only layout: unknown bindings receive no guessed default button. A known source without a glyph keeps the runtime's localized source name. Unbound rows never enter the wrist projection.

`summary::refresh` requires an `eligibility::Eligibility` snapshot from the central input owner after weapon finish and neutral-transfer reconciliation. `eligibility::resolve` admits ordinary actions already declared for the current mode, then applies explicit gates to contextual actions. Skip cutscene, handheld fire, reload, tether retraction/release, use, vehicle entry, grenade throw, and explosive placement require current action permission. The typed action set needs review when contextual mechanics change. Steering, camera, movement, and ordinary seat controls are not omitted merely because they lack a separate mechanic status.

The snapshot carries the input owner's final `CurrentRouting`. Its `ready` flags describe whole-hand focus, recovery, and tracking readiness. Trigger-transfer suppression is separate, so it does not hide a usable face button, stick, or grip. The producer applies the configured per-hand firing path, reload, docking, carrying, action, and engine shooting permission before publishing each trigger role. The summary does not rediscover ownership. Native-pair semantic fire remains distinct from synthesized per-hand gun fire.

The source-only description keeps physical hands separate until readiness filtering. Named display sources compare by hand and resolved runtime name rather than a table-local index. The full reference retains its exact source identifiers and folding behavior. `Published::wrist_revision` changes only when projected display content changes, so unrelated reference or source-index churn does not restart pagination.

Physical grip hints use the grab resolver's chosen target and its physical hand. The snapshot can supply other current physical mechanic rows with their real controls. Enabled features alone do not prove a usable target. Missing action permission, unavailable hands, and absent targets are retained as typed omission reasons in `Published::omitted`. The current adapter is bounded: contextual action permission and physical mechanic eligibility still require owning-subsystem integration. Passing the full reference as usable or passing an empty placeholder snapshot does not complete that integration.

The physical-hand provider supplies `OpenVehicleDoor` only for the resolver's actual selected, unheld, latched `DoorTarget`. A copied provider-owned offer retains the source epoch, sample time, and complete reach identity separately from diagnostic observations. Final capture requires the same fresh, unclaimed reach after finish, enabled physical hands, pickup, and doors, a ready physical hand, and no released or consumed grip. The resulting row is that hand's grip press with the label `Open vehicle door`. Open or held doors, other selected targets, stale sources, and ownership changes receive no row. This hint describes the mod's door grip; it does not grant native use or vehicle-entry permission or change door execution.

Parachute handle capture distinguishes an unheld handle from a held handle. The input owner supplies copied active `HandleHold` values before and after finish. Capture requires the resolver's selected handle for that physical side, enabled handles, the parachute context, a ready hand, and no released or consumed grip. An unchanged held owner supplies `PullParachuteHandle` on that hand's motion source with the label `Pull down to steer; pull both handles to brake`. An unheld selected handle supplies the grip-to-take row only while its final owner remains empty. A changed or missing owner, a different selected side or holder, and a non-parachute context supply no handle row. The configured bound reference retains its combined handle description. These rows describe the mod's existing handle mechanic and do not grant deployment, native use, or vehicle-entry permission.

The fixed suit bindings remain source-derived. Left-trigger machine gun, right-trigger rockets, right upper-button boost, and right lower-button canopy descriptions follow the actual runtime sources. The flight gesture owner supplies sustained recognizer availability separately from transition pulses and held braking. Its matched head/controller packet, mode, configuration, gameplay, canopy, occupancy, and interaction-claim gates apply at evaluation and late commit revalidation before summary refresh. The post-revalidation value enters `Eligibility.mechanics` without another game query. Falling admits the bilateral deploy sequence; Wingsuit admits the bilateral close and brake sequences. Their physical motion labels describe the mod's gesture sequences, not game-side permission. Vehicle, UI, and parachute contexts receive no flight gesture rows.

## Context hints and labels

The input tick reads the HUD's current queue through [`HUDUI::m_ButtonHints`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##field-m_ButtonHints) under a non-waiting lock. A busy lock retains the previous read. The full reference retains the separate context section. The wrist merges a current hint into the matching usable action row and retains each distinct usable source once within its spatial cell. A missing binding or ineligible route cannot be revived by a hint.

Native reload taps and held holster use separate current permissions and labels on the same resolved source. Holster does not require a partly empty magazine or native reload mode. Release and tighten hints likewise use independent, read-only permissions from the grapple-button state machine; tether count alone does not prove that a held press tightens.

Action labels use the game's localisation keys through [`Locator::GetLocalizedStringRaw`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::locator::Locator##func-GetLocalizedStringRaw), with the existing English fallback. The wrist removes repeated localized hold words when the row already has a hold prefix. Case-insensitive duplicate hint labels merge their sources. Runtime source names remain unchanged. The use-item and weapon-pickup prompts, notifications, and tutorials still use their native gamepad glyphs.

## Compact grid and pagination

The grid keeps physical left on the left and physical right on the right regardless of dominant-hand setting. Shared available actions and view/menu actions occupy a second side-by-side pair only when present. Empty pairs consume no height. Each cell has a four-row page budget. Text wraps at the configured readable row size. Overflow creates additional pages; it never causes iterative shrinking or a single vertical group stack. A single indivisible wrapped row can enlarge its page rather than lose text.

The production `grid::layout` helper measures the same row jobs and supplies the same rectangles used by the painter. The minimum width preserves readable two-column geometry even for an undersized texture setting. The texture has one stable size across its pages. Each footer shows the current page, page count, and the full-reference destination. An empty projection says `No usable controls here`.

No wrist next/back semantic route exists. The interim pagination policy cycles while the panel is actively shown, with an eight-second dwell and an explicit countdown. `page_clock::PageClock` is deterministic and renderer-independent. Hidden time and fade-out do not advance it. A new glance or content revision resets it to page one. No controller chord is added, and no gameplay navigation input is consumed. A future manual route must use an explicitly approved existing UI route rather than silently stealing a gameplay input.

## Visibility and rendering

The panel has its own egui context, renderer, render target, and quad pass. Eye zero advances visibility and pagination; both eyes draw the same cached world corners. The panel stays on the back of the off-hand wrist. Existing glance dwell, hysteresis, linger, trackpad-touch pin, mode-change display, placement, and fade settings remain in effect. Trackpad presses still cancel the pin rather than page the wrist. The health/heat wrist display remains a separate surface.

`controllers.summary` retains `enabled`, `hide_game_hints`, `show_on_glance`, `glance`, `show_on_trackpad_touch`, `show_on_mode_change_s`, `placement`, `width_px`, `row_px`, `max_height_px`, and `fade_s`. Page overflow does not lower `row_px`. `max_height_px` is a page budget rather than a request to shrink text.

## Verification and integration status

The frozen workspace passes Windows all-target, all-feature clippy and the Wine suite, including 2,655 payload tests. Current-summary tests cover actual source tables, readiness, native-pair subsets, named-source index churn, independent reload/holster and release/tighten permissions, hold normalization, and missing bindings. Renderer-free tests call the production measurement and paint helpers for empty, multi-page, and wrapped content. Page-clock tests cover dwell, wrap, hidden pause, and content identity. These results do not establish live readability or engine acceptance.

The shared refresh runs after final ownership reconciliation. Implemented providers cover held-gun permissions, native reload and holster, phase-aware tether controls, physical yank, selected vehicle controls, flick eject, the dominant hand's eligible belt reload, and several selected grip targets. The reload owner produces the belt row from copied post-step facts and a final ammo read after weapon finish. The offer requires the same input sequence, a current non-carry gun, a well and pouch, ammunition, magazine space or an unseated magazine, the draw delay, and no competing insertion or extraction claim. Final gun claims and hand readiness can revoke it before publication. The row retains its physical hand motion and does not use pouch model visibility or native reload-button permission. Consumed grabs and relevant ownership or reload mutations invalidate old choices until the next provider pass. Active cutscene skip, selected use/vehicle-entry prompts, and additional interaction-target labels remain unintegrated and are conservatively omitted. The flight provider covers only the supported Falling and Wingsuit gesture sequences; it does not establish general game-side flight permission. Those omissions keep the complete current-usable feature open. Overflow dwell, long localized headings and footers, minimum text size, and wrist geometry still require headset validation.
