# Weapon wheel

The weapon wheel opens the game's own selection cross with a held input and lets the hand choose an arm, as in Half-Life: Alyx. It is off by default (`controllers.weapons.wheel.enabled`, in the debug UI's weapons feature), because one game-drawn cross shared by both hands breaks the artifice of weapons drawn from the body's sockets. The code is `crates/jc3vr-weapons/src/controllers/weapons/wheel/`, tuned by the `wheel` section of `crates/jc3vr-weapons/tuning/inventory.toml`.

The game's selection logic is in [weapon-selection.md](../engine/gameplay/weapon-selection.md): four float slot-select actions, the largest held one wins, and the release commits. The wheel produces exactly that input through the binding injection, so the game's offer, highlight, sound, and commit rules stay in charge.

Two inputs open it, and the hand holding the opener steers: `weapon_select_press` (unbound by default, since the off-hand Index trackpad lies on the thumb's way to the debug panel chord), and `weapon_wheel`, the dominant stick pushed up, the one free stick direction. While the stick holds the wheel, the body turn reads zero. It opens only while the game reads the slot-select inputs ([`Inventory::GetAnimationAllowsSwitchWeaponGUI`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-GetAnimationAllowsSwitchWeaponGUI)).

The steering hand's turn from its aim at the open picks one of four arms in the cross's gamepad layout ([bindings.md](input/bindings.md#gamepad-semantics)), with hysteresis. An arm the game does not offer, per [`HUDUI::m_LastWeaponSelectionParams`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##field-m_LastWeaponSelectionParams), counts as the centre. The wheel always holds exactly one slot-select action and switches within a single tick, because a tick with all four at zero reads as a release; the centre holds the wielded weapon's arm, which the game treats as no change.

Releasing on another offered arm commits. Anything else cancels (the centre, the wielded arm, a mode change, a menu, the bindings standing down), and a cancel clears [`Inventory::m_SlotToSelectOnRelease`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_SlotToSelectOnRelease) for a few ticks so the game does not commit a pending selection; the input tick runs before the game's update, so the clear lands first.

The engine places the cross over the hips ([`HUDUI::UpdateWeaponSelectionPlacement`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##func-UpdateWeaponSelectionPlacement)), which in the headset clamps it to the panel's bottom edge, so a post-call detour (`wheel/placement.rs`) writes it where the line from the head through the steering hand meets the panel, clamped to the safe area. With the HUD atlas on, the cross is drawn at the hand on a quad of its own ([hud.md](hud.md#hud-depth)).

Unverified in game: that switching the held action retargets the highlight without a commit, that the cancel beats the commit in every case, and the comfort of the thresholds.
