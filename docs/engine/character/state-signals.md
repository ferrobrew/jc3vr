# Per-tick character state signals

The per-tick signals, read from the local `CCharacter` or a cheap singleton, that separate on foot, vehicle (and class), wingsuit, parachute, grapple traversal, swimming, and game UI up. The pyxis defs are mainly [`Character`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character), [`StateBitFlag`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag), and [`Clock`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock).

## The central mechanism: the character state-bitflag words

Almost every "what is the player doing" predicate is a one-bit read of the character's state-bitflag words. [`Character::m_ControlParameters`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_ControlParameters) points to the character's [`ControlParameters`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::control_parameters::ControlParameters), whose [`m_UserVM`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::control_parameters::ControlParameters##field-m_UserVM) holds the run of `u64` words [`UserVM::m_CurrentStateBitFlags0`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::control_parameters::UserVM##field-m_CurrentStateBitFlags0), [`m_CurrentStateBitFlags1`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::control_parameters::UserVM##field-m_CurrentStateBitFlags1), and [`m_CurrentStateBitFlags2`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::control_parameters::UserVM##field-m_CurrentStateBitFlags2). The bits are named by [`StateBitFlag`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag): flag `n` lives in word `n / 64` at mask `1 << (n % 64)`. Some predicates also require [`AnimatedModel::m_InstanceData`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AnimatedModel##field-m_InstanceData) (on [`Character::m_AnimatedModel`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AnimatedModel)) to be non-null; it and `m_ControlParameters` can be null in the first frames after spawn or stream-in.

The words are written during the sim tick's animation-graph evaluation, so a render-worker read races the write. The flags, verified in the IDB:

## The state-machine-hash predicates (vehicle riding, reeled in, hang)

The hash predicates compare the base rule system's current state hash (`m_AnimatedModel.m_RuleSystems[0]->m_StateMachineInstance->m_CurrentState->m_HashID.m_Hash`) against a set of state ids, sometimes ORed with a state bit or the grapple-hook state. They cost a few pointer chases and are authoritative where a raw bit is ambiguous or lags a transition:

| Predicate | What it establishes |
|---|---|
| [`IsInRidingInVehicleState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsInRidingInVehicleState) | seated and riding (idle, driver, passenger, or reverse states, or [`SB_IS_RIDING_MOTORBIKE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_RIDING_MOTORBIKE)) |
| [`IsInDrivingVehicleState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsInDrivingVehicleState) | the driver seat's driving states, or `SB_IS_RIDING_MOTORBIKE` |
| [`IsInVehicleAttachState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsInVehicleAttachState) | riding, or the enter, exit, switch-seat, or eject transitions (the widest vehicle test) |
| [`IsReeledIn`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsReeledIn) | fully reeled onto an attach point: a reeled hook state combined with [`SB_IN_GRAPPLE_ATTACHED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IN_GRAPPLE_ATTACHED), [`SB_IS_GRAPPLE_UPSIDEDOWN`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_GRAPPLE_UPSIDEDOWN), or the stunt and hang state hashes |
| [`IsGrappleHanging`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsGrappleHanging) | hanging from a reeled grapple (`GHS_REELED_HANG`, or `S_GRAPPLE_HANG`/`S_IDLE_HANG_STUNT`, or `SB_IS_GRAPPLE_UPSIDEDOWN`) |
| [`IsStuntTraversing`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsStuntTraversing) | stunt-position traversal (`S_STUNT_FWD/RIGHT/LEFT/BWD`) |

## Vehicle presence and class

[`Character::GetVehicle`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-GetVehicle) walks the graph's top-root object and fills a `boost::shared_ptr<CVehicle>` with `rtti_cast<CVehicle>`; [`GetVehiclePtr`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-GetVehiclePtr) is the raw-pointer wrapper. Both take and release a refcount (interlocked), so each costs more than a field read. The class predicates are RTTI `IsType` tests against the vehicle's `TYPE_ID`:

| Class predicate | `TYPE_ID` tested |
|---|---|
| [`IsAttachedToVehicle`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsAttachedToVehicle) | any (has a `CVehicle` and is graph-attached) |
| [`IsAttachedToLandVehicle`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsAttachedToLandVehicle) | `CLandVehicle` (car and motorcycle) |
| [`IsAttachedToAirVehicle`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsAttachedToAirVehicle) | `CAirVehicle` (plane and helicopter) |
| [`IsAttachedToSeaVehicle`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsAttachedToSeaVehicle) | `CSeaVehicle` (boat and jetski) |
| [`IsAttachedToHelicopter`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsAttachedToHelicopter) | `CHelicopter` |
| [`IsAttachedToMech`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsAttachedToMech) | via [`Vehicle::IsMech`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##func-IsMech) |

The `CButtonMapping::EMapping` sections give car, motorcycle, boat, jetski, plane, and helicopter each a mapping; the predicates combine as: helicopter, `IsAttachedToHelicopter`; plane, `IsAttachedToAirVehicle && !IsAttachedToHelicopter`; motorcycle, `IsAttachedToLandVehicle && IsRidingMC`; car, `IsAttachedToLandVehicle && !IsRidingMC`; boat or jetski, `IsAttachedToSeaVehicle`, which the RTTI does not split. The engine's vehicle-type enum, [`VehicleType`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::VehicleType) (`NVehicle::EVehicleType`: `ECAR`, `EHELICOPTER`, `EBOAT`, `EAIRPLANE`, `EMOTORCYCLE`, `ESUB`, and `ETRAIN`), stored as `CVehicle::m_VehicleType` and returned by the everywhere-inlined `CVehicle::GetVehicleType`, also folds the jetski into `EBOAT`; the jetski mapping comes from a jetski-specific type elsewhere. TODO: pin the `m_VehicleType` offset and the jetski discriminator.

The seat also decides the mapping: the context predicates test [`Vehicle::m_LocalPlayerSeat`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##field-m_LocalPlayerSeat) (a [`Seat`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Seat), `NVehicle::ESeat`, or `ENoSeatIdentifier` without a seat) against `EDriverSeat` for driver controls. `CVehicle::GetSeat` is bound as [`Vehicle::GetSeat`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/vehicle::vehicle::Vehicle##func-GetSeat).

## Grapple traversal states (`GHS_*`)

The hook's state machine is the finest grapple signal, independent of the animation flags. [`Character::GetGrapplingHook`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-GetGrapplingHook) returns the hook shared-ptr, and the raw pointer is cached in the inventory ([`Character::m_Inventory`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_Inventory), [`Inventory::m_GrapplingHook`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_GrapplingHook)). Its state, [`GrapplingHook::m_State`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##field-m_State), is a [`GrapplingHookState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHookState) (`EGrapplingHookState`): `GHS_INITIALIZING`, `GHS_INACTIVE`, `GHS_REELING_IN` (mid-reel), the reeled states `GHS_REELED_ATTACHED`, `GHS_REELED_HANG` (hanging), `GHS_REELED_UPSIDEDOWN`, and `GHS_REELED_STUNT`, and `GHS_CUSTOM_ACTIVE_WIRE`. The character's `IsReelingIn`, `IsGrappleHanging`, and `IsReeledIn` combine it with the animation state.

## Game UI up and gameplay input suspended

1. Hard pause (the pause menu). `CGameStateRun` copies the update context's [`GameObjectUpdateContext::m_Paused`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/game::GameObjectUpdateContext##field-m_Paused) into the [`PhysicsSystem`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/physics::PhysicsSystem) singleton's `m_Pause` and calls `CClock::Pause(true)`. `m_Pause` is nonzero for the whole pause; leaving clears both.
2. Pause until action. [`GamePauseUtility`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::game_pause_utility::GamePauseUtility), a `Base::CSingle` singleton, pauses the game until an action is pressed, for tutorials; it is not a weapon selector ([input.md](../gameplay/input.md#weapon-selection-rebel-drops-and-gear-mods)). Its first field, [`GamePauseUtility::m_state`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::game_pause_utility::GamePauseUtility##field-m_state), equals [`PauseState::E_STATE_PAUSED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::game_pause_utility::PauseState##variant-E_STATE_PAUSED) while the pause is up; [`GamePauseUtility::SetState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::game_pause_utility::GamePauseUtility##func-SetState) drives it.
3. Input focus (the map and the commlink). No pause; input focus switches to `CSteeringUI`'s static UI action map (`CSteeringUI::GetActionMap` → `m_ActionMapUI`), and the `CButtonMapping` band `FIRST_UI_MAPPING..END_UI_MAPPINGS` applies. The signal is `CSteeringUI` being the active steering; no per-tick global is pinned. TODO: pin it, from `CSteeringUI::m_SteeringUI` presence plus a focus check.

## What the game's pause freezes, and the clock split

Under a hard pause `CGameStateRun` runs [`GameStateRun::UpdateRenderPaused`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/game::GameStateRun##func-UpdateRenderPaused), which drives landscape LOD, UI prerender, video, `WaitForCPUDrawToFinish`, and resource streaming. It reads the active camera's already-computed `m_TransformF` but calls neither `GameCameraManager::UpdateRender` nor `CameraTree::UpdateRenderContexts`, so the camera transform stays frozen at its last value.

[`Clock::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##func-Update) keeps accumulators that always advance and ones that stop while [`Clock::m_Stop`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_Stop) is set:

| Field | Type | Behaviour in `Update` |
|---|---|---|
| [`m_FPS`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_FPS) | `f32` | `1 / m_SPF` |
| [`m_SPF`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_SPF) | `f32` | frame delta smoothed with an exponential filter, times `m_UpdateSpeed` |
| [`m_RealFPS`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_RealFPS) | `f32` | `1 / m_RealSPF` |
| [`m_RealSPF`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_RealSPF) | `f32` | raw frame delta |
| [`m_UpdateSpeed`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_UpdateSpeed) | `f32` | timescale multiplier on `m_SPF` |
| [`m_Time`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_Time), [`m_RealTimeAtUpdate`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_RealTimeAtUpdate) | `u32` | milliseconds, always advance |
| [`m_PauseTime`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_PauseTime) | `u32` | milliseconds, stops while `m_Stop` is set |
| [`m_GameTimeMicro`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_GameTimeMicro) | `u64` | microseconds of `m_SPF`, always advances |
| [`m_GameRunTimeMicro`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_GameRunTimeMicro) | `u64` | microseconds of `m_SPF`, stops while `m_Stop` is set |
| [`m_CpuFrequency`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_CpuFrequency) | `u64` | performance-counter frequency, the divisor for all deltas |

[`Clock::Pause`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##func-Pause) writes `m_Stop`, and on entering a pause snapshots `m_RealTimeAtUpdate` into [`m_PauseTimeAtUpdate`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_PauseTimeAtUpdate) and [`m_RealTimeAtUpdateGame`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_RealTimeAtUpdateGame) into [`m_PauseTimeAtUpdateGame`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##field-m_PauseTimeAtUpdateGame); these and the three millisecond counters above are the six `u32` fields the pyxis `Clock` binds. `m_SPF` is not zeroed during a pause; [`Clock::GetSPF`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock##func-GetSPF) returns [`Clock::PAUSED_SPF`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/clock::Clock::PAUSED_SPF) while `m_Stop` is set unless its `ignore_pause` argument is true. So game time can stop while the real clock keeps running.

## State overlap and precedence

The states overlap: a reeled grapple is also airborne, a wingsuit dive is also falling, wingsuit and parachute both count as falling, a vehicle-parachute is both an attach state and a parachute state, `IsInVehicleAttachState` spans the enter and exit animations, and the pause and UI signals hold whatever the character state beneath. Vehicle transitions, the grapple wind-up, and reel release pass through states where the coarse bit is not yet set though the body is committed; the hash predicates and the pre-reel and pre-hang bits cover them, and a blend frame can flip a predicate for a single tick. `IsSwimming` is set independently of the on-foot locomotion task, and on a teleport tick the signals can misclassify the frame.

The `EvaluateCharacterOrientation` call count advances every on-foot tick including idle ([root-motion-and-proxy.md](root-motion-and-proxy.md#the-locomotion-task-runs-at-idle-and-writes-the-proxy-input-directly)), so it corroborates on foot but identifies no other state.

## Ledge climbs and vaults

The player's one ledge climb is the grapple's. Reeling in to a ledge ends in the climb over it (`ACT_GRPL_CLIMB` into `S_GRAPPLE_CLIMB_START` in `rico_base.afsmb`), and the climb's motion task, [`NStateTask_ReeledInLedgeClimbMotionTask`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::NStateTask_ReeledInLedgeClimbMotionTask), carries the character over: its [`Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::NStateTask_ReeledInLedgeClimbMotionTask##func-Update) runs on every tick the climb's state is active, writes a code-controlled wanted velocity along the climb (from the climb segment's local time while it plays, the animation's root velocity after), and sets the task-defined motion state. No flag marks the climb; the task running is the signal.

There is no on-foot vault or obstacle climb. The act table has `ACT_START_VAULT`, `ACT_END_VAULT`, and `ACT_CLIMB_OBSTACLE`, but no state machine under `animations/jc_statemachine` (Rico's graphs and the NPCs', base and patch archives alike) names them or any vault state, so nothing would accept them. `CPfxCharacterInstance::CheckLedges` is not a ledge grab: it pushes ledge points to the proxy so the character clamps to its support surface at a ledge's edge (`m_LedgeClampToSupportSurface`; unverified).

## Hit reactions and scripted sequences

For a player ([melee-and-damage.md](../gameplay/melee-and-damage.md#the-hit-reaction) has the rest), [`Character::HitReaction`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-HitReaction) picks by the character's thresholds a ragdoll, a knock-back from an explosion ([`ACT_HITREACT_FLY`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::symbol_table::EventIdSymbolTable), or the full ragdoll when the state machine refuses it), a stumble ([`ACT_HITREACT_STUMBLE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::symbol_table::EventIdSymbolTable), or its bullet or melee variant, each tested with the state machine first), or a flinch. It queues the act on the animated model with [`AnimatedModel::QueueAct`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AnimatedModel##func-QueueAct), which [`Character::QueueAct`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-QueueAct) only forwards to. In `rico_base.afsmb` the stumbles lead to the `S_JC_HITREACT_STUMBLE_*` states and the knock-back to `S_JC_HITREACT_FLY_*`.
