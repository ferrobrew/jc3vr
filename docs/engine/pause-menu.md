# The pause menu and its Scaleform screen

The screen framework, the `ui/pause.gfx` movie's structure and widgets, its traffic with native code, its input, and what code outside the movie can reach. The constants and hashes are in the pyxis modules [`ui::pause_ui`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/ui::pause_ui), [`ui::ui_base`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/ui::ui_base), and [`ui::scaleform`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/ui::scaleform). The native side is verified in the IDB; the ActionScript is read from the decompiled movie ([Reading the movies](#reading-the-movies)), and statements resting only on it say so.

## Screens and the root movie

Every Scaleform screen is a static [`UIBase`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase) subclass, and all share one root movie, `ui/root.gfx`, whose AS3 keeps a hard-coded table from screen class name to movie file, draw order, and input level (`CPauseUI` maps to `pause`). Activating a screen calls the root's `Activate(<class name>)`, which loads `<file>.gfx` with a `flash.display.Loader`, adds it to the root's display list, and reports it through the ExternalInterface call `<class name>:active`. [`UIBase::BaseHandleCommand`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase##func-BaseHandleCommand) stores the clip in [`m_Clip`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase##field-m_Clip), marks the screen active, and calls [`OnActive`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase##vfunc-OnActive).

Every deactivation (the movies' own commands, `CUIManager::ForceDeactivatePause`, the UI manager's event handling, and the game-state transitions) goes through [`UIBase::Deactivate`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase##func-Deactivate). Unless the screen is inactive, it calls [`OnDeactivate`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase##vfunc-OnDeactivate) synchronously, on the requesting thread with the clip still loaded, then has the root unload the movie (`unloadAndStop`), which reports `inactive`, calling [`OnInactive`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase##vfunc-OnInactive) and releasing the clip. [`PauseUI::OnDeactivateImpl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-OnDeactivateImpl) has the settings manager save when any setting changed, so changes are saved however the menu closes, with or without `persist_changes`. The native screen object lives for the session; the movie is loaded fresh on each activation, so AS3 state is lost when the menu closes.

Application domains are disabled, so every loaded movie shares one AS3 class namespace: a class from any loaded movie can be constructed by qualified name, from AS3 or through [`MovieImpl::CreateObject`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::MovieImpl##func-CreateObject). `uibase` and the `shared.*` widgets are compiled into several movies; the first definition loaded wins.

### Calls from the movie to native code

AS3 reaches native code only through `ExternalInterface.call("<class name>:<command>", ...)`; no movie uses `fscommand`. `uibase.Invoke(name, ...)` prefixes the screen's class name, coercing `name` to text (so a document's `Invoke` taken as a callback sends its integer argument as a command name); `SendEvent(name)` and `PlaySound(name)` are both `Invoke("event", name)`; helpers such as `SetSettingValue` and `GetLocalizedStringFromString` name their own commands. [`ScaleformEIHandler::Callback`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::ScaleformEIHandler##func-Callback) splits at the colon, ignores the root movie's prefix, finds the screen (the movie's user data, or the screen registered under the prefix; an unknown prefix is dropped), and calls its [`HandleCommand`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase##vfunc-HandleCommand) with the `hashlittle` hash of the command. The call is synchronous, so the handler's changes to the movie are visible to the caller when it resumes. Return values go through [`SetExternalInterfaceRetVal`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::MovieImpl##func-SetExternalInterfaceRetVal). The base handler covers the shared commands; `event` posts its argument as an engine event.

### Calls from native code to the movie

The engine calls AS3 methods on a screen's clip through the [`Invoke`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase##vfunc-Invoke) virtual, implemented only by [`UIBase::InvokeImpl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase##func-InvokeImpl), which calls at once when the screen is active and the caller is the capture thread and otherwise queues the call for the screen's next update. Every native access to AS3 goes through the per-movie [`ValueObjectInterface`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::ValueObjectInterface) (`GetMember`, `SetMember`, `Invoke`, `GetArraySize`, `GetElement`, `SetElement`, `PushBack`, `RemoveElements`); values are built with `MovieImpl::CreateObject`, `CreateArray`, `CreateString`, and `CreateFunction` ([scaleform.md](scaleform.md#native-access-to-a-movie)). All of these run AS3 synchronously and belong on the capture thread.

## The pause movie

The document class of `ui/pause.gfx` is `pause` (extending `uibase`), with its code in `pause`, the `pause_code` package, and a few timeline classes. It compiles in its own copies of `uibase`, `shared_lib`, and several `shared.*` widgets (`generic_scrolling_list`, `generic_scrolling_list_row`, `scrollbar_manager`, `button_hint_bar`, `ctx_menu`, `c_msgbox_base`, `menu_button`, and others), but not the tab bar `shared.main_nav`, which it imports from `ui/shared_lib.gfx`.

### Menus and entries

The movie is not tab-driven. It shows one list of entries at a time on a fixed column of main buttons ([`MAIN_BUTTON_COUNT`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI) `stat_category_button` instances `MCI_button_00` onwards under `MCI_button_container`; entries past the last are not shown), and keeps one list per [`PauseMenuType`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseMenuType). An entry is an `OptionClass`: a name, a type, and for event entries an event string, whether to confirm, and whether to close the menu. `SwitchToMenu(type)` lays a list out on the buttons. The lists are built by:

- `InitMenu(valid_menus, dlc_flags)`, which builds each valid menu's fixed list once per movie (a second call builds only menus the first left out). The options list is graphics (PC only), sound, gameplay, controller mapping, keyboard mapping (PC only), credits, and DLC. The in-game menu's fixed entries are options and, when the main-menu list is already built, main menu; `InitMenu` builds the main-menu list first, so both arrive. The front-end's are options and, for SKUs that show it, the membership link.
- `AddEventOption(menu, folder, label, event, add_to_top, need_confirm, confirm_text, close_menu)`, which appends or prepends an event entry.
- `AddOption(menu, folder, label, add_to_top)`, the public primitive under both, which returns the new entry with public fields.

The valid menus, [`m_IsValidMenu`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##field-m_IsValidMenu) passed as an array of booleans, are in game [`SetPauseGameMenu`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-SetPauseGameMenu)'s set (in-game, options, controller mapping, and the main-menu submenu except on Boom Island), on the title screen [`SetFrontEndMenu`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-SetFrontEndMenu)'s (front-end, options, controller mapping). The developer and proctor menus are never valid.

After `InitMenu`, [`InitShipMenu`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-InitShipMenu) and [`InitFrontEndMenu`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-InitFrontEndMenu) add the engine's entries through [`AddEventOption`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-AddEventOption), mostly to the top, so a root menu reads as the engine's top entries in reverse order of adding, the fixed entries, then the engine's appended ones. The in-game menu is resume, skip video or cutscene while one plays, the active mission's quit and restart and the active challenge's restart and quit when they apply, options, main menu, and go online when reconnecting is not enabled. The front-end menu is continue or start, start new game, Boom Island, and the DLC store, then options and the membership link, then go online and exit. Nothing can be inserted mid-list from outside: `AddOption` only appends or prepends, and the lists are private.

A non-empty `folder` puts the entry in a folder entry of that name, created on first use; selecting it opens the folder (`OpenFolder`, up to two levels, with `< BACK` appended), drawn on the developer menu's text fields (`TXT_root_*`, `TXT_sub_*`, `TXT_sub_sub_*`) with the main buttons hidden, and only the in-game menu's back handling closes one. It is the developer menu's structure; the shipped menus use no folders.

`pause.OnSelect` dispatches on the entry's type in a hard-coded chain chosen by the document's menu state, reading the selection from the main buttons of the list on show. An event entry ([`OPTION_EVENT`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI), a new entry's type) sends `m_Event` as the `event` command (confirming first if asked) and closes the menu when `m_CloseMenu` is set; in a root menu the other types switch menus (options, main menu, controller and keyboard mapping) or open a folder, the membership page, or the Tomb Raider video. Only the options branch opens the settings screen (graphics, sound, gameplay, and DLC, each on a fixed page) or the credits; a root-menu entry of the graphics type does nothing. Both branches play `jc3_gui_msg_box_show_hide`. No type opens an arbitrary page, and the chain cannot be extended from outside.

`SwitchToMenu`, `OnSelect`, and `ShowPauseFromHideCredits` are public; the last, used by the credits to return, puts the document in the options state and shows the main buttons without laying out a list. The main-button container (`MCI_button_container.MCI_root`) is a dynamic timeline class and takes members of any name.

[`PauseUI::OnActiveImpl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-OnActiveImpl) fills a fresh movie in order: `InitMenu`, the engine's event entries, the player and infocast text, and `SwitchToMenu` to the in-game or front-end menu. The options menu is laid out only when the player switches to it, so entries added to its list after `OnActiveImpl` are shown.

### The settings screen

The settings screen (`MCI_settings_screen`, `pause_code.settings_screen`) shows one page of rows from the document's public `m_SettingsArray` of page objects `{m_Name, m_Settings}`. Opening it (the private `pause.ShowSettings(page)`) first invokes `populate_settings`: [`PauseUI::PopulateSettings`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-PopulateSettings) empties the array and [`SettingsUI::PopulateSettingsMenu`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::SettingsUI##func-PopulateSettingsMenu) refills it with the graphics, sound, gameplay, and DLC pages in `PAGE_*` order ([`SettingsUI`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::SettingsUI)). Only then does the screen read the array, so what native code leaves in it during that call is what shows. [`PauseUI::UpdateImpl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-UpdateImpl) also repopulates it and has the screen redraw (`RefreshCurrentSettings`) whenever [`m_RefreshSettings`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##field-m_RefreshSettings) is set.

The screen owns a tab bar (`MCI_tabs.MCI_navbar`) that no shipped screen shows. `settings_screen.Show(page)` names a selector for each of the graphics, sound, and gameplay pages, locks the next five, sets the bar's callback to its own `SetNewCurrentScreen`, selects `page` through it, and hides the bar; `controls_screen.Show` hides it too. The page is chosen by the options entry selected. The list manager's screen index, which decides whether a change goes as `set_setting_value` or `set_upgrade_value` (the DLC page), is set by `Show` alone.

`SetNewCurrentScreen(page)` saves the current page's list position (`GetTopIndex`, `GetSelectedRow`) in the private `m_TabData` by page index, slides the panel out and in, shows the new rows, and restores `m_TabData[page]` when set; for the current page it skips the save and slide. `m_TabData` lives until the movie unloads. Because every native path goes through `Show` and the bar is hidden, the only writer of `m_TabData` is the controls screen's shoulder buttons, which step the hidden bar and so call whichever callback the settings screen last set.

The page is drawn by `MCI_panel.MCI_container.MCI_root.MCI_manager`, a `pause_code.controls_manager` (a `shared.generic_scrolling_list`): a title field, a fixed set of `pause_code.controls_row` clips ([`ROW_CLIP_COUNT`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::SettingsUI), `MCI_controls_row_00` onwards, each returning its row object from `GetData()`) over a scrolling window of rows, a scrollbar, and a button-hint bar (select, reset value, reset all, back). Its public methods: `SetRowArray(rows)` shows rows from the top; `UpdateRows(top_index)` refills the visible rows in place; `HighlightByIndex`, `GetTopIndex`, `GetSelectedData`, and `GetSelectedRow` (the selected row's index in the page); `RestoreSavedState(top_index, selected_row)` scrolls and highlights without clearing the previous highlight (the screen calls `DeHighlightCurrent` first); `HighlightNext` and `HighlightPrev` move one row. The screen's `RefreshCurrentScreen` redraws from the top with the first row highlighted.

### Row objects and widgets

A row is a plain AS3 object whose `m_Format` selects the widget (`WIDGET_*` on `SettingsUI`). [`SettingsUI::AppendSettingToggle`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::SettingsUI##func-AppendSettingToggle) shows the native side: it creates the row with `UIBase::CreateObject` and fills it through the static [`SetIntField`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/ui::ui_base##func-SetIntField) and [`SetStringField`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/ui::ui_base##func-SetStringField), which pass unmanaged values (an int, or a C string the movie copies).

- Every row has `m_Name` (drawn upper-cased), `m_Type` (an integer sent back with the value), `m_Value`, `m_DefaultValue`, and `m_NeedConfirm`.
- A toggle shows the `m_Labels` entry whose `m_Values` entry equals `m_Value`, or `---`. Selecting it opens the shared context menu (`MCI_ctx_menu`, `shared.ctx_menu.ctx_menu`) listing every label. It is the game's only option picker and serves any number of choices.
- A slider (`pause_code.slider`) shows a notch between `m_MinValue` and `m_MaxValue`, integers only, with no number. Left and right move it by a fixed fraction of the range; the mouse drags it.
- A key-binding row shows a glyph or `m_KeyText` with a hold or release prefix from `m_Interaction`. Selecting it invokes `get_key_for_action` with `m_Action` when `m_IsCustomizable` is set, and plays a refusal sound otherwise.

`controls_manager.AssignNewValue` writes a change to `m_Value`, redraws the row, and calls `SetSettingValue(m_Type, m_Value)` (`SetUpgradeValue` on the DLC page), then asks to keep or revert when `m_NeedConfirm` is set. The special button resets the selected row to `m_DefaultValue`; Y resets every row on the page with one `SetSettingValue` each, or, on a key-binding row, all key bindings.

There is no header, read-only, or button row and no help pane. A row clip (`pause_code.controls_row`, parts in `MCI_row`, a dynamic timeline class) knows only the three formats; its frames are the selection states (`normal`, `overstate`, `down`, `selected`) and the empty `inactive`, used past the last row, at which up and down stop, so an empty row cannot separate groups. The only non-interactive title is the list's `MCI_title`, a single-line field over a separator (`MCI_line`) showing the page name, about a row label's height; every row clip draws the same separator. The shared message box (`MCI_msgbox`, `shared.msg.c_msgbox_base`: header, body, and a short option list) is the only place for longer text, used for the confirmations.

### The tab bar

`shared.main_nav`, from `ui/shared_lib.gfx` (also referenced by `ui/comm_link.gfx` and `ui/rom.gfx`), holds a row of `shared.nav_button` selectors ([`TAB_COUNT`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::SettingsUI), `MCI_button_00` onwards, in the public `m_Selectors`) between two shoulder-button hints. Its public methods are the whole interface:

- A selector's `SetButtonVariables(name, unused)` sets its label; `SetSelected` and `SetDeselected` animate it; `SetNew` shows its "new" badge.
- `SetButtonLocked(index, locked)` hides or shows a selector and lays the unlocked ones out by label width (`RedistributeButtons`); the unlocked selectors, in index order, are the tabs the shoulder buttons cycle.
- `SetSelectFunctionCB(callback)` sets the callback and `SelectScreen(index)` calls it. Clicking a selector calls `FindUnlockedIndex(index)` and `SelectScreen(index)`; a shoulder hint click, `OnNextTabButton`, or `OnPrevTabButton` steps to the next or previous unlocked selector, wrapping. The bar never changes which selector shows selected; the callback does.

The bar is placed on the document's first frame and never removed, so its visibility is whatever code last set.

### Commands the pause movie sends

[`PauseUI::HandleCommandImpl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-HandleCommandImpl) handles them; their hashes are the `COMMAND_*` constants on [`PauseUI`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI). The settings-related ones:

| Command | Arguments | Native handling |
|---|---|---|
| `populate_settings` | none | `PopulateSettings` |
| `set_setting_value` | `m_Type`, `m_Value` (ints, no type check) | sets `m_AnySettingsChanged`, then [`SettingsManager::SetValue`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/settings_manager::SettingsManager##func-SetValue), which ignores a disallowed value |
| `get_setting_value` | `m_Type` | returns the value |
| `set_upgrade_value` | `m_Type`, `m_Value` | loads the chosen DLC gear upgrade |
| `get_key_for_action` | `m_Action` | starts a key capture, sets `m_Waitingforkey` |
| `restore_default_keymap` | none | `RestoreDefaultMapping` |
| `persist_changes` | none | `PersistChanges`: the settings manager saves when anything changed |
| `load_controller_mapping` | category | fills the controls screen's rows |

The movie also sends `show_fullscreen_video`, `hide_fullscreen_video`, `request_new_infocast`, `check_dlc_sell_messages`, the membership-page commands, and through `event` the entry events (among them `ui.manager.disable_pause`, which closes the menu) and every sound.

Besides `InitMenu`, `AddEventOption`, and `SwitchToMenu`, the engine invokes `SetOptionEnabled`, `SetPlayerInfo`, `SetInfoCastText`, `ShowPercentageInstall`, `UpdatePercentageInstall`, `HidePercentageInstall`, `RefreshCurrentSettings`, `RefreshKeyMap`, the membership-page methods, `ShowMercenaryModePrompt`, `ShowSellDLCMessage`, and the input handlers below, and reads `m_SettingsArray`, `m_ControllerActionArray`, and `m_KeyboardActionArray` off the clip.

## Input, focus, and navigation

Gamepad and keyboard input reach the movie only as method calls. Each frame the screen with the highest input priority runs [`OnManageInput`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase##vfunc-OnManageInput), and [`UIBase::BaseOnManageInput`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase##func-BaseOnManageInput) turns the steering's UI actions into `Invoke` calls with no arguments: `OnUp`, `OnDown`, `OnLeft`, `OnRight`, the `OnDpad*` family, `OnSelect`, `OnCancel`, `OnSpecialButton`, `OnYButton`, `OnNextTabButton`, `OnPrevTabButton`, and the page buttons. The pause screen adds gamepad-only select and cancel handlers for the membership page.

The document routes each handler by a private `m_MenuState` (the main-button lists, the settings screen, the controls screen, a confirmation box, the credits, and a few more); there is no page stack. In the settings screen, `OnCancel` first closes an open context menu or message box, and otherwise leaves through `HideSettings`, which puts the document in the options state, plays the panel back to the main buttons without laying out a list (so they show whichever list they showed before), and sends `persist_changes` last. In the options menu back returns to the in-game or front-end menu; in the in-game menu it closes the pause menu. A message box or video remembers one previous state. The tab buttons do nothing in the settings screen; in the controls screen they step the hidden tab bar (see [the settings screen](#the-settings-screen)), not the controls screen's own categories, which are chosen from the controller-mapping menu's entries.

The mouse works through AS3 mouse events on the widgets: rolling over a main button or row highlights it and releasing activates it; the slider drags; the tab bar's arrows and selectors call its callback; the hint bar's hints and the back button (shown only without a gamepad) call the document's handlers. A release elsewhere while a context menu or message box is open in the settings or controls screen cancels it. Gamepad focus and mouse hover share one highlight.

## Reaching the menu from outside the movie

Public on the loaded `pause` clip, which [`UIBase::m_Clip`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_base::UIBase##field-m_Clip) holds while the menu is open, are `AddOption` and its entries' fields, `m_SettingsArray`, the settings screen with its list manager and row clips, the tab bar, the message box, and `RefreshCurrentSettings`. Private are `m_MenuState`, `ShowSettings`, `OnSelect`'s dispatch, and the entry lists, though the public `SwitchToMenu` and `ShowPauseFromHideCredits` set the menu state and `OnSelect` dispatches on an entry's public `m_Type`. Whether native `GetMember` resolves an AS3 private member is untested.

The `pause_code.*` classes are constructible by name only while the pause movie is loaded, `shared_lib` classes whenever `shared_lib.gfx` is; a second movie in the shared domain gains nothing over native `CreateObject` and `Invoke`.

Native code sees the menu at [`PauseUI::OnActiveImpl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-OnActiveImpl) (loaded and built), [`PauseUI::PopulateSettings`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-PopulateSettings) (the settings screen is about to read its pages), and [`PauseUI::HandleCommandImpl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::pause_ui::PauseUI##func-HandleCommandImpl) (every change), all on the capture thread inside the root movie's advance. The movie file is read through [`ScaleformFileOpener::OpenFile`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::ScaleformFileOpener##func-OpenFile), and `ui/pause.gfx` is one of the movies the UI manager's file cache keeps ([scaleform.md](scaleform.md#files)).

## Reading the movies

The shipped movies are CFX files (a zlib SWF with a renamed signature and Scaleform's exporter tags), which JPEXS FFDec reads directly. `scripts/fetch_ffdec.sh` fetches a pinned FFDec into the git-ignored `vendor/ffdec/`, and `scripts/ffdec.sh` runs it headless, for example `scripts/ffdec.sh -export script <out dir> <movie>.gfx`. Export into a git-ignored directory; decompiled game code is never committed. Extract the movies with the Gibbed tools, taking the `patch_win64` copy where one exists.
