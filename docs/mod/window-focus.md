# Window focus during a VR session

The game freezes itself when its desktop window loses the foreground ([engine/window-focus.md](../engine/window-focus.md)). In VR the desktop focus says nothing about where the player is looking, and it changes often (focus-follows-mouse, an overlay such as WayVR, a terminal), so left alone the headset view, head pose, and controllers would freeze until someone clicked the window.

`crates/jc3vr-view/src/hooks/window_focus.rs` detours [`LoseFocus`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/window::LoseFocus) and [`GainFocus`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/window::GainFocus), where the main loop applies and lifts the suspension, so skipping them keeps the frame, the audio, and the fullscreen mode running together. They run outside `Game::Update`, so they read the session from `vr::is_running_published` rather than the runtime lock ([threading.md](threading.md#lock-rules)).

While a session runs, a `LoseFocus` is skipped except that it clears [`m_IsInFocus`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_device_manager::InputDeviceManager##field-m_IsInFocus), because the mouse is a background device and would otherwise turn the camera from another window; gamepads and the OpenXR controllers ignore the flag. The paired `GainFocus` is skipped too and only sets the flag again, since the engine's version would apply a stale fullscreen mode. A suspension from before the session (focus lost on the main menu) is lifted by `window_focus::resume_for_vr` at the top of each `Game::Update`. Without a session both functions run unchanged.

It is unverified in the headset whether anything else in the frame depends on the skipped pause event, and whether `resume_for_vr` behaves in exclusive fullscreen with the window still in the background.
