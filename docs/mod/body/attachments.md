# Body attachment observations

The body mirror consumes copied input-tick observations for weapon sockets and copied render-time matrices for pouch props. It does not read a weapon, a source model, or a model instance on the pose-finalization thread. The finalized skeleton, wrist targets, socket observations, and render-time pouch comparison retain distinct sampling phases.

## Weapon sockets

`controllers::weapons::docks::socket_points` observes the socket weapons under its existing input-thread safety contract. It returns a copied native `attachments::Sample` to the input tick. `controllers::weapons::begin::socket_candidates` selects the interaction target poses, returns candidates from that selected sample's `points()`, and publishes the same selected sample for the mirror. The sample records the character identity, timestamp, source character transform, target policy, socket occupancy, loadout item identity, source object identity, hand-specific usage, and pose or missing reason.

The native pose sources are a visible weapon grip, a remembered bone-relative grip, a native socket bone, a configured offset from a socket bone, and an unavailable socket weapon. With `follow_docks` disabled, the existing body-landmark helper supplies the hip, shoulder, and chest interaction poses with the configured holster offsets. The selected pose has the explicit `BodyLandmark` source and retains the copied native source and pose separately. A draw target at a landmark is distinct from its native visible grip. A docking target at a landmark does not place a native weapon there. Native inventory placement continues to own the socket bones and weapon offsets. The outer back has no landmark and retains its native target. A missing body retains the existing native fallback and records `NativeWithoutBody`; missing native poses do not create new landmark offers.

Object identities are diagnostic values. They neither retain an object nor authorize a grab. The existing loadout and grab rules still determine draw, dock, and no-fit behavior. Hand restrictions, occupancy, item identities, offer ordering, and radii remain unchanged. The occupied-but-unobserved socket fallback remains a no-fit observation with occupied state.

The mirror rebases copied poses through the character's current world transform. This follows character or platform movement without another bone read. It does not refresh the input observation's timestamp or reconstruct the current skeleton pose. Foreign characters, observations older than the bounded age, future timestamps, and invalid source or destination transforms produce no sample. A visible grip remains usable when its bone orientation is unavailable; the orientation line then uses a neutral orientation.

The mirror shows actual hand-specific offers where present. Otherwise, it shows the socket observation. Occupied sockets use amber rings, empty offers use cyan rings, no-fit offers use red rings, and neutral empty-socket estimates use gray rings. Landmark interaction targets use smaller rings than native observations. A missing pose produces no marker. Missing counts remain available through `controllers::body::mirror::attachment_status`. Holsters must be enabled, and the copied sample's target policy must match the current `follow_docks` setting. A policy change cannot relabel an old native sample as a landmark sample. The comparison establishes interaction-target diagnostic parity, including the body-landmark mode. It does not establish displayed native weapon-pose parity.

## Pouch props

The grenade and C4 pouch centers use the same volume helpers as their interaction targets. The magazine prop uses the reload provider's stocked pouch. `controllers::weapons::pouch_models::attachments::placement` converts that supplied pouch pose into character model space and applies the configured prop offset and rotation. The input loop uses the resulting local transform directly and copies the observation with its input character transform. Interaction centers retain their input-tick behavior; they do not acquire render interpolation.

Each input observation records its kind, side, optional magazine weapon identity, borrowed source-model identity, pouch pose, model transform, and instance visibility. An unoffered pouch is distinct from an offered pouch whose source model is unavailable. The observation has an owner identity, an owner epoch, a producer-local input sequence, and a bounded age. Identities never authorize pointer dereferences. Stand-down clears the observation, advances the epoch, and clears the retained pouch submission. Owner changes release the old instances before accepting another owner's placements.

`pouch_models::render_frame` computes the displayed matrix from the character and local placement histories. Immediately after applying that matrix to the owned instance, it copies the same matrix value into `attachments::RenderSample`. The mirror consumes that value during the same render call, after the model-state lock is released. It does not rebuild the model matrix or read native state. Each render call advances a producer-local render sequence. The render observation records that sequence and the input observation's identity separately. These are local phase identities, not engine frame numbers, and timestamps are only an expiry check.

`controllers::body::mirror::PouchRenderContext` derives the plane from the character transform copied for that render call, using the same interpolation helper as model placement. The context and render sample must have the same render identity. Pouch primitives use world anchors, so the comparison does not depend on an older pose-finalization head sample. The plane can differ from the skeleton mirror's input-rate plane during motion. No head-frame or finalized-skeleton parity is claimed.

The render mirror draws a green ring and orientation line from the applied model matrix. A cyan ring marks the copied interaction center, carried through its captured input transform, and a line joins that center to the displayed model origin. A hidden, missing, unapplied, or source-mismatched model has only a red interaction ring when its target exists. `pouch_render_status` records the render and input identities, displayed-model count, target count, and missing-model count for the same comparison.

`Source::BodyMirrorPouches` owns the retained render submission. It does not replace `Source::BodyMirror`, which retains the skeleton and socket observations. Each render call clears the prior pouch submission before any early return. Visibility and source changes, stand-down, an unavailable owner, and owner changes also clear it. Missing or expired input observations and invalid render transforms cannot republish a previous render matrix. The retained slot's bounded lifetime also removes output if the render producer stops.

## Boundaries and verification

The shared providers change attachment placement values and diagnostics. They do not change claims, ammunition, model ownership, native inventory writes, reload actions, or current-joint validity. Socket interaction candidates still pass through the existing cockpit-frame conversion and resolver. Pouch models still use the existing instance creation, visibility, interpolation, and release paths.

The socket tests compare the production point adapter with the production mirror renderer across remembered body poses, visible grips, missing bones and grips, native and configured fallbacks, character rebasing, cockpit conversion, owner changes, age expiry, and invalid transforms. The body-landmark tests call the production candidate provider and compare its returned centers with canonical sample points and rings from the production mirror renderer through the same plane. They cover bends, platform translation and rotation, configured offsets, occupied draw targets, empty docking targets, no-fit offers, missing native poses, a missing body, the outer-back fallback, retained native provenance, policy changes, and expiry. The pouch tests feed the production render-matrix output into the production applied-matrix adapter and marker helper at interpolation fractions `0`, `0.5`, and `1`. They cover each prop, both sides, local and body rotations, platform movement, unchanged input targets, model identity mismatches, hidden and unapplied models, absent offers, invalid transforms, owner and epoch changes, age expiry, mismatched render contexts, and retained-source isolation.

The copied attachment status is separate from `MirrorStatus`, so existing status consumers remain source-compatible. Socket status belongs to the last solve pass; pouch availability and missing counts belong to the separate render publication. The detailed pouch status distinguishes both sample identities and counts. Input-tick attachment observations can differ from the later finalized skeleton and displayed models. This comparison establishes exact pouch render placement only; it does not establish full attachment, grab-target, head-frame, or skeleton parity.
