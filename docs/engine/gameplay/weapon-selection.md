# Weapon selection

The game has no stick-steered radial wheel and no slowdown while selecting: the HUD's selection cross is four arms that appear while a slot-select button is held, highlight the held slot, and commit on release. The default buttons are in [input.md](input.md#the-default-gamepad-keymap).

Unlinked native functions below are verified in the IDB but not yet bound. The movie side was read from `ui/hud.gfx`'s ActionScript.

## The actions

The actions are the four slot selects, [`SELECT_DUEL_WIELD`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-SELECT_DUEL_WIELD), [`SELECT_TWO_HANDED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-SELECT_TWO_HANDED), [`SELECT_TWO_HANDED_SPECIAL`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-SELECT_TWO_HANDED_SPECIAL), and [`SELECT_EXPLOSIVES`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-SELECT_EXPLOSIVES) (1, 2, 3, and Caps Lock on the keyboard), and the cycle actions [`NEXT_WEAPON`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-NEXT_WEAPON) and [`PREV_WEAPON`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-PREV_WEAPON), which only the mouse wheel (up and down) has.

`CCharacter::UpdatePlayerGlobalInput`, called from the character's pre-state-machine parallel pass, reads them for the local player unless a blackboard value blocks it, while [`Inventory::GetAnimationAllowsSwitchWeaponGUI`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-GetAnimationAllowsSwitchWeaponGUI) holds (the animation-latched [`m_DoesAnimationAllowSwitchWeaponGUI`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_DoesAnimationAllowSwitchWeaponGUI) with [`SB_DISABLE_SWITCH_WEAPON_GUI`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_DISABLE_SWITCH_WEAPON_GUI) clear). It folds them into [`Character::m_WeaponInputs`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_WeaponInputs) by taking the maximum and clamping: the four slot selects as float values into the entries from [`E_INPUT_SELECT_DUEL_WIELD`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::WeaponInput##variant-E_INPUT_SELECT_DUEL_WIELD) to [`E_INPUT_SELECT_PLANT_EXPLOSIVES`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::WeaponInput##variant-E_INPUT_SELECT_PLANT_EXPLOSIVES), and the cycle actions as pressed states into [`E_INPUT_SELECT_PREVIOUS_WEAPON`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::WeaponInput##variant-E_INPUT_SELECT_PREVIOUS_WEAPON) and [`E_INPUT_SELECT_NEXT_WEAPON`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::WeaponInput##variant-E_INPUT_SELECT_NEXT_WEAPON). A closed permission reads as zero, which the decision takes as a release.

The `NInventorySelect` state tasks read no input. Each queues its configured act when the game time since a per-character timestamp falls inside its configured window (unverified).

## The decision

[`Inventory::UpdateWeaponHandling`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-UpdateWeaponHandling) acts on them every frame:

- The largest slot-select value wins; ties prefer two-handed, then dual-wield, special, and explosives. A slot is a candidate only when its [`m_Weapons`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_Weapons) entry holds a weapon. The planted explosive also needs the planted-explosives ability, the animation permission [`m_DoesAnimationAllowSwitchToPlantedExplosive`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_DoesAnimationAllowSwitchToPlantedExplosive), and [`SB_DISABLE_SWITCH_TO_PLANTED_EXPLOSIVE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_DISABLE_SWITCH_TO_PLANTED_EXPLOSIVE) clear, and with keyboard semantics its button has to be released once first ([`m_CanSelectExplosiveOnRelease`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_CanSelectExplosiveOnRelease)).
- While any select input is non-zero, the HUD is told to show the cross with the winner selected and which of the four slots are valid, and the inventory records the winner as the slot to select on release ([`m_SlotToSelectOnRelease`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_SlotToSelectOnRelease)), or none when the winner is already wielded. It follows the input every frame, so pressing another select retargets it.
- When all four select inputs are zero and a slot is pending, the inventory commits: [`Character::SwitchWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-SwitchWeapon) when the animation allows switching and the slot differs from the wielded one (or the planted explosive is in planting mode), or it sets the selected slot and calls [`Character::DrawWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-DrawWeapon) when nothing is wielded and drawing is allowed. Otherwise the slot stays pending and is retried each frame, the HUD showing only it until [`m_WeaponSwitchQueuedTimer`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_WeaponSwitchQueuedTimer) passes a fixed timeout.
- With keyboard semantics a planted-explosive selection commits while held; with gamepad semantics it waits for release. The semantics come from the [`EPCUseGamepad`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/settings_manager::SettingType##variant-EPCUseGamepad) setting.
- `NEXT_WEAPON` and `PREV_WEAPON` step through dual-wield, two-handed, and special (not explosives), skipping empty slots, queue the result ([`m_QueuedCycleSelectedWeaponSlot`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_QueuedCycleSelectedWeaponSlot)), show the cross with it highlighted, and commit a short fixed delay after the last step ([`m_CycleSelectedWeaponTimer`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_CycleSelectedWeaponTimer)). Pressing both cancels the step.
- A holster press sets a latch ([`m_WeaponSwitchInputConsumed`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_WeaponSwitchInputConsumed)) that hides the cross and drops the pending slot until every select input is released, and starts a holster.
- The cross is not shown in a vehicle seat, except on a motorcycle, and the seat clears the pending slot.

## The draw from a weapon input

`UpdateWeaponHandling` also draws from weapon inputs alone ([`Character::m_WeaponInputs`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_WeaponInputs), read during the call). With nothing wielded or while a holster plays, a positive fire input ([`E_INPUT_MAIN_WEAPON`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::WeaponInput##variant-E_INPUT_MAIN_WEAPON)) calls `DrawWeapon`: the trigger brings out the last selected weapon, or brings it straight back mid-holster. For the player, a positive precision-aim input ([`E_INPUT_PRECISION_AIM`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::WeaponInput##variant-E_INPUT_PRECISION_AIM)) with nothing wielded, while precision aim is possible, draws the selected weapon and enters precision aim if it supports it. `DrawWeapon`'s other callers are, inside the call, the combat mental state's draw ([aim-state.md](aim-state.md#the-mental-state)), and outside it the slot select, the AI, and [`Player::SetAimMode`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::Player##func-SetAimMode).

## The switch away from an empty weapon

The game switches weapons on its own only when the player pulls the trigger of an empty weapon that cannot reload, in the per-gun ammunition check ([weapon-ammo-and-reload.md](weapon-ammo-and-reload.md#the-ammunition-check)), [`WeaponBase::CheckIfReloadShouldBeTriggeredBase`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-CheckIfReloadShouldBeTriggeredBase) (the virtual is [`CheckIfReloadShouldBeTriggered`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-CheckIfReloadShouldBeTriggered); the rocket launcher and the sniper rifle override it and call the base).

- With the magazine empty and no reload running, a weapon that [`CanReload`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-CanReload) starts the automatic reload, trigger or not, which needs a reserve.
- A weapon that cannot reload, with a shot requested, calls [`Inventory::TryToSwitchToValidWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-TryToSwitchToValidWeapon) (except the hand grenade and the planted explosive). That tries the two-handed, then the dual-wield, then the special weapon, and selects the first whose magazine or inventory stock is not empty through [`Character::SelectWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-SelectWeapon), as a committed manual selection does. It waits on the animation's switch permission ([`m_DoesAnimationAllowSwitchingWeapons`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_DoesAnimationAllowSwitchingWeapons)) and is blocked by [`SB_DISABLE_SWITCH_WEAPONS`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_DISABLE_SWITCH_WEAPONS); while blocked, it is tried again on the next tick that requests a shot.
- At the pull's press edge only, when no switch happened, the local player's HUD gets [`HUDUI::OnOutOfAmmoFire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##func-OnOutOfAmmoFire) (the grenade counterpart for the hand grenade), and the gun's `OutOfAmmoFire` attached-effect usage is activated whether or not a switch happened. What the movie shows for it, and whether every weapon defines an `OutOfAmmoFire` effect (a dry click), is unverified.
- The shot is cancelled either way, so an empty weapon never fires.

`TryToSwitchToValidWeapon`'s only other caller is `NWeaponEquipTask`, on entry with nothing wielded; manual selection, scripted switches, and weapon removal bypass it. Nothing else reacts to an empty weapon: it stays wielded, and the reload input does nothing, because `CCharacter::StartReloadingWieldingWeapon` queues the reload act only while `CanReload` holds. The dual-wield pistols share one magazine and run dry together.

## The selected slot

The selected slot ([`Character::m_SelectedWeaponSlot`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_SelectedWeaponSlot)) has one writer, [`Character::SetSelectedWeaponSlot`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-SetSelectedWeaponSlot). It writes the slot (and, for the dual-wield, two-handed, and special slots, the last gun slot), queues a weapon-switched statistic for the local player on a change to an occupied slot, and nothing else: no act, equip, or state change. Its callers are the slot select, the valid-weapon select, the inventory's add, the equip virtual, the completed pickup, the clips' track messages, `NWeaponEquipTask`, the inventory's weapon handling, the wingsuit challenges' setup, the guitar case's post-simulation update, the AI's equip, and the animation previewer.

The weapon the game treats as wielded is [`Character::GetWieldingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-GetWieldingWeapon): the selected slot's weapon in the wielding, dual-wielding, or mounted state, or the planted explosive while planting. A slot selected through `SetSelectedWeaponSlot` alone keeps its weapon holstered, so `GetWieldingWeapon` finds nothing and the game draws on the next trigger, precision-aim input, or combat mental state; a weapon still wielding in another slot stays wielding, unseen by whatever reads the selected slot. The selected slot's weapon in any state is [`Character::GetSelectedWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-GetSelectedWeapon), and any slot's is [`Character::GetWeaponInInventory`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-GetWeaponInInventory) (or [`Inventory::GetWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-GetWeapon), which the disassembler mislabels as a point-of-interest factory).

The game's switches go through `SelectWeapon`, which selects and draws the slot, or holsters for none. Its callers are the committed selection (`SwitchWeapon`), the character's pickup into an equipping slot ([`Character::PickUpWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-PickUpWeapon)), the switch away from an empty weapon, the graph script's `SpawnWeapons` node (for its equipped-weapon field), the player's script event handler (whose unequip event selects no slot; unverified), the AI, and the network.

[`Inventory::SelectValidWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-SelectValidWeapon) selects a weapon that has ammunition. Its callers are the draw, the inventory's drop with its select flag, a mounted gun's stop-using, the planted explosive's stop, and the store's close ([`CommStoreUI::OnInactive`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::comm_store_ui::CommStoreUI##func-OnInactive)), which, after a delivery while the planted explosive is in use, stops using it and selects a valid weapon.

`DrawWeapon`, when drawing is allowed and a valid weapon is selected, queues `UB_ACT_DRAW` and closes the draw and grenade permissions; the equip happens when the draw clip's equip track message reaches the equip virtual ([weapon-equip-and-drop.md](weapon-equip-and-drop.md#who-equips-and-unequips)). The holster ([`Character::HolsterWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-HolsterWeapon)) is called by the inventory's weapon handling (the holster input and its delayed retry), the planted explosive's fire start, the mortar's update, and the AI; for the player it takes effect through the automatic holster of the relaxed mental state ([aim-state.md](aim-state.md#the-mental-state)).

## The selection cross

`MCI_weapon_selection_wheel` is a static clip on `hud.gfx`'s main timeline (listed on [`ScaleformInfo`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::ScaleformInfo)). Its arms are `MCI_dual`, `MCI_two_handed`, `MCI_two_handed_special`, and `MCI_explosives`, each with `MCI_weapon_icon`, `TXT_name`, `MCI_arrows`, and a direction-specific background, and the movie maps the inventory's slots onto them (`WeaponSlotToWheelSlot`): [`E_SLOT_DUAL_WIELD`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_DUAL_WIELD), [`E_SLOT_TWO_HANDED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_TWO_HANDED), [`E_SLOT_TWO_HANDED_SPECIAL`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_TWO_HANDED_SPECIAL), and [`E_SLOT_PLANTED_EXPLOSIVE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::WeaponSlot##variant-E_SLOT_PLANTED_EXPLOSIVE). The heavy, hand-grenade, FOW, and beacon slots are not on it.

With gamepad semantics (the movie's `m_IsUsingGamepad`, fed by the `OnUseGamepad` call described on [`UIManager::m_IsUsingGamepad`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_manager::UIManager##field-m_IsUsingGamepad)) the arms tween out from the centre into the d-pad cross: dual-wield up, two-handed right, special left, explosives down. With keyboard semantics they lie in one horizontal row. A `MCI_selection_arrow` child and its angle, scale, and radius fields are hidden and unused, the remains of an analog radial selector.

Each arm shows the weapon's icon, a streamed texture `textures/ui/weapon_icons/<weapon id>.ddsc` loaded through `hud_code.weapon_icon_type.LoadIcon`, and the weapon's name. The cross shows no ammunition; the persistent weapon display is the bottom-right block `MCI_safe_area_bottom_right.MCI_weapons_parent.MCI_weapons` (the icon's `_sm` variant, the name, a magazine bar, and the reserve), which fades out on a timer.

The native side calls four ActionScript methods:

- `InitWeapons(weapon_data)`: the weapon id and name for each slot.
- `OnPickupWeapon(id, slot, name)` and `OnSelectWeapon(slot, ...)`.
- `UpdateWeaponSelection(selected_slot, should_show, valid_dual, valid_two_handed, valid_special, valid_explosives)`. The arms' visibility follows the valid flags. A show edge tweens the arms out at full alpha; while shown, the selected arm is at full alpha and the others are dimmed, and each change of selection plays `jc3_gui_hud_weapon_switch`; a hide edge scales the selected arm up while fading it and retracts the rest.

[`HUDUI::UpdateWeaponSelection`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##func-UpdateWeaponSelection), whose only caller is `UpdateWeaponHandling`, is called every frame for the player with a [`WeaponSelectionParams`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::WeaponSelectionParams) (whether to show, the selected slot, and the four valid flags). It packs them into six values and invokes the AS3 method only when a field differs from the last pushed state, [`m_LastWeaponSelectionParams`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##field-m_LastWeaponSelectionParams), which it then updates. All the cross's state passes through that field, which always holds the latest state, including the valid flags the inventory computes every frame, shown or not.

The movie's `GetWeaponSelectionWheelBB{Left,Right,Top,Bottom}` give the cross's extent for the current layout; [`HUDUI::RecalculateWheelBB`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##func-RecalculateWheelBB) reads them into [`m_SelectionWheelBB`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##field-m_SelectionWheelBB) on `InitWeapons` and on a change of gamepad use. The HUD holds the cross's clip as [`m_SelectionWheelUi`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##field-m_SelectionWheelUi).

## Placement

[`HUDUI::UpdateWeaponSelectionPlacement`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##func-UpdateWeaponSelectionPlacement), called every frame from [`HUDUI::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##func-Update), passes the hips bone's world position to `CUIMenu::UpdateHysteresis`. That projects it with [`UIManager::Convert3DCoords`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_manager::UIManager##func-Convert3DCoords) through the render camera's view-projection directly, not through [`Get2DInfo`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_manager::UIManager##func-Get2DInfo) or [`Convert3DCoordsDefault`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_manager::UIManager##func-Convert3DCoordsDefault), clamps the result so the cross's extent stays inside [`UIManager::m_SafeArea`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_manager::UIManager##field-m_SafeArea) (or, when the point does not project, centres the cross horizontally at the bottom of the safe area), averages it with the last few positions, and writes the clip's x and y with a [display-info write](../rendering/ui-rendering.md#display-info-writes).
