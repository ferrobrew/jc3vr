# The grapple pipeline

The grapple is Just Cause 3's signature mechanic. The player fires a hook at a surface or object to zip toward it (traversal) or to tether two things together (attach), and can reel in. The sections below cover grapple targeting, the hook flight and attach, the traversal, tether, and retract modes, the readers of the grapple aim slot, and the related arm IK and reticle. The weapon side of the same aim state is in [aim-pipeline.md](aim-pipeline.md).

The addresses and field offsets behind the names below are in the pyxis defs, chiefly [`PlayerAimControl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl), [`GrapplingHook`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook), [`WireEnd`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::wire_end::WireEnd), and [`HookTargetInfo`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::wire_end::HookTargetInfo).

## The one-line summary

The grapple does not cast its own ray. It reads the same shared aim state the guns read (the single per-tick raycast in [`PlayerAimControl::UpdateDirectAim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-UpdateDirectAim)), bucketed by the target-type index [`TargetType`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::TargetType) (the full list is in "The aim target" in [aim-pipeline.md](aim-pipeline.md)). Weapons use [`TargetType::TARGET_WEAPONS`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::TargetType##variant-TARGET_WEAPONS) and the grapple uses [`TargetType::TARGET_GRAPPLE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::target::TargetType##variant-TARGET_GRAPPLE). Both the ray origin and direction come from [`GameCameraManager::GetCameraMatrix`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/camera::game_camera_manager::GameCameraManager##func-GetCameraMatrix) (see "The camera getters" in [aim-pipeline.md](aim-pipeline.md)). Because one ray fills both slots, any change to the matrix that `GetCameraMatrix` returns moves the gun aim and the grapple aim together. The two uses are separated by slot index, not by caller.

## 1. Targeting: how the target point and entity are chosen

There is no grapple-specific raycast. `PlayerAimControl` owns aim for the local player and runs one physics ray per sim tick that services every aim consumer.

- [`PlayerAimControl::UpdateDirectAim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-UpdateDirectAim) is the per-tick driver. It builds the ray's origin and direction from the camera matrix; the construction is in [aim-pipeline.md, "The raycast"](aim-pipeline.md#the-raycast-updatedirectaim). It then calls [`PhysicsSystem::CastRay`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/physics::PhysicsSystem##func-CastRay) once and hands the single hit to [`PlayerAimControl::CheckDirectTargets`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-CheckDirectTargets).
- `CheckDirectTargets` loops over the target types (weapon, grapple; melee is skipped here) and fills, per type, the parallel arrays on `PlayerAimControl`: [`PlayerAimControl::m_DirectTargets`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_DirectTargets), [`PlayerAimControl::m_DirectHits`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_DirectHits), [`PlayerAimControl::m_DirectPositions`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_DirectPositions), [`PlayerAimControl::m_AimPos`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_AimPos), [`PlayerAimControl::m_IsInRange`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_IsInRange), and [`PlayerAimControl::m_MaxAimDistance`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_MaxAimDistance). For the grapple it also maintains the "last valid grapple" cache ([`PlayerAimControl::m_LastHitGrappleTargetGO`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_LastHitGrappleTargetGO), [`PlayerAimControl::m_HasLastValidGrapple`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_HasLastValidGrapple), and [`PlayerAimControl::m_DirectGrapplePosIsGrapplable`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_DirectGrapplePosIsGrapplable)), so a momentarily lost target can persist.

Where the chosen grapple result is read:

- [`PlayerAimControl::GetActiveGrappleTargetPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-GetActiveGrappleTargetPosition) returns a pointer to `m_AimPos[TARGET_GRAPPLE]`. The aim blend states and the grapple's fire-input predicate (`CGrapplingHook::GetFireInputEnabled`, which the disassembler mislabels `CInventory::UpdateWeapons_Serial`) call it.
- [`PlayerAimControl::GetCurrentGrappleTargetGO`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-GetCurrentGrappleTargetGO) and [`PlayerAimControl::GetCurrentGrappleTargetWeakGO`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-GetCurrentGrappleTargetWeakGO) return the cached grapple game object, gated on `m_HasLastValidGrapple && m_IsInRange[TARGET_GRAPPLE]`.
- [`PlayerAimControl::IsLastValidGrappleAimPosStillValid`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##func-IsLastValidGrappleAimPosStillValid) re-validates the cached grapple aim by re-reading `GetCameraMatrix`. It is one of the few grapple-specific callers of the camera getter.

The grapple therefore has no raycast of its own. It reads the camera matrix through the shared `UpdateDirectAim` ray, and the result lands in the grapple slot. The chosen target lives in `PlayerAimControl::m_AimPos[TARGET_GRAPPLE]` (world position) plus `m_Target[TARGET_GRAPPLE]` and `m_LastHitGrappleTargetGO` (entity).

### The grapple's own read of that state

When the player fires, the hook latches the aim state into a cached target rather than re-reading it live:

- [`GrapplingHook::SetUpTarget`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-SetUpTarget) (static) is the capture point. Its signature is `(CPlayer* player, CWireEnd::SHookTargetInfo& out, CTarget::ETargetType type)`. It reads the player's aim control ([`Player::m_AimControl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::Player##field-m_AimControl)), then `m_AimPos[type]` and `m_Target[type]`, transforms the world aim position into the target object's local space, and writes a [`HookTargetInfo`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::wire_end::HookTargetInfo). When there is no direct `CTarget` it falls back to `GetCurrentGrappleTargetGO` only for `TARGET_GRAPPLE`. The target info has two setup overloads: [`HookTargetInfo::SetupTargetFromTarget`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::wire_end::HookTargetInfo##func-SetupTargetFromTarget) (`CTarget*`, `CVector3f local`) and [`HookTargetInfo::SetupTargetFromGameObject`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::wire_end::HookTargetInfo##func-SetupTargetFromGameObject) (`CGameObject*`, `CVector3f local`).
- [`GrapplingHook::GetLastGrappleTargetPos`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-GetLastGrappleTargetPos) returns that cached target's current world position. Downstream fire and IK read this, not live `PlayerAimControl`.

The grapple's use of the aim state is keyed by `TARGET_GRAPPLE`, so it is separate from the weapon's `TARGET_WEAPONS` use regardless of which function reads it.

## 2. Fire and attach: not instant — a short hook flight

Between "target chosen" and "hook attached" there is an animation-gated wire *extension*, i.e. a genuine (short) projectile flight of the hook from the hand toward the cached target. The pipeline:

1. [`GrapplingHook::TryFireHook`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-TryFireHook) computes the fire direction from the cached `HookTargetInfo` and calls the animation fire.
2. [`GrapplingHook::DoActFire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-DoActFire) (static), with signature `(const CVector3f& direction, boost::shared_ptr<CCharacter>&, bool dual_tether, bool reel)`, takes a direction, not a position. It only selects a directional fire animation sector (angle to `ACT_GRAPPLE_FIRE_*`, or `ACT_GRAPPLE_TETHER_FIRE_*` when dual-tether) and `QueueAct`s it. No wire is created here; the callbacks (`FireHookQueueActCallback`, `FireDualTetherQueueActCallback`, `FireHookGrappleReelQueueActCallback`) only notify. The act is re-issued each tick until `CCharacter::IsGrappleFiring` goes true.
3. The fire animation emits a track message. On the "release the hook now" frame the hook is spawned in [`GrapplingHook::OnPostCamUpdate`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-OnPostCamUpdate): it reads the hand and shoulder position, creates the wire with [`GrapplingHook::CreateNewWire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-CreateNewWire), pins the near end to the device, and starts the far end extending with [`WireEnd::SetExtend`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::wire_end::WireEnd##func-SetExtend) (`(const CVector3f& start, float speed, SHookTargetInfo&, bool ghost)`). `SetExtend` puts the far end into an EXTENDING state at a tuning speed aimed at the cached target. This is the flight.
4. On reaching or hitting, [`WireEnd::Attach`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::wire_end::WireEnd##func-Attach) builds an attachment proxy (`CGrapplePointProxy`) and moves the end to ATTACHED. A wire end attaches to a proxy, not a raw coordinate: [`WireEnd::AttachToProxy`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::wire_end::WireEnd##func-AttachToProxy), and [`WireEnd::AttachToCharacterBone`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::wire_end::WireEnd##func-AttachToCharacterBone)`(shared_ptr<CCharacter>&, int bone, const CMatrix4f& localOffset)`. A [`GrapplingHookWire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHookWire) holds two `CWireEnd`s: `[0]` near/device and `[1]` far/hook. So a tether is entity/bone/world-proxy per end, not a two-point pair of bare coordinates.

## 3. Traversal versus tether versus retract

The three modes are distinguished by input and by [`GrapplingHookState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHookState) ([`GHS_INACTIVE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHookState##variant-GHS_INACTIVE), `GHS_REELING_IN`, `GHS_REELED_ATTACHED`, `GHS_REELED_HANG`, `GHS_REELED_UPSIDEDOWN`, `GHS_REELED_STUNT`, and `GHS_CUSTOM_ACTIVE_WIRE`; `SetState` is the mutator). The hook stores it in [`GrapplingHook::m_State`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##field-m_State). The ownership path to the hook runs through [`Character::m_Inventory`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_Inventory) (the embedded `Inventory`), which holds the character's hook as [`Inventory::m_GrapplingHook`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_GrapplingHook); [`Character::GetGrapplingHook`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-GetGrapplingHook) returns it. Input is dispatched from [`GrapplingHook::OnPreSimUpdate`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-OnPreSimUpdate) and `OnPostCamUpdate`, reading a `CActionMap`. The relevant actions (see also `docs/engine/gameplay/input.md`):

- [`Action::FIRE_GRAPPLE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-FIRE_GRAPPLE) is the mode selector, tap versus hold against the tuning hold-time:
  - A tap with a wire already attached reels to the target (zip): `SetState(GHS_REELING_IN)`, `QueueAct(ACT_PRE_REEL)`, and the reel completes into a `GHS_REELED_*` state via the reel tasks (`NStateTask_ReelIn`, `StartReelAttach` / `StartReelHangAtPosition` / `StartReelUpsideDown`).
  - A hold fires a dual tether: a second wire whose far end dual-attaches, connecting two things (`OnDualTetherAttach`). The multi-tether count is upgrade-gated (`GetMaxDualTethers`), and the oldest tether is broken when over budget (`BreakOldestDualTetherIfNeeded`).
- [`Action::RETRACT_GRAPPLE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-RETRACT_GRAPPLE) retracts or pulls. [`GrapplingHook::RetractActiveWire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-RetractActiveWire) destroys the constraint and detaches the near end. `CGrapplingHook::HandleGrapplePull` is the path that yanks a light object toward the player: it slerps a pull direction, applies an impulse, and then retracts. This behaviour is unconfirmed. The function IDA labels `HandleGrapplePull` calls `RetractActiveWire`, then sets a state and queues an act.
- [`Action::RELEASE_GRAPPLE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-RELEASE_GRAPPLE) releases tethers: `ReleaseAllDualTethers` and `DetachAllDualTetheredWiresAttachedToGameObject`.
- [`Action::PUSH_GRAPPLE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-PUSH_GRAPPLE) and the reeled-in actions [`Action::REELED_IN_JUMP_ACTION`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-REELED_IN_JUMP_ACTION) and [`Action::REELED_IN_RELEASE_ACTION`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-REELED_IN_RELEASE_ACTION) drive the reeled states.

## 4. Readers of the grapple slot

The grapple slot is the `TARGET_GRAPPLE` entry of the `PlayerAimControl` arrays ([`PlayerAimControl::m_AimPos`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_AimPos), [`PlayerAimControl::m_DirectPositions`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_DirectPositions), [`PlayerAimControl::m_DirectTargets`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_DirectTargets), [`PlayerAimControl::m_DirectHits`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_DirectHits), and [`PlayerAimControl::m_IsInRange`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_IsInRange)) plus the grapple cache ([`PlayerAimControl::m_LastHitGrappleTargetGO`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_LastHitGrappleTargetGO), [`PlayerAimControl::m_HasLastValidGrapple`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_HasLastValidGrapple), and [`PlayerAimControl::m_DirectGrapplePosIsGrapplable`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_DirectGrapplePosIsGrapplable)). For a surface hit the slot holds the ray hit. For entity attach and dual-tether targets, `m_Target[TARGET_GRAPPLE]` and `m_LastHitGrappleTargetGO` come from the grapple fitness and target scoring. The reads in `UpdateGrappleReticle` and `NReelInAimIK::Update` confirm the layout of `m_AimPos`, [`PlayerAimControl::m_LastAimPos`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_LastAimPos), and [`PlayerAimControl::m_IsGrappleUsingDirectPos`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_IsGrappleUsingDirectPos).

Two grapple-specific functions call `GetCameraMatrix` directly instead of reading the slot: `IsLastValidGrappleAimPosStillValid` and [`NStateTask_InAirGrappleFireMotionTask::OnEnter`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::NStateTask_InAirGrappleFireMotionTask##func-OnEnter). All other grapple aim comes through the shared raycast.

The readers of the slot fall into two groups:

- Live readers of `m_AimPos[TARGET_GRAPPLE]`: `GetActiveGrappleTargetPosition`, `IsLastValidGrappleAimPosStillValid`, and the grapple reticle (section 5).
- Readers of the latched target: `GrapplingHook::SetUpTarget` copies the slot into a `HookTargetInfo` when the hook fires, and `GetLastGrappleTargetPos` and the fire arm IK (section 5) read that copy. A change to the slot after `SetUpTarget` runs does not move the hook's target, and the reticle shows the live slot rather than the latched target.

## 5. Arm IK and the reticle

### Arm IK during grapple (interface point for [hands-locomotion-and-state.md](../character/hands-locomotion-and-state.md))

Two IK tasks aim the arm during the grapple, each with its own target source:

- [`NGrapplingFireArmIK::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/animation::arm_aim_ik##func-NGrapplingFireArmIK_Update) is the fire arm aim. Its target is [`GrapplingHook::GetLastGrappleTargetPos`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-GetLastGrappleTargetPos), the cached fire target, which is the same point the hook flies to. It computes `aim_dir = target − left_shoulder`, projects a wanted left-hand position at arm length, and writes it to the blackboard (hand-position and weight keys). It is not camera-sourced and does not read the live wire endpoint.
- [`ReelInAimIK::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::arm_aim_ik::ReelInAimIK##func-Update) calls [`ReelInAimIK::UpdateAimEffector`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::arm_aim_ik::ReelInAimIK##func-UpdateAimEffector) for the reel-in arm aim. Its arm and chest targets are in [hands-locomotion-and-state.md, "Reel-in aim IK"](../character/hands-locomotion-and-state.md#reel-in-aim-ik-the-grapple-arm-one-arm-effector-and-the-chest-grapple-pipeline-interface-point).

### The grapple reticle

The grapple has its own reticle, separate from the weapon reticle:

- [`HUDUI::UpdateGrappleReticle`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##func-UpdateGrappleReticle) computes the reticle base point as `m_LastAimPos[TARGET_GRAPPLE]` lerped toward `m_AimPos[TARGET_GRAPPLE]` by the frame's interpolation factor ([`Vector3::Lerp`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/types::math::Vector3##func-Lerp)). Both are [`PlayerAimControl`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl) fields ([`PlayerAimControl::m_LastAimPos`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_LastAimPos) and [`PlayerAimControl::m_AimPos`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_AimPos)). It projects that point with the four-argument `CUIManager::Convert3DCoords(pos, &x, &y)` overload, which pyxis binds as [`UIManager::Convert3DCoordsDefault`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_manager::UIManager##func-Convert3DCoordsDefault). That overload takes no matrix: it reads the active camera's view-projection and forwards to the five-argument [`UIManager::Convert3DCoords`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::ui_manager::UIManager##func-Convert3DCoords). When [`PlayerAimControl::m_IsGrappleUsingDirectPos`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_IsGrappleUsingDirectPos) is set, the function skips the projection and places the base point at the centre of the stage (`CUIManager::m_CachedStageSize × 0.5`). The result goes to the Scaleform clip as `m_BaseX` / `m_BaseY`.
- [`GrapplingHook::ShouldShowAttachedUI`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-ShouldShowAttachedUI) gates only the attached-wire part of the reticle (`m_IsAttached`, `m_AttachedX` / `m_AttachedY`, `m_AttachedBlend`, and `m_AttachedRotation`). That part projects [`GrapplingHook::GetActiveWireAttachmentGraphicsWorldPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-GetActiveWireAttachmentGraphicsWorldPosition) through the same four-argument overload. A third projection of an offset from `m_AimPos[TARGET_GRAPPLE]` sets `m_GripRadius`.
- [`HUDUI::UpdateWeaponReticle`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::hud_ui::HUDUI##func-UpdateWeaponReticle) only reads `ShouldShowAttachedUI`, to suppress itself while grappling.
- Wire tension and attach-type overlays are pushed separately by [`GrapplingHook::PushWireDataToUI`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-PushWireDataToUI).

The grapple reticle projects from the live `m_AimPos[TARGET_GRAPPLE]`, so it tracks the grapple slot as it changes each tick and does not read the target latched by `SetUpTarget`.
