# The aim state and fire gating

The player character is either aiming a weapon (or grapple) or not, and firing is not gated by it. Where the aim point comes from is in [aim-pipeline.md](aim-pipeline.md), the arm IK in [weapon-attachment-and-arm-ik.md](../character/weapon-attachment-and-arm-ik.md), and the grapple in [grapple-pipeline.md](grapple-pipeline.md). State-bit names come from the `SUserVM` enum, and animation-graph names from Rico's state machines (`animations/jc_statemachine/main_characters/rico/rico_base.afsmb` and `rico_partial_global.afsmb`, from `patch_win64/game1`).

## The state

The state lives in one byte, [`Character::m_AimFlags`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AimFlags), typed as [`AimState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState):

| Flag | Meaning |
|---|---|
| [`m_AimingEnabled`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingEnabled) | Aiming enabled (`CCharacter::SetAimingEnabled`, driven from the animation state machine). Every other aim flag is forced off without it. |
| [`m_AimingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingWeapon) | Aiming a weapon. |
| [`m_AimingGrapple`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingGrapple) | Aiming the grapple (holding a live tether, below). |
| [`m_WasAiming`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_WasAiming) | Aiming last tick, for the start and stop edges. |
| [`m_InCargoBay`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_InCargoBay) | In a vehicle cargo bay, not an aim flag: `CVehicleCargoBay` sets and clears it, and `CCharacter::IsInCargoBay`, `NClampCapsuleSpeed`, the air movement code, and the reel-in kick task read it (unverified). |

The byte's other flags are unrelated: [`m_WasVisible`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_WasVisible) (the previous frame's visibility), [`m_UseFinalTransparency`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_UseFinalTransparency), and [`m_GodModeSequence`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_GodModeSequence) (the sequence-scoped god mode). The neighbouring byte [`Character::m_DamageFlags`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_DamageFlags) ([`DamageStateFlags`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::DamageStateFlags)) carries the weapons-enabled flag, [`WEAPONS_ENABLED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::DamageStateFlags##flag-WEAPONS_ENABLED), written by [`Character::SetWeaponsEnabled`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-SetWeaponsEnabled) and read by the aim logic.

It is mirrored into the state words as [`SB_IS_AIMING_WPN_OR_GRPL`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_AIMING_WPN_OR_GRPL), which the animation graph's `C_IS_AIMING_WPN_OR_GRPL` condition tests.

## Writers

### `Character::HandleAimingInputPlayer`

[`Character::HandleAimingInputPlayer`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-HandleAimingInputPlayer) runs each tick from `CCharacter::UpdatePassPreStateMachines_Parallel`, on the local-player branch (which also runs the player's global input and the inventory's pre-state update). Other characters run [`Character::HandleAimingInputNPC`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-HandleAimingInputNPC), which refills the timer from the wielded weapon and the behaviour-tree avatar's aim request and shares the rest. The IDB swaps the two names; the defs follow the bodies. The player version:

1. Copies "aiming weapon or grapple" into `m_WasAiming`.
2. If `m_AimingEnabled` is clear, clears `m_AimingWeapon` and returns.
3. Picks the weapon: the planted explosive while planting, otherwise the weapon in [`Character::m_SelectedWeaponSlot`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_SelectedWeaponSlot) when it is wielded, dual-wielded, or mounted.
4. With a weapon, refills the aim timer when the weapon's [`WeaponBase::IsWeaponAiming`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-IsWeaponAiming) virtual is true and `WEAPONS_ENABLED` is set, or when [`Player::m_AimMode`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::Player##field-m_AimMode) is [`AIM_PRECISION`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::AimMode##variant-AIM_PRECISION). The virtual's base, [`WeaponBase::IsWeaponAimingBase`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-IsWeaponAimingBase), returns [`m_IsTryingToFire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_IsTryingToFire) or [`m_IsFeatheringTrigger`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_IsFeatheringTrigger). The timer is zeroed instead when the weapon's [`m_IsPrecisionAimDisabled`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_IsPrecisionAimDisabled) is set, when its [`m_AimingWeaponIsPossible`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_AimingWeaponIsPossible) is clear (the wall block clears it, [weapon-firing.md](weapon-firing.md#trigger-interval-and-the-forced-shots)), or while the mental state is [`E_RELAXED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::avatar::MentalState##variant-E_RELAXED). With no weapon it is zeroed unless [`SB_IS_DRAWING_WEAPON`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_DRAWING_WEAPON) or [`SB_IN_FULLBODY_PICKUP`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IN_FULLBODY_PICKUP) is set, when it runs on.
5. The refill value is a float in the aim-settings resource that [`Character::m_AimingSettings`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AimingSettings) references, unless the weapon's [`GetAimTimerOverride`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-GetAimTimerOverride) (tuning field [`m_aim_timer_override`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponTuning##field-m_aim_timer_override)) is non-negative. That is weapon tuning's only aim timing; there is no per-weapon raise time.
6. The timer, [`Character::m_AimTimer`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AimTimer), otherwise counts down by `dt`, except while [`SB_PAUSE_AIM_TIMER`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_PAUSE_AIM_TIMER) (set by `NPauseAimTimerTask`) is set, which also holds it at or above the floor that bit's def gives.
7. `m_AimingWeapon` is set while the timer is positive. Two overrides force it on: planting an explosive while [`SB_IS_HOLSTERING_WEAPON`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_HOLSTERING_WEAPON) is clear, and [`SB_IS_SWITCHING_WEAPONS`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_SWITCHING_WEAPONS) in one phase of the switch. Then [`SB_NO_WEAPON_AIM_NOAIM_TRANSITIONS`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_NO_WEAPON_AIM_NOAIM_TRANSITIONS) latches whatever the flag is, and [`SB_NO_WEAPON_AIM`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_NO_WEAPON_AIM) forces it off over everything else. Only the two aim-input functions read `SB_NO_WEAPON_AIM`, and it leaves `m_AimingGrapple` alone.
8. Mirrors `m_AimingWeapon | m_AimingGrapple` into `SB_IS_AIMING_WPN_OR_GRPL` and queues one act on the animated model directly, not through [`Character::QueueAct`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-QueueAct): `ACT_ON_STARTING_AIM` on the rising edge, `ACT_AIM` while aiming, and `ACT_ON_LEAVING_AIM` on the falling edge. Only `ACT_ON_LEAVING_AIM` appears in Rico's graphs (in `rico_partial_global.afsmb`).

So any trigger value ("feathering") raises the weapon without firing, and the character stays aimed for the timer's tail after release. IDA labels [`WeaponBase::GetMagazineSize`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-GetMagazineSize) as a `boost::shared_ptr<CWeaponBase>::operator->` thunk; it is a non-virtual accessor of [`WeaponTuning::m_magazine_size`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponTuning##field-m_magazine_size), not the body behind the `IsWeaponAiming` slot.

### `Character::PreSimUpdateGrapple`

[`Character::PreSimUpdateGrapple`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-PreSimUpdateGrapple) owns `m_AimingGrapple`. It is set when `m_AimingEnabled` is set and either [`GrapplingHook::IsHookAimingState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-IsHookAimingState) is true, or the hook's [`m_State`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##field-m_State) is [`GHS_REELING_IN`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHookState##variant-GHS_REELING_IN) with [`SB_IS_PARACHUTING`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_PARACHUTING) set. `IsHookAimingState` is true while the hook has an active wire that is not reeling in and not a custom wire (with the re-reel upgrade, reeling in also counts). Grapple firing does not need it: `CGrapplingHook::DoActFire` queues directional acts (`S_RUN_STRAFE_GRPL_FIRE_*`) and `CCharacter::IsGrappleFiring` drives the fire-arm IK on its own.

### Related queries

- [`Character::IsAimingWeaponPossible`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsAimingWeaponPossible): a wielded weapon with `m_AimingWeaponIsPossible`, not holstering, and either already aiming or not latched by `SB_NO_WEAPON_AIM_NOAIM_TRANSITIONS`.
- [`Character::IsTryingToAim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsTryingToAim): already aiming, or shooting is allowed and the trigger value is past the weapon's sensitivity, or a force-fire timer, count, or input buffer is live. The fire action is [`FIRE_RIGHT`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-FIRE_RIGHT), [`MC_FIRE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-MC_FIRE) on a motorbike, or `CWeaponBase::GetNextFireButton` for weapons that alternate.
- [`Character::IsTryingToFireAnyWeapons`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsTryingToFireAnyWeapons) and [`Character::HasAnyWeaponInput`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-HasAnyWeaponInput): weapon-input queries used by the IK and the mental state.

## Consumers

### Locomotion task selection

Every on-foot input locomotion task reads `m_AimingWeapon` and `m_AimingGrapple` directly to choose between run and steer acts and aim-relative strafe acts: [`NStateTask_InputLocoMoveTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_InputLocoMoveTask##func-Update), [`NStateTask_InputLocoAimRelativeTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_InputLocoAimRelativeTask##func-Update), [`NStateTask_InputLocoAimPrecisionTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_InputLocoAimPrecisionTask##func-Update), and the Idle, Starts, Stops, Plants, RotateOnSpot, FlickStick, AimFlickStick, MoveOneOff, MoveGrappleFire, SetTargetFaceDir, and SetTargetSpeeds tasks, most also calling `IsAimingWeaponPossible`. So do the `NStateTask_LocoUtil` queue helpers [`QueueMoveActions`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_LocoUtil##func-QueueMoveActions), [`QueueAimRelativeMoveActions`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_LocoUtil##func-QueueAimRelativeMoveActions), `QueueStarts`, and `QueueMoveOneOffActions`; [`SB_IN_LOCOMOTION_STRAFING`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IN_LOCOMOTION_STRAFING) reports the result to the graph.

The strafe branch queues the `ACT_MOVE_AIM_FOCUS_*` acts (forward, 90 left, 90 right, and 180) and the `ACT_FORCE_MOVE_*` acts, which by name drive the aim family's `S_MOVE_AIM_FOCUS` states, moving the lower body in the aim family even while the aim flags (and the states keyed on `C_IS_AIMING_WPN_OR_GRPL` and `C_IS_AIMING`) are off. Which states play was not re-traced against the decoded graph ([animation-graph.md](../character/animation-graph.md)) and is unverified; that graph does show `C_HEAVY_WEAPON` (the selected slot holds the heavy weapon, in any state) sending the aim-strafe moves to `S_MOVE_AIM_FOCUS` and the idle to `S_IDLE_AIM_FOCUS`. `QueueAimRelativeMoveActions` takes its reference direction from the wielded weapon's aim point ([`WeaponBase::m_AimTargetPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_AimTargetPosition), through its getter) minus the character's position, or unarmed from the player aim control's weapon point.

### Animation graph states and blend spaces

The base graph selects between two full-body families ([below](#relaxed-and-aimed-holds)) with `C_IS_AIMING_WPN_OR_GRPL`, the code conditions `C_IS_AIMING` and `C_IS_AIMING_WEAPONS` (`CAimingCondition`, which reads `m_AimingWeapon`), and `C_IS_TRYING_TO_FIRE` ([`WeapoIsTryingToFireCondition::Evaluate`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeapoIsTryingToFireCondition##func-Evaluate)).

In the aimed states, aim yaw and pitch are a blend space. `CLocoAimBlendState`, `CVerticalAimBlendState`, and `CVerticalAimStrafingBlendState` switch to world-space displacement and aim-target pitch when `m_AimingWeapon` or `m_AimingGrapple` is set; `CJumpAimBlendState`, `CGrappleAttachAimBlendState`, `CParachuteBlendState`, and `CSpecialFireAimBlendState` also read the byte. The additive graph carries `AimUpMaxAngle` and `AimDownMaxAngle` limits on its aim states. The upper-body partial graph uses the aim flag only for the strafing grenade-throw variant and `ACT_ON_LEAVING_AIM`. Their transitions were not traced.

### Arm and look IK

- [`NAimIKTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/animation::arm_aim_ik##func-NAimIKTask_Update) activates aim IK when `IsAimingWeaponPossible` holds and the character is aiming (`m_AimingWeapon`), trying to fire, or wielding a heavy weapon; or, for the grapple variant, when aiming the grapple or `IsGrappleFiring`; or during a grenade throw; or when a data-driven state bit is set. With [`SB_USE_ENABLE_AIM_IK_SEG`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_USE_ENABLE_AIM_IK_SEG) set it also requires the `ENABLE_AIM_IK_SEG` segment.
- [`RightArmAimIK::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::arm_aim_ik::RightArmAimIK##func-Update) is player-only. Its weight is the blackboard float keyed by [`ObjectBlackboard::AIM_IK_WEIGHT_ID`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/blackboard::ObjectBlackboard::AIM_IK_WEIGHT_ID), written by animation data. It drives three effectors through [`RightArmAimIK::UpdateAimEffector`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::arm_aim_ik::RightArmAimIK##func-UpdateAimEffector) with the gains [`RightArmAimIK_ArmGain`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::arm_aim_ik::RightArmAimIK_ArmGain), [`RightArmAimIK_HandGain`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::arm_aim_ik::RightArmAimIK_HandGain), and [`RightArmAimIK_HeadGain`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::arm_aim_ik::RightArmAimIK_HeadGain).
- [`NLookAtIKTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/animation::arm_aim_ik##func-NLookAtIKTask_Update) disables head look-at while `m_AimingWeapon` is set.

### Other readers

- Body turn and facing: [`NStateTask_MovementJumpTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_MovementJumpTask##func-Update) selects different facing properties and faces the aim target while `m_AimingWeapon` is set, and `NAlignAttachJointToTarget`, the reeled-in input task, and the grapple hang task read it (unverified). The aim-relative turns are in [aim-pipeline.md](aim-pipeline.md#body-turn-reactions-to-the-aim-direction).
- Foot IK: [`NLocoIKTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/animation::arm_aim_ik##func-NLocoIKTask_Update) uses a different effector interpolation rate while aiming weapon or grapple (unverified).
- Mental state: `CPlayer::UpdateMentalState` treats `m_AimingWeapon` (outside explosive planting) as a reason to stay in combat ([below](#the-mental-state)).
- HUD: `CPlayerActionObserver::Update` reads `m_AimingWeapon` only for motorbike aiming. No reader was found in `CHUDUI` (unverified).
- Aim assist: `PlayerAimControl` does not read the aim state. Assist follows [`PlayerAimControl::m_AimType`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerAimControl##field-m_AimType) ([`ENormal`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::AimType##variant-ENormal) or [`EAuto`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::AimType##variant-EAuto)), which `CPlayer::SetAimMode` and the aim-assist setting write, and by [`SB_DISABLE_AIM_ASSIST`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_DISABLE_AIM_ASSIST).
- AI: NPCs do not read the player's aim flag. [`PlayerIsAutoAimingCondition::Evaluate`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerIsAutoAimingCondition##func-Evaluate) is true when the evaluating character is the player's current weapon target (`PlayerAimControl::m_Target[TARGET_WEAPONS]`), aiming or not, and `CAIPerception::GetCharacterWithMentalState` reads the player's mental state (not located; the IDB function of that name is [`AiGetClosestEntityInRange`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/ai::ai##func-AiGetClosestEntityInRange)), so NPCs observe the relaxed and combat switch (unverified).
- The laser-beam weapon component switches its beam off unless the holder has `m_AimingWeapon` set, and the motorbike riding state has its own aim sub-states (`S_AIM_*_RIDING_MOTORBIKE`) (unverified).

## Fire gating

A wielded weapon with `m_AimingWeapon` clear fires at once, from wherever its muzzle is, toward the aim point. The gates are the inventory's shooting permission, which zeroes the fire input and so the feathering ([weapon-firing.md](weapon-firing.md#the-shooting-permission)), and the weapon's own trigger, interval, wall-block, and forced-shot rules ([weapon-firing.md](weapon-firing.md#trigger-interval-and-the-forced-shots)). Recoil and muzzle placement are per shot and independent of the aim state ([aim-pipeline.md](aim-pipeline.md)).

## Relaxed and aimed holds

The relaxed and aimed holds are separate full-body state families, not one blend weight:

- No-aim: `S_MOVE_NO_AIM`, `S_NO_AIM_*` (turns to backpedal), `S_FLICK_*_NO_AIM`, `S_TURN_*_NO_AIM_STUNT`.
- Aim: `S_MOVE_AIM_STRAFE`, `S_MOVE_AIM_FOCUS` (with 90L, 90R, and 180 variants), `S_IDLE_AIM_FOCUS`, `S_AIM_FOCUS_ROTATE_90L/90R`, `S_RUN_AIM_STRAFE_PLANT_*`, `S_MOVE_STUNT_AIM_STRAFE`, and the `*_AIM` variants of the stunt step-up and step-down states. The additive graph layers `S_MOVE_AIM_STRAFE_ADDITIVE` and `S_IDLE_AIM_FOCUS_ADDITIVE` on top.
- Transitions: `S_IDLE_TRANS_TO_AIM`, `S_IDLE_TRANS_TO_NO_AIM`, and `S_IDLE_TRANS_TO_NO_AIM_SLOW`, reported by [`SB_IN_NOAIM_TO_AIM`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IN_NOAIM_TO_AIM) and [`SB_IN_IDLE_AIMING`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IN_IDLE_AIMING).
- Non-combat: `S_MOVE_NON_COMBAT`, `S_WALK_START_*_NON_COMBAT`, and `S_COMBAT_IDLE_TO_UNARMED_IDLE`, selected by `C_IS_NON_COMBAT` (`CIsPlayerNonCombat`, the player in the relaxed mental state).

The idle is the exception: `S_IDLE_AIM_FOCUS` plays only the minigun's idle, and the other weapons' held and aimed idles are clip variants of `S_IDLE` chosen by animation modifiers ([animation-graph.md, "The on-foot idle"](../character/animation-graph.md#the-on-foot-idle)). Weapon-specific grip, reload, pump, bolt, draw, holster, switch, and pickup animations are in the upper-body partial graph (`S_UB_*`, keyed by per-weapon `C_<WEAPON>` conditions), independent of the aim families.

## The mental state

[`CPlayer::UpdateMentalState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/character::player##func-Player_UpdateMentalState) sets the player's avatar mental state ([`Avatar::m_MentalState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::avatar::Avatar##field-m_MentalState)) each tick through [`Character::SetMentalState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-SetMentalState):

- `E_RELAXED` in a sequence or while holstering.
- [`E_COMBAT`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::avatar::MentalState##variant-E_COMBAT), with a timer, while there is any weapon input, a grenade throw, a heavy weapon wielded, or `m_AimingWeapon` (outside explosive planting), or while already in combat with the heat manager's restricted-military timer running. Melee sets combat directly with the tuning's minimum combat time.
- Otherwise relaxed. On the transition to relaxed with a weapon wielded it queues `ACT_ON_UNEQUIP_WEAPON_SLOW`, an automatic holster.

Two static overrides short-circuit it: [`CCharacter::m_ForceNonCombat`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character_ForceNonCombat) forces relaxed and [`CCharacter::m_ForceCombat`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character_ForceCombat) forces combat.

[`Inventory::UpdateWeaponHandling`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-UpdateWeaponHandling) holds a second automatic holster: for the player, each tick it is relaxed with a weapon wielded, holstering allowed, no deferred unequip pending, no weapon input, and no draw or holster playing, it leaves precision aim, clears the grenade and mortar permissions (re-latched by the next tick's permission update), and queues `UB_ACT_HOLSTER` through `QueueAct`. The player's own holster works through it: for the player, [`Character::HolsterWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-HolsterWeapon) only forces the mental state to relaxed with a zero hold timer, and this branch queues the act later in the same call.

The same function draws a weapon when the player is in combat with nothing wielded and no weapon input, unless [`SB_DISABLE_MENTAL_STATE_DRAW_WEAPON`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_DISABLE_MENTAL_STATE_DRAW_WEAPON) is set. That bit is an inventory permission (set by tasks, latched and cleared each tick), so the draw checks both the latch and the live bit. The draw from weapon input is in [weapon-selection.md](weapon-selection.md#the-draw-from-a-weapon-input).

## Other on-foot stance switches

- Holster: hold [`RELOAD`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-RELOAD) (`HolsterWeapon`, through the relaxed branch above), plus the automatic holsters. `SB_IS_HOLSTERING_WEAPON` and `SB_IS_DRAWING_WEAPON` flag the transitions.
- Walk and run: there is no sprint action. Speed follows stick magnitude, the PC-only [`WALK`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-WALK) hold, and the context bit [`CB_FORCE_WALK`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::ContextBitFlag##variant-CB_FORCE_WALK).
- Stunt step-up and step-down: running into a ledge plays `S_STUNT_FWD_STEP_UP_*` or `S_STUNT_FWD_STEP_DOWN_*` from [`NStateTask_MovementStuntingTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_MovementStuntingTask##func-Update), with aimed variants (triggers unverified).
- Flick-stick and rotate-on-spot turns, queued by the locomotion tasks from stick and aim-reference changes, and idle one-offs (`S_IDLE_ONE_OFF`, driven by `NStateTask_InputLocoIdleTask`).
- Cover: [`SB_IN_COVER_ENTRY`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IN_COVER_ENTRY), [`SB_IN_COVER`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IN_COVER), and [`SB_IN_COVER_EXIT`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IN_COVER_EXIT) exist as NPC states; no player cover behaviour was found (unverified).
- Precision aim: [aim-pipeline.md](aim-pipeline.md#precision-aim-and-sniper-zoom).
