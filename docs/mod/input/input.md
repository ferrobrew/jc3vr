# The game's look, move, and mouse input

The head and body are driven by the mod, so the game's own look input must stop rotating the camera and feed the mod's scheme instead, the move input must steer the body without the game's aim switch, and the mouse must keep working on the redirected HUD. The controller bindings that inject input are [bindings.md](bindings.md). The engine's input pipeline, the action effectors, the write API, and the mouse and UI pipeline are in [engine/gameplay/input.md](../../engine/gameplay/input.md).

## Tapping the look input

The detour is the post-call on `InputDeviceManager::Update`, the per-frame device poll (`crates/jc3vr-gameplay/src/hooks/input/look.rs`), which is also the bindings' poll stage ([bindings.md, "Injection timing"](bindings.md#injection-timing)). After the poll, it reads the four look effectors off `LocalPlayerActionMap`, clears them (value, previous value, and state to idle) so the game's camera sees no look input, and feeds the net deltas to the headpose through `headpose::sim::on_input_tick`. Post-poll the values are the fully resolved per-frame deltas, and clearing them at the effector is safe because the look effectors feed only camera code, so aim assist, which derives from the resulting camera orientation, is undisturbed. While the debug UI captures input the sim still ticks with a zero delta, so its latch and cadence keep running. The tick runs on the engine's fixed-rate sim tick, so the published pose pair rotates in phase with the engine's sub-frame interpolation reset (`crates/jc3vr-view/src/headpose/sim/mod.rs`).

The look could be tapped where the camera consumes it instead, but `InputToOrbitModifier::CalculateInputDeltaAngles`, which combines the devices and applies sensitivity, carries an anti-tamper codemarker ([engine/gameplay/input.md](../../engine/gameplay/input.md)), so it is off-limits as a hook point, and consuming the effectors post-poll keeps the mod clear of it.

## Tapping the move input

Move is handled in the locomotion tasks rather than by clearing effectors (`crates/jc3vr-body/src/hooks/input/locomotion.rs`). The tasks pick run-and-steer or aim-relative strafe from the local player's aim flags (`Character::m_AimFlags`), the same flags that drive the weapon raise, the reticle, and auto-aim, so the mod leaves those flags alone ([hands-and-aiming.md, "The aim-state pin and the mental-state cuts"](hands-and-aiming.md#the-aim-state-pin-and-the-mental-state-cuts)) and steers the body through the orientation and displacement evaluators. `NStateTask_InputLocoSetTargetDirTask::SetupTargetDir` reads the move axes, rotates them camera-relative, and writes the move vectors to the character blackboard; the body yaw and the slide overrides build on it, the heading through the target-face-dir blackboard and the displacement through `EvaluateCharacterDisplacement` ([head-and-body.md](../body/head-and-body.md), [locomotion.md](../body/locomotion.md)).

## The mouse on the redirected HUD

The HUD redirect points the movie's cached viewport and scale at the mod's offscreen texture ([hud.md](../hud.md)), so window-client pixels no longer relate to either space. While the redirect is active, the `SendMouseEvents` detour (`crates/jc3vr-hud/src/hooks/ui/mouse.rs`, with the mapping in `crates/jc3vr-hud/src/hud/cursor.rs`) replaces the conversion: it normalizes the client position against the window's live client rect, published from the `WndProc` detour (the back buffer can differ in size and aspect under Wine and Proton scaling), maps that fraction of the stage through the movie's live `ViewportMatrix`, which `HandleEvent` and `NotifyMouseState` invert exactly, and hands Scaleform the whole state each frame through [`MovieImpl::NotifyMouseState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/ui::scaleform::MovieImpl##vfunc-NotifyMouseState) (position and button mask, diffed internally into hover, press, and release, which also sidesteps the DirectInput delta gate). Buttons and the wheel are tracked from window messages in the `WndProc` detour. The game's cursor clip is parked offscreen and replaced by the mod's own quad just off the panel, shown exactly when the game's cursor policy shows a cursor. Both axes normalize independently, so a window of another aspect stretches mouse travel rather than leaving parts of the panel unreachable.

The redirect maintenance compares the movie's live viewport with the redirect each render tick and re-applies on drift (`hud::binding::movie_viewport_matches`), on top of the engine's own reset path. The map converts the mouse itself through the movie's delta and scale fields, which the redirect bypasses, so it is the one screen the redirect breaks; a detour replaces its conversion with the same normalization, which fixes icon picking, click selection, drag panning, and zoom to cursor together.
