# The aim state and fire gating

The player character carries a binary aim state: at any moment it is either aiming a weapon (or grapple) or not. This doc covers what writes that state, everything that reads it, how firing is actually gated (it is not gated by the aim state), the full-body animation families the state selects between, the combat/relaxed mental state that sits beside it, and the other on-foot stance switches the body goes through.

The addresses, field offsets, and state-bit indices behind the names below are in the pyxis defs, chiefly [`Character`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character), [`AimState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState), [`StateBitFlag`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag), [`Inventory`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory), [`WeaponBase`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase), and the `animation::arm_aim_ik` module. Unconfirmed claims are marked as such. State-bit names come from the `SUserVM` enum. Animation-graph names come from Rico's shipped state machines (`animations/jc_statemachine/main_characters/rico/rico_base.afsmb` and `rico_partial_global.afsmb`, from `patch_win64/game1`). Related: `aim-pipeline.md` (where the aim point comes from and how shots are built), `grapple-pipeline.md`, and `docs/engine/character/hands-locomotion-and-state.md`.

## The state

The state lives in one byte, [`Character::m_AimFlags`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AimFlags), typed as [`AimState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState):

| Flag | Meaning |
|---|---|
| [`AimState::m_AimingEnabled`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingEnabled) | Aiming enabled (`CCharacter::SetAimingEnabled`, driven from the animation state machine). Every other aim flag is forced off without it. |
| [`AimState::m_AimingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingWeapon) | Aiming a weapon. |
| [`AimState::m_AimingGrapple`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingGrapple) | Aiming the grapple (holding a live tether, see below). |
| [`AimState::m_WasAiming`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_WasAiming) | Was aiming last tick, used to detect the start and stop edges. |
| [`AimState::m_InCargoBay`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_InCargoBay) | In a vehicle cargo bay. Not an aim flag: `CVehicleCargoBay` sets and clears it, and `CCharacter::IsInCargoBay`, `NClampCapsuleSpeed`, the air movement code, and the reel-in kick task read it. Medium confidence (unconfirmed). |

The remaining flags in the byte are unrelated to aiming: [`AimState::m_WasVisible`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_WasVisible) (the previous frame's visibility), [`AimState::m_UseFinalTransparency`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_UseFinalTransparency), and [`AimState::m_GodModeSequence`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_GodModeSequence) (the sequence-scoped god mode).

The neighbouring byte [`Character::m_DamageFlags`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_DamageFlags) ([`DamageStateFlags`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::DamageStateFlags)) carries the weapons-enabled flag, [`DamageStateFlags::WEAPONS_ENABLED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::DamageStateFlags##flag-WEAPONS_ENABLED), written by [`Character::SetWeaponsEnabled`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-SetWeaponsEnabled). The aim logic reads it (below).

The aim state is mirrored into the character's state words as [`StateBitFlag::SB_IS_AIMING_WPN_OR_GRPL`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_AIMING_WPN_OR_GRPL), which is what the animation graph's `C_IS_AIMING_WPN_OR_GRPL` condition tests.

## Writers

### `Character::HandleAimingInputPlayer`

[`Character::HandleAimingInputPlayer`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-HandleAimingInputPlayer) is called each tick from `CCharacter::UpdatePassPreStateMachines_Parallel`, on the branch taken for the character driven by local player input, the same branch that runs the player's global input and the inventory's pre-state update. Every other character runs [`Character::HandleAimingInputNPC`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-HandleAimingInputNPC) instead, which differs in how it refills the timer (it reads the wielded weapon and the behaviour-tree avatar's aim request) and shares the countdown and the tail. The IDB carries the two names swapped; the addresses in the defs follow the bodies. The player version:

1. Copies "aiming weapon or grapple" into [`AimState::m_WasAiming`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_WasAiming).
2. If [`AimState::m_AimingEnabled`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingEnabled) is clear, clears [`AimState::m_AimingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingWeapon) and returns.
3. Picks the weapon: the planted explosive while planting, otherwise the weapon in [`Character::m_SelectedWeaponSlot`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_SelectedWeaponSlot) when it is wielded, dual-wielded, or mounted.
4. With a weapon, decides whether the aim timer is refilled this tick. It is refilled when the weapon's [`WeaponBase::IsWeaponAiming`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-IsWeaponAiming) virtual returns true and [`DamageStateFlags::WEAPONS_ENABLED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::DamageStateFlags##flag-WEAPONS_ENABLED) is set, or when the player's [`Player::m_AimMode`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::Player##field-m_AimMode) is [`AimMode::AIM_PRECISION`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::player::AimMode##variant-AIM_PRECISION). The base implementation of the virtual, [`WeaponBase::IsWeaponAimingBase`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-IsWeaponAimingBase), returns [`WeaponBase::m_IsTryingToFire`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_IsTryingToFire) or [`WeaponBase::m_IsFeatheringTrigger`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_IsFeatheringTrigger). The timer is zeroed instead, and not refilled, when the weapon's [`WeaponBase::m_IsPrecisionAimDisabled`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_IsPrecisionAimDisabled) is set, when its [`WeaponBase::m_AimingWeaponIsPossible`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_AimingWeaponIsPossible) is clear (the wall-penetration component clears it, see "Fire gating"), or while the mental state is [`MentalState::E_RELAXED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::avatar::MentalState##variant-E_RELAXED). With no weapon the timer is zeroed unless [`StateBitFlag::SB_IS_DRAWING_WEAPON`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_DRAWING_WEAPON) or [`StateBitFlag::SB_IN_FULLBODY_PICKUP`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IN_FULLBODY_PICKUP) is set, in which case it runs on.
5. The refill value is a float in the aim-settings resource that [`Character::m_AimingSettings`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AimingSettings) references, unless the weapon's [`WeaponBase::GetAimTimerOverride`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-GetAimTimerOverride) (tuning field [`WeaponTuning::m_aim_timer_override`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponTuning##field-m_aim_timer_override)) is non-negative, in which case the override is used. That override is the only aim timing in weapon tuning; there is no per-weapon raise time.
6. The timer, [`Character::m_AimTimer`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_AimTimer), is otherwise decremented by `dt`. While [`StateBitFlag::SB_PAUSE_AIM_TIMER`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_PAUSE_AIM_TIMER) (set by `NPauseAimTimerTask`) is set it is not decremented, and it is held at no less than 0.5 s.
7. [`AimState::m_AimingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingWeapon) is set while the timer is positive. Two overrides force it on: planting an explosive while [`StateBitFlag::SB_IS_HOLSTERING_WEAPON`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_HOLSTERING_WEAPON) is clear, and [`StateBitFlag::SB_IS_SWITCHING_WEAPONS`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_SWITCHING_WEAPONS) in one phase of the switch. Two graph bits bend the result after that: [`StateBitFlag::SB_NO_WEAPON_AIM_NOAIM_TRANSITIONS`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_NO_WEAPON_AIM_NOAIM_TRANSITIONS) latches whatever the flag currently is, and [`StateBitFlag::SB_NO_WEAPON_AIM`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_NO_WEAPON_AIM) forces it off over everything else. The two aim-input functions are the only code that reads `SB_NO_WEAPON_AIM`, and it leaves [`AimState::m_AimingGrapple`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingGrapple) alone.
8. Mirrors `m_AimingWeapon | m_AimingGrapple` into [`StateBitFlag::SB_IS_AIMING_WPN_OR_GRPL`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_AIMING_WPN_OR_GRPL) and queues one act on the animated model directly, not through [`Character::QueueAct`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-QueueAct): `ACT_ON_STARTING_AIM` on the rising edge, `ACT_AIM` while aiming, and `ACT_ON_LEAVING_AIM` on the falling edge. Of the three, only `ACT_ON_LEAVING_AIM` appears in Rico's graphs (in `rico_partial_global.afsmb`).

So the aim state is a consequence of trigger input, not a separate button. A trigger value above zero ("feathering") raises the weapon without firing; firing needs the value to pass `m_trigger_sensitivity[0]`, with release at the lower `m_trigger_sensitivity[1]`. After the trigger is released the character stays aimed for the timer's tail.

IDA labels the function [`WeaponBase::GetMagazineSize`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-GetMagazineSize) as a `boost::shared_ptr<CWeaponBase>::operator->` thunk. It is a non-virtual accessor that returns [`WeaponTuning::m_magazine_size`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponTuning##field-m_magazine_size) through [`WeaponBase::m_Tuning`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_Tuning), and it is not the body behind the `IsWeaponAiming` slot.

### `Character::PreSimUpdateGrapple`

[`Character::PreSimUpdateGrapple`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-PreSimUpdateGrapple) owns [`AimState::m_AimingGrapple`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingGrapple). The flag is set when `m_AimingEnabled` is set and either [`GrapplingHook::IsHookAimingState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##func-IsHookAimingState) is true, or the hook's [`GrapplingHook::m_State`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHook##field-m_State) is [`GrapplingHookState::GHS_REELING_IN`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::grappling_hook::GrapplingHookState##variant-GHS_REELING_IN) with [`StateBitFlag::SB_IS_PARACHUTING`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_PARACHUTING) set. `IsHookAimingState` is true while the hook has an active wire that is not reeling in and not a custom wire (with the re-reel upgrade, reeling in also counts). So grapple "aiming" means holding a live tether, not preparing to fire. Grapple firing does not need it: `CGrapplingHook::DoActFire` queues directional acts (`S_RUN_STRAFE_GRPL_FIRE_*`) and `CCharacter::IsGrappleFiring` drives the fire-arm IK on its own.

### Related queries

- [`Character::IsAimingWeaponPossible`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsAimingWeaponPossible): a wielded weapon with [`WeaponBase::m_AimingWeaponIsPossible`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_AimingWeaponIsPossible), not holstering ([`StateBitFlag::SB_IS_HOLSTERING_WEAPON`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_HOLSTERING_WEAPON)), and either already aiming or not latched by [`StateBitFlag::SB_NO_WEAPON_AIM_NOAIM_TRANSITIONS`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_NO_WEAPON_AIM_NOAIM_TRANSITIONS).
- [`Character::IsTryingToAim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsTryingToAim): already aiming, or shooting is allowed and the trigger value is past the weapon's sensitivity, or a force-fire timer, count, or input buffer is live. The fire action is [`Action::FIRE_RIGHT`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-FIRE_RIGHT), [`Action::MC_FIRE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-MC_FIRE) on a motorbike, or `CWeaponBase::GetNextFireButton` for weapons that alternate.
- [`Character::IsTryingToFireAnyWeapons`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-IsTryingToFireAnyWeapons) and [`Character::HasAnyWeaponInput`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-HasAnyWeaponInput): weapon-input queries used by the IK and the mental state.

## Consumers

### Locomotion task selection

Every on-foot input locomotion task reads [`AimState::m_AimingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingWeapon) and [`AimState::m_AimingGrapple`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingGrapple) directly and branches between run/steer acts and aim-relative strafe acts: [`NStateTask_InputLocoMoveTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_InputLocoMoveTask##func-Update), [`NStateTask_InputLocoAimRelativeTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_InputLocoAimRelativeTask##func-Update), [`NStateTask_InputLocoAimPrecisionTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_InputLocoAimPrecisionTask##func-Update), and the Idle, Starts, Stops, Plants, RotateOnSpot, FlickStick, AimFlickStick, MoveOneOff, MoveGrappleFire, SetTargetFaceDir, and SetTargetSpeeds tasks. Most also call `IsAimingWeaponPossible`. The `NStateTask_LocoUtil` queue helpers do the same: [`NStateTask_LocoUtil::QueueMoveActions`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_LocoUtil##func-QueueMoveActions), [`NStateTask_LocoUtil::QueueAimRelativeMoveActions`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::locomotion::NStateTask_LocoUtil##func-QueueAimRelativeMoveActions), `QueueStarts`, and `QueueMoveOneOffActions`. [`StateBitFlag::SB_IN_LOCOMOTION_STRAFING`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IN_LOCOMOTION_STRAFING) reports the result back to the graph. High confidence.

The aim-relative strafe branch queues the `ACT_MOVE_AIM_FOCUS_*` acts (forward, 90 left, 90 right, and 180) and the `ACT_FORCE_MOVE_*` acts. By name these drive the `S_MOVE_AIM_FOCUS` states, which belong to the aim family (see "Relaxed and aimed holds"), so a task that takes the strafe branch moves the lower body in the aim family even while the aim flags are clear outside the task and the states keyed on `C_IS_AIMING_WPN_OR_GRPL` and `C_IS_AIMING` stay off. The graph's transition wiring is decoded ([animation-graph.md](../character/animation-graph.md)), but this path was not re-traced against it, so which states play is medium confidence. The decoded base graph does show `C_HEAVY_WEAPON` (the selected slot holds the heavy weapon, in any state) sending the aim-strafe moves to the `S_MOVE_AIM_FOCUS` states and the idle to `S_IDLE_AIM_FOCUS`. With a weapon wielded, `QueueAimRelativeMoveActions` takes the reference direction that selects the act from the wielded weapon's aim point ([`WeaponBase::m_AimTargetPosition`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_AimTargetPosition), read through the weapon's aim-target getter) minus the character's position; unarmed, it uses the player aim control's weapon point.

### Animation graph states and blend spaces

The base graph selects between two full-body families with `C_IS_AIMING_WPN_OR_GRPL` ([`StateBitFlag::SB_IS_AIMING_WPN_OR_GRPL`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IS_AIMING_WPN_OR_GRPL)) and the code conditions `C_IS_AIMING` / `C_IS_AIMING_WEAPONS` (`CAimingCondition`, which reads [`AimState::m_AimingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingWeapon)) and `C_IS_TRYING_TO_FIRE` ([`WeapoIsTryingToFireCondition::Evaluate`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeapoIsTryingToFireCondition##func-Evaluate)). The families are listed under "Relaxed and aimed holds" below.

Inside the aimed states, the aim yaw and pitch are a blend space. `CLocoAimBlendState`, `CVerticalAimBlendState`, and `CVerticalAimStrafingBlendState` switch to world-space displacement and aim-target pitch when `m_AimingWeapon` or [`AimState::m_AimingGrapple`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingGrapple) is set; `CJumpAimBlendState`, `CGrappleAttachAimBlendState`, `CParachuteBlendState`, and `CSpecialFireAimBlendState` also read the byte. The additive graph carries `AimUpMaxAngle`/`AimDownMaxAngle` limits on its aim states. The upper-body partial graph uses the aim flag only for the strafing grenade-throw variant and `ACT_ON_LEAVING_AIM`. The state and condition names are high confidence. The transitions that wire them together are decoded ([animation-graph.md](../character/animation-graph.md)) but were not traced for this section.

### Arm and look IK

- [`NAimIKTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/animation::arm_aim_ik##func-NAimIKTask_Update) activates aim IK when `IsAimingWeaponPossible` holds and the character is aiming ([`AimState::m_AimingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingWeapon)), trying to fire, or wielding a heavy weapon; or, for the grapple variant, when aiming the grapple ([`AimState::m_AimingGrapple`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingGrapple)) or `IsGrappleFiring`; or during a grenade throw; or when a data-driven state bit is set. When [`StateBitFlag::SB_USE_ENABLE_AIM_IK_SEG`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_USE_ENABLE_AIM_IK_SEG) is set it additionally requires the `ENABLE_AIM_IK_SEG` segment.
- [`RightArmAimIK::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::arm_aim_ik::RightArmAimIK##func-Update) is player-only. Its weight is the blackboard float keyed by [`ObjectBlackboard::AIM_IK_WEIGHT_ID`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/blackboard::ObjectBlackboard::AIM_IK_WEIGHT_ID), written by the animation data, not by the aim logic. It drives three effectors through [`RightArmAimIK::UpdateAimEffector`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::arm_aim_ik::RightArmAimIK##func-UpdateAimEffector) with the per-effector weight constants [`RightArmAimIK_ArmGain`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::arm_aim_ik::RightArmAimIK_ArmGain), [`RightArmAimIK_HandGain`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::arm_aim_ik::RightArmAimIK_HandGain), and [`RightArmAimIK_HeadGain`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/animation::arm_aim_ik::RightArmAimIK_HeadGain).
- [`NLookAtIKTask::Update`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/animation::arm_aim_ik##func-NLookAtIKTask_Update) disables head look-at while `m_AimingWeapon` is set.

High confidence.

High confidence (unconfirmed); the functions linked here are located.

### Foot IK

### Mental state

`CPlayer::UpdateMentalState` treats [`AimState::m_AimingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingWeapon) (outside explosive planting) as a reason to stay in combat. See "The mental state" below.

### Aim assist

High confidence.

### AI

NPCs do not read the player's aim flag. Two related signals exist. [`PlayerIsAutoAimingCondition::Evaluate`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/aim::aim::PlayerIsAutoAimingCondition##func-Evaluate) is a graph condition that is true when the evaluating character is the player's current weapon target (`PlayerAimControl::m_Target[TARGET_WEAPONS]`), which is computed whether or not the player is aiming. `CAIPerception::GetCharacterWithMentalState` reads the player's mental state; it is not yet located, and the IDB function with that name is [`AiGetClosestEntityInRange`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/ai::ai##func-AiGetClosestEntityInRange). ### Other

## Fire gating

Firing does not depend on the aim state. A wielded weapon with [`AimState::m_AimingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingWeapon) clear fires immediately, from wherever its muzzle is, toward the aim point.

- [`Inventory::GetAnimationAllowsShooting`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-GetAnimationAllowsShooting) is [`Inventory::m_DoesAnimationAllowShooting`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##field-m_DoesAnimationAllowShooting) and not [`StateBitFlag::SB_DISABLE_SHOOT`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_DISABLE_SHOOT).
- [`Inventory::UpdateInventoryPermissions`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-UpdateInventoryPermissions) recomputes the permissions each tick. Shooting defaults to allowed; it is cleared while pre-reeling or reeling in unless the `shoot_while_reeling_in` upgrade is owned, and cleared when `SB_DISABLE_SHOOT` is set.
- `SB_DISABLE_SHOOT` and the other disable bits are set by `NSetInventoryPermissions` state tasks in the graph ([`NSetInventoryPermissions_SetPermissions`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::NSetInventoryPermissions_SetPermissions)), for a whole state or within a named clip segment, and latched and cleared by `UpdateInventoryPermissions` each tick. No draw, holster, switch, or reload state carries the shoot permission; those block firing through state bits the ammunition check reads instead. Which states do carry it is in [weapon-firing.md](weapon-firing.md#the-shooting-permission).
- [`Inventory::UpdateWeapons_Parallel`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-UpdateWeapons_Parallel) and [`Inventory::UpdateWeapons_Serial`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-UpdateWeapons_Serial) zero the fire input passed to the weapon when shooting is not allowed. Because feathering is derived from the same input, a blocked weapon also cannot raise.

Inside the [`WeaponBase::UpdateFromUserPostSim_Parallel`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-UpdateFromUserPostSim_Parallel) virtual (base implementation [`WeaponBase::UpdateFromUserPostSim_ParallelBase`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-UpdateFromUserPostSim_ParallelBase)), in the per-gun [`WeaponBase::UpdateWeapon_Parallel`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##func-UpdateWeapon_Parallel), which does nothing unless the weapon has a user (see [weapon-firing.md](weapon-firing.md)):

- The trigger is pulled when the input exceeds `m_trigger_sensitivity[0]` (or stays above `[1]` once pulled); [`WeaponBase::m_IsFeatheringTrigger`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_IsFeatheringTrigger) is any input above zero.
- For a local player on a semi-automatic weapon, [`WeaponBase::m_FiredThisInput`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_FiredThisInput) limits one shot per pull; releasing the trigger clears it.
- A wall-penetration check ([`WeaponBase::m_IsWeaponPenetratingWallIfInAim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_IsWeaponPenetratingWallIfInAim) without [`WeaponBase::m_IsLeanOverFirePossible`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_IsLeanOverFirePossible), on the dual-wield, two-handed, and two-handed-special slots) blocks the shot and sets [`WeaponBase::m_InputBufferTimer`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_InputBufferTimer) to [`WeaponBase::INPUT_BUFFER_TIME`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase::INPUT_BUFFER_TIME), so the shot fires when the block clears within that window. The flags are written only by [`WallPenetrationWeaponComponent::UpdateWeapon_Serial`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WallPenetrationWeaponComponent##func-UpdateWeapon_Serial), for weapons held by a player, from a box collided from the holder's animated shoulders or hips toward the barrel; a wall hit also clears `m_AimingWeaponIsPossible` unless the component allows aiming while penetrating.
- [`WeaponBase::m_IsFiringCancelled`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_IsFiringCancelled) suppresses fire until the trigger is released.
- Force-fire timers and counts and burst shots force fire regardless of input.

Recoil and muzzle placement are per shot and independent of the aim state (see `aim-pipeline.md`). Nothing in the fire path reads the weapon's state or the user's selected slot; what it reads instead is in [weapon-firing.md](weapon-firing.md).

## Relaxed and aimed holds

The relaxed and aimed holds are separate full-body state families in the base graph, not one blend weight:

- No-aim: `S_MOVE_NO_AIM`, `S_NO_AIM_*` (turns to backpedal), `S_FLICK_*_NO_AIM`, `S_TURN_*_NO_AIM_STUNT`.
- Aim: `S_MOVE_AIM_STRAFE`, `S_MOVE_AIM_FOCUS` (with 90L/90R/180 variants), `S_IDLE_AIM_FOCUS`, `S_AIM_FOCUS_ROTATE_90L/90R`, `S_RUN_AIM_STRAFE_PLANT_*`, `S_MOVE_STUNT_AIM_STRAFE`, and the `*_AIM` variants of the stunt step-up and step-down states. The additive graph layers `S_MOVE_AIM_STRAFE_ADDITIVE` and `S_IDLE_AIM_FOCUS_ADDITIVE` on top.
- Transitions: `S_IDLE_TRANS_TO_AIM`, `S_IDLE_TRANS_TO_NO_AIM`, and `S_IDLE_TRANS_TO_NO_AIM_SLOW`; [`StateBitFlag::SB_IN_NOAIM_TO_AIM`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IN_NOAIM_TO_AIM) and [`StateBitFlag::SB_IN_IDLE_AIMING`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_IN_IDLE_AIMING) report them.
- Non-combat: `S_MOVE_NON_COMBAT`, `S_WALK_START_*_NON_COMBAT`, and `S_COMBAT_IDLE_TO_UNARMED_IDLE`, selected by `C_IS_NON_COMBAT` (`CIsPlayerNonCombat`, the player in the relaxed mental state).

The idle is the exception to the split: `S_IDLE_AIM_FOCUS` plays only the minigun's idle, and the held and aimed idles of the other weapons are clip variants of `S_IDLE` chosen by animation modifiers rather than by the aim states ([idle-stance.md](../character/idle-stance.md)).

Weapon-specific grip, reload, pump, bolt, draw, holster, switch, and pickup animations are in the upper-body partial graph (`S_UB_*`, keyed by per-weapon `C_<WEAPON>` conditions) and are independent of the aim families.

## The mental state

[`CPlayer::UpdateMentalState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/module/character::player##func-Player_UpdateMentalState) sets the player's `CAvatar` mental state ([`Avatar::m_MentalState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::avatar::Avatar##field-m_MentalState)) each tick through [`Character::SetMentalState`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-SetMentalState):

- [`MentalState::E_RELAXED`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::avatar::MentalState##variant-E_RELAXED) in a sequence or while holstering.
- [`MentalState::E_COMBAT`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::avatar::MentalState##variant-E_COMBAT), with a timer, while there is any weapon input, a grenade throw, a heavy weapon wielded, or [`AimState::m_AimingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::AimState##flag-m_AimingWeapon) (outside explosive planting), or while already in combat with the heat manager's restricted-military timer running.
- Otherwise relaxed. On the transition to relaxed with a weapon wielded it queues `ACT_ON_UNEQUIP_WEAPON_SLOW`, an automatic holster.

A second automatic holster sits in [`Inventory::UpdateWeaponHandling`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-UpdateWeaponHandling). For the player, every tick the mental state is relaxed, a weapon is wielded, the animation allows holstering, the weapon has no deferred unequip pending, and there is no weapon input and no draw or holster playing, it leaves precision aim, clears the grenade and mortar permissions (re-latched by the next tick's `UpdateInventoryPermissions`), and queues `UB_ACT_HOLSTER` through `Character::QueueAct`. This branch is also how the player's own holster takes effect: for the player, [`Character::HolsterWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-HolsterWeapon) queues nothing and instead forces the mental state to relaxed with a zero hold timer, and the relaxed branch queues the act later in the same `UpdateWeaponHandling` call.

Two static overrides short-circuit it: [`CCharacter::m_ForceNonCombat`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character_ForceNonCombat) forces relaxed and [`CCharacter::m_ForceCombat`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character_ForceCombat) forces combat.

[`Inventory::UpdateWeaponHandling`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-UpdateWeaponHandling) draws a weapon automatically when the player is in combat with nothing wielded and no weapon input, unless [`StateBitFlag::SB_DISABLE_MENTAL_STATE_DRAW_WEAPON`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/state::StateBitFlag##variant-SB_DISABLE_MENTAL_STATE_DRAW_WEAPON) is set. That bit is an inventory permission: `NSetInventoryPermissions` tasks set it, and `Inventory::UpdateInventoryPermissions` latches it and clears it every tick, so the draw checks both the latch and the live bit. Weapon input with nothing wielded also draws ([`Character::DrawWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-DrawWeapon)). Melee sets combat directly with the tuning's minimum combat time.

AI perception reads the mental state (`CAIPerception::GetCharacterWithMentalState`, not yet located), not the aim flag, so the relaxed/combat switch is what NPCs observe. Medium confidence on the extent of the AI reaction.

- Holster. Hold [`Action::RELOAD`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/input::input_action_map::Action##variant-RELOAD) ([`Character::HolsterWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-HolsterWeapon), which for the player goes through the relaxed branch of `UpdateWeaponHandling`), plus the automatic holsters above. Medium confidence on the triggers.
- Flick-stick and rotate-on-spot turns. Queued by the locomotion tasks from stick and aim-reference changes.

Medium confidence.
- Precision aim. `CPlayer::SetAimMode`, described in `aim-pipeline.md`.
