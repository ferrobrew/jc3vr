# The true reload

Under the controller scheme the game's timed reload is replaced by one done with the hands. The old magazine is knocked out with the fresh one, ejected with a button, or pulled out by hand; a fresh one is taken from a pouch on the belt and pushed into the gun's own magazine well; and a gun can be reloaded in one hand by pushing it down onto the pouch. The code is in `crates/jc3vr-weapons/src/controllers/weapons/reload/`. The one setting is `controllers.weapons.reload.enabled` (`TRUE RELOAD` on the pause menu's `VR: CONTROLS` page, on by default); with it off the reload button plays the game's timed reload, as on a gamepad. The tuning is `crates/jc3vr-weapons/tuning/reload.toml` (root `ReloadTuning`, [tuning.md](../tuning.md)), whose keys are named below by their path in the file. The engine side is in [weapon-ammo-and-reload.md](../../engine/gameplay/weapon-ammo-and-reload.md). None of this has been run in the headset; see "Outstanding checks".

## Which weapons

A weapon is reloaded by hand when it is wielded or armed in a hand, has a magazine limit, is not one of the game's untimed or unlimited-kind reloads, and is of a class with something to load: the pistols, revolvers, SMGs, rifles, shotguns, sniper rifles, grenade and rocket launchers, and the mortar (`plan.rs`). The minigun, the mounted and vehicle guns, and the special weapons keep the game's reload.

What a weapon loads, where its well is in the gun's model frame, and where its handle is come from the wells table, `tools/sights/wells.json`, extracted from the game's archives by `tools/sights/extract_wells.py` ([tools/sights/README.md](../../../tools/sights/README.md)). A weapon the table lacks, or whose entry is not trusted, takes its class's load and a well at `well_offset_m` from the holding wrist.

| Load | Eject | One push loads |
|---|---|---|
| Magazine | yes | a whole magazine |
| Shell | no | one shell |
| Rocket | no | one round into the muzzle |
| Cylinder | no; swung out and dumped | a whole cylinder, from a speedloader |

## Stopping the game's reload

Every animated reload the game starts goes through [`Character::StartReloadingWieldingWeapon`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-StartReloadingWieldingWeapon): the reload button, the automatic reload of an empty or magazine-less gun, the predicted reload while idle, a reserve refilled by a pickup, an animation's request, and the launchers' and sniper rifles' own requests. A detour on it refuses the start for the local player while the input tick reloads either hand's weapon by hand (`gate.rs`). The start counts as the local player's when its character is the one the input tick publishes or carries [`Character::m_IsLocalCharacter`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##field-m_IsLocalCharacter), so a published address that lags the character does not let a start through. No reload act is queued, so the game's reload state never begins and nothing is left to clean up.

The input tick publishes each hand's reloaded weapon with a time stamp. If it stops publishing for `gate.stale_ms`, the detour stops refusing and the game reloads as usual. A local start that is let through logs `reload: the game's own reload starts for the local player` with why (`the input tick has not published lately` or `no weapon is reloaded by hand`), at most once a second.

## Eject

A tap of the semantic `reload` action (the off-hand's lower face button on foot, in the default layout) ejects the magazine of the driest gun in either hand: the one with the fewest rounds in its magazine, the dominant hand's on a tie (`eject::tap_target`). A gun whose magazine is already out, or whose eject is queued, is passed over, so a double tap ejects both. The same button held is the game's holster, so only a press released within `tap_s` ejects. A tap that finds nothing logs `reload: the reload button found no magazine to eject`.

In a vehicle seat the reload action is not bound, so a double tap of a gun hand's fire press (each tap within `tap_s`, the second ending within `double_tap_gap_s` of the first, `eject::DoubleTapDetector`) ejects that gun's magazine when it is empty. A loaded gun's double tap is two shots, which no detector can tell apart in time, so it ejects nothing.

### The drop

The eject, the knock, the pull, and the belt swap all drop the magazine through one path: the input tick queues a request, and [`Character::UpdatePassPostPhysics_Serial`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-UpdatePassPostPhysics_Serial) executes it for the local character, before the original callback polls the animation's track messages (`reload/serial/mod.rs`). The engine runs that callback in its non-parallel post-physics range; drop calls from the input tick would run outside the place the game itself calls them. The mailbox holds at most one operation per gun hand, including an unread result. A request carries copied identities (character, weapon, gun, and spare), never borrowed pointers, and the callback resolves the current owned weapon again and rechecks the world, holder, gun, spare, magazine state, controller focus, tracking, reload permission, and, for a pull, the pulling hand's grip before it calls anything. A canceled or changed request does not fall back to the input tick.

The callback calls [`WeaponData::ThrowAwayMagazineObject`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##func-ThrowAwayMagazineObject), which drops the gun's spare magazine prop from the magazine part (hiding the part) or from the gun, with the gun's velocity; [`WeaponData::SpawnMagazineObject`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##func-SpawnMagazineObject) to ask for the next spare; and sets [`WeaponBase::m_WeaponIsWithoutMagazine`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##field-m_WeaponIsWithoutMagazine), which the game reads to refuse fire. The flag is set before the original message poll, so the game's own throw-away message cannot detach the magazine a second time. A gun whose spare prop has not respawned yet still takes its magazine out, with no prop dropped. The result is one of `NoThrow` (nothing changes: no spare requested, no ammunition, flag, or visibility touched), `DroppedUnretained`, or `Retained` (see "Magazines in the world"). A refused drop logs `reload: serial magazine request refused`, buzzes the gun hand, and plays the dry-fire click, and a belt push whose drop is refused leaves the trigger free.

## Magazines in the world

A dropped magazine is an object that keeps its rounds, and a magazine lying in the world that fits the held gun can be picked up and seated with them (`reload/loose/`). The game drops every character's spare props through the one call above, the mod's drops and its own reload's track message alike, and a detour on it notes them.

- A manual drop (eject, knock, pull, belt swap) that the store can retain carries its magazine-owned rounds out of the gun (see "The chamber"); a live chamber stays on the weapon. Under unlimited ammunition it carries none.
- A drop the store cannot retain (the fixed store is full, or the prop cannot be kept) drops unretained: its rounds stay counted in the weapon until the next magazine seats, when the game's reload returns them to the reserve, as the game's own reload does. An absent magazine cannot feed another round either way.
- The local player's automatic drops and other characters' empty drops can be recorded as empty pickups. Another character's non-empty drop stays the game's and untracked: the game's throw leaves those rounds counted in its weapon and its reload returns them to the reserve, so copying them into the magazine would duplicate ammunition.

Reservations, held magazines, unread results, and world records share one fixed cap. A full store refuses a manual drop unchanged and lets an automatic one run untracked. An empty unheld magazine expires after `loose.keep_s`; an unreadable body never lowers the count, and a record whose body ownership is lost is quarantined rather than restored by a reused body id.

While the gun's magazine is out, each noted magazine of the gun's tag ([`WeaponData::m_MagazineUniqueTag`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##field-m_MagazineUniqueTag)) within `loose.range_m` of the player is a grab volume of `loose.radius_m` for the hand without a gun. Taking it makes it the round in hand (`reload: picked a magazine up from the world`): its own body is carried to the hand each tick by velocities, capped at `loose.max_carry_mps` and `loose.max_carry_turn_radps`, so the magazine in the hand is the one that was on the ground. Seated, it loads its own rounds and the prop is disabled (`reload: seated a magazine from the world`); let go, it falls with the carry's motion. Held world magazines have no pouch timeout, and grip release and tracking loss still drop them. Offering them only while the magazine is out keeps a magazine lying near the player a loose object for the physical hands while the gun has one.

## Pulling the magazine out

A free hand can pull the inserted magazine out (`reload/extraction/mod.rs`). It needs a tracked hand, a detachable magazine in a table-placed well, a measured gun frame, and a live spare prop; shell feeds, revolver cylinders, muzzle-loaded rockets, and wrist-fallback wells are excluded. A fresh grip within `extraction.grab_radius_m` of the magazine target, or anywhere in the magazine's zone, starts the pull. The target sits outside the well along its axis by `loose.half_length_m` at the player's scale, an approximation of the magazine's centre rather than a measured hull. The hand then travels `extraction.pull_m` out along the well's axis, measured relative to the moving gun, so moving the gun with the hand does not count.

Opening the grip, losing tracking or world conversion, changing the gun or the world scale, or straying past `extraction.lateral_tolerance_m` cancels the pull and leaves the magazine, its rounds, and the chamber as they were. A brace or an action grip already held blocks the pull. For a new grip inside the target, `reload::prioritize_extraction` removes overlapping brace, gun-transfer, and action targets before the ordinary nearest-target choice ([grip.md](grip.md) owns that choice). An active pull owns the hand, holds the gun's fire, and blocks the belt for that gun until its result or cancellation.

Completion queues a drop (`DetachKind`) and the hand takes whatever comes back: a retained magazine goes into the pulling hand as the round in hand (`InsertionSource::RetainedMagazine`), matched on both gun and spare so an unrelated throw cannot replace it. On a mode change the stand-down calls `reload::cancel_extraction_on_standdown`, which clears magazine claims and queued ejects and requires the grip to open before a new pull; a magazine already detached stays in the world with its rounds.

### The magazine's zone

Which part of the held gun the free hand is at decides what its grip takes (`reload/zones.rs`). The handover takes the gun by its pistol grip within a radius wide enough to reach the bottom of a pistol's grip, where its magazine is, so the space under the well is the magazine's: a cylinder down the well's axis from `zones.lip_m` inside the mouth to `zones.length_m` below it, `zones.radius_m` from the axis, in model metres at the player's scale. It exists while the gun has a magazine in a table-placed well. A hand in it is not offered the handover, and its grip starts the pull wherever in the zone it is; only a grab above the well, or elsewhere in the handover's reach, hands the gun over. Without a magazine target (no pull possible, or a hand that has not opened since its last pull), a grab in the zone takes nothing rather than the gun. The grab view draws the zones ([grab-view.md](grab-view.md)).

## Load

The magazine pouch (the [hold tuning](../tuning.md)'s `volumes.pouches.magazine`) is one universal pouch at the middle of the belt's front, so the free hand takes from it and the gun is pushed onto it without crossing the body ([controllers.md](controllers.md#sockets-pouches-the-foregrip-and-the-action-runs-tier) places it). The reload picks the gun the pouch serves before placing it, and the pouch keeps its side while the free hand is busy with a round. Its centre for the take and the belt push is the displayed model's centre, including the model's placement offset (`pouch_models::display_centre`), so the player reaches for what they see. It hands out whatever the gun in the other hand takes and is a grab target for the hand without a gun:

- a magazine at any time, whether the gun's own is in or out, though it seats only once the well is empty (see "Knocking the old magazine out");
- a shell or a rocket only while the gun has room;
- a speedloader for a revolver.

A grab with no ammunition left (and no unlimited ammunition) gives nothing and a faint pulse (`Event::PouchEmpty`). While the pouch is not a target the grip press log says why (`magazine pouch: not offered, ...`: no free hand, no gun reloaded by hand, no rounds left, the gun is full, a round already in hand, or no skeleton to place it on). A launcher of one round that still holds its round is full and is offered nothing.

### The round in the hand

The hand holds the round as a magazine is held for loading: feed end up the finger tube with its top `held_top_m` ahead of the closed fist, its back in the palm, and its centre line `held_palm_gap_m` out of the palm (`insert.rs`, `render.rs`). A round that goes in along the gun's length (a rocket) turns its top out of the palm instead. A shell or a revolver's group of casings is held side-on, its axis the group's half width out of the palm in place of `held_palm_gap_m` (`Reload::for_plan`). The insertion check reads the top from the same line as the drawn round.

The top catches the well when it comes within `capture_radius_m` of the mouth, turned no more than `capture_angle_deg` from the well's axis, and moving into the gun relative to the well. The radius is a little more than a magazine's width, since nothing stops the hand at the well as a real gun would and the hand and the well each carry tracking and placement error. Launchers' wells are large and far from the grip hand, so they use `launcher_capture_radius_m` and `launcher_capture_angle_deg`. Motion is taken from consecutive top-to-well samples, so carrying the gun and the round together does not count, and a segment that crosses the mouth between ticks still catches. A caught round follows the well's axis at its depth and seats `seat_depth_m` past the mouth while it stays within `retain_radius_scale` capture radii of the axis; straying sideways or backing out releases it. Letting go seats a caught round between `release_seat_shares` of the seat depth. A pouch round not caught within `timeout_s` drops.

A round let go of near the well floats in (`insert::Float`): its top within `float.radius_m` of the mouth (or `float.capture_radius_scale` capture radii for a large well), short of the mouth's plane, and turned no more than `float.angle_deg` from the axis. Its top travels onto the axis (`float.approach_share` of the float) and then down it to the seat depth, eased over `float.min_s` to `float.max_s` at `float.speed_mps`, and seats on arrival. It catches the well as it starts and drops if the gun stops taking it on the way. Anything else let go of drops.

While a round is in hand, the gun's well is a touch target marked with a gold ring at its mouth ([grip.md](grip.md#markers)): the round goes in as the hand brings it there, without a squeeze. The ring turns red while the well still holds a magazine; pushing at it then plays the dry-fire click and the refusal pulse once. The wrist summary shows `Push the Round into the Gold Ring on the Gun`. An X-ray outline of the round at its seat in the well, with a preview sliding from the capture radius to the seat, guides the push while the round is held (`reload/guide/`, the `guide` tuning); it turns from the holding colour to the caught colour when the well takes the round.

### What the hand shows

A pouch magazine in the hand is drawn with the gun's spare magazine model: a second instance of the model the belt pouch draws ([pouch-models.md](pouch-models.md#the-magazine-in-the-hand)), separate from the gun, so the old magazine stays drawn in the gun until it leaves. Once the well catches it, it slides along the well in the gun's orientation. Where the model's top is comes from the wells table (`spare_top_m`). A seated magazine hides the instance and the gun shows its own part again ([`WeaponComponentBase::Enable`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponComponentBase##vfunc-Enable)).

The game has no model of a loose round for the shotguns or the revolvers, so their rounds are drawn with the spent casing the gun's casing-ejection effect throws out: one shell for a shotgun, and six pistol casings in a ring, as a speedloader holds them, for a revolver. The wells table gives the model and its geometry (`round_model`, `round_top_m`, `round_axis`, `round_radius_m`, `round_count`, `round_ring_m`), read into `ReloadPlan::round`. Once caught, the casings slide along the well with their axis turned onto the well's, and they are hidden once they seat.

A round without either model is the gun's own round part (`render::is_round_part`), shown in the hand that took it by the late update of the gun's parts, and hidden again if dropped while the magazine is out (for a rocket, while the launcher is empty). That is the UPU-210's cartridge (its spare prop is the empty cartridge), the rockets, and the Hydra's pod. While such a gun still holds its magazine, the part is that magazine, so the fresh one shows nothing in the hand until the old one is out. The Balloon Head has neither and shows nothing.

The Automat 12's magazine is modelled into its body and the gun has no magazine prop, so it borrows the UP-61's, the prop closest in size to its built-in magazine (`spare_from`, with `spare_top_m` and the seated origin `spare_origin_m`). The input tick gives each of its guns the borrowed prop's spawn tag ([`SpawnSystem::GetUniqueTag`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/spawn_system::SpawnSystem##func-GetUniqueTag) into [`WeaponData::m_MagazineUniqueTag`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##field-m_MagazineUniqueTag)) and requests its first spare, once per gun (`engine::borrow_spare`); from then on the game spawns, drops, and respawns it as a gun's own. A gun with no magazine part drops its spare from its own transform, so the drop moves the gun's transform to the borrowed model's seated origin for the call and puts it back (`engine::throw_spare`). The built-in magazine stays drawn throughout, and a borrowed magazine in the world carries the UP-61's tag, so it fits either gun.

### The seat

A seated magazine, cylinder, or rocket loads through the weapon's own reload ([`WeaponBase::Reload`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-Reload)), which keeps every rule of the game's: the reserve, unlimited ammunition, the upgrades, the rocket on the launcher, the magazine-out flag, and the HUD. A shell adds one round through [`WeaponBase::SetMagazineAmmo`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-SetMagazineAmmo) and takes it from the reserve through [`Inventory::SetAmmoCount`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::inventory::Inventory##func-SetAmmoCount), unless the ammunition is unlimited. Pickups, crates, and cheats touch only the reserve, so they keep working; the game's reload-on-refill is one of the starts the detour refuses. A seat counts as a load (the thud, the sound, the part shown) when the reload refilled the magazine, or when the magazine was out and is in again with rounds in it (`engine::load_full`). A seat never drops a magazine.

## Knocking the old magazine out

A pouch magazine in the hand can knock the gun's own magazine out of the well, as a tactical reload is done in the films (`reload/knock/mod.rs` for the test and the impulse, `reload/knocking.rs` for the input tick). While the well holds a magazine, the fresh one only waits: it neither catches nor floats in, and a slow push at the mouth is refused with the red ring, the click, and the refusal pulse (`InsertInputs::occupied`). Two motions knock instead:

- a push that reaches the mouth (within the capture radius) moving into the gun at `push_knock_mps` or faster (`InsertEvent::Pushed`), after which the fresh one catches the emptied well;
- a strike on the inserted magazine, on its base or its side near the well, closing at `knock.min_speed_mps` or faster.

The speed is one tick's travel, which reads well under the hand's peak as it slows into the contact. A hand bringing a magazine to the gun moves at a few tenths of a metre per second and a deliberate strike several times faster, so a gentle touch does nothing; the palms knock a loose object from the same speed ([physical-hands.md](physical-hands.md)).

The held magazine has no body in the physics world, so the strike is a test between its tip and a capsule down the well's axis, `knock.radius_m` from it, from `knock.lip_m` inside the mouth to the magazine's base (the table's `part_length_m` below the mouth for a magazine part, the mouth alone for a magazine modelled into the gun). The test runs in the well's moving frame, so the gun's own motion does not count, and sweeps the tip between ticks so a fast strike cannot pass through. The tip must enter the capsule from outside: a tip resting or sliding along the magazine never knocks. Only a magazine in a table-placed well can be knocked; a wrist-fallback well is ejected or pulled.

A knock queues the drop with `DetachKind::Knock` and the eject's round accounting. Nothing is loaded and the reserve is not touched: the fresh magazine seats once the well is empty and the reserve pays for it alone. `Event::MagazineKnock` plays on both hands at the strike, and `reload: knocked the magazine out` logs the closing speed (a too-slow contact logs its speed against the threshold).

The knocked magazine's flight is the physics world's. Once the drop's result returns, the strike adds an impulse at the struck point along the strike, sending the point on at `knock.share` of the tip's speed relative to the gun, capped at `knock.max_knock_mps` and `knock.max_spin_radps`. A base strike sends it out along the well and a side strike turns it. A fuller share sends magazines out of view before the player sees them leave. The impulse waits up to `knock.impulse_ticks` for the prop's body to be readable; an unreadable or unretained prop flies with the gun's velocity alone. The prop is not drawn for a frame or two after it appears, so the gun's magazine part, which the drop hides, is shown again until the impulse lands and for `knock.linger_ticks` after (`Linger`). That needs the part free, so it applies only to guns whose hand magazine is the spare model.

## The belt reload

Pushing a gun down onto its belt pouch reloads it in one hand (`belt.rs`), for every weapon reloaded by hand, whether or not a hand is free. The point pushed is the base of the magazine still in the gun (the table's visible length below the mouth), the mouth with the magazine out or modelled in, or a revolver's cylinder face. It must come within `belt.radius_m` of the pouch's centre with the gun's insertion axis no more than `belt.max_tilt_deg` from straight up, then go `belt.depth_m` deeper. Speed does not matter, since a hand bringing a gun to its hip slows as it arrives. A magazine still in the gun drops as the fresh one goes in (the swap loads only after the drop's result returns), and the reload chambers by itself. A shotgun takes one shell per push.

An entry that does not push (tilted, a full magazine, no reserve, or within `belt.after_draw_s` of a draw from the hip socket beside the pouch) does nothing until the point leaves and holds nothing back, so a gun lowered to the hip fires as ever (`belt::PushStage::Brushed`). After a push reloads, the gun cannot fire until the pushed point leaves the pouch.

With one gun, it is pushed onto the one pouch the free hand takes from. With a gun in each hand, each gun has a pouch of its own on its own side of the belt (the placement mirrored), so neither reaches across the body. While a gun's push is eligible and its point comes upright within `belt.approach_m`, its pouch is marked with a gold ring, a touch target that is never taken (`reload::belt_marks`). The wrist hint offers the push (`Push the Gun onto the Belt Pouch: Reload`) to the dominant hand's gun, and with a gun in each hand to each; it is read after the weapon tick finishes, so it reflects the final gun claims and ammunition. The pouch's model and the reload button's permission do not decide whether a push is eligible.

## Launchers

The grenade launchers, the rocket launchers, and the mortar are launchers (`ReloadPlan::launcher`). None has an action: a seated round fires at once, and the game has no cocking step for any of them ([weapon-ammo-and-reload.md, "Launchers"](../../engine/gameplay/weapon-ammo-and-reload.md#launchers)). The UPU-210's cartridge goes up into the bay ahead of the grip; a rocket goes rear end first into the front of the tube; the Hydra's pod goes forward into the rear of its housing, loaded as a magazine because the game reloads the Hydra as a magazine of rockets whose spare prop is the pod.

The spent round of a launcher of one round (the UPU-210's empty cartridge, the Hydra's empty pod) does not hold the well (`ReloadPlan::spent_round_replaced`): a fresh round catches and seats in its place, so a dry launcher reloads with one push and no eject. A launcher with rounds left still drops its round first. The seat discards the spent round before the weapon's reload runs (`engine::discard_spent_round`): the magazine is emptied and each gun's burst ([`WeaponData::m_BurstShotsLeft`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##field-m_BurstShotsLeft)) ended. Without it, a Hydra burst cut short leaves its round counted (a burst debits the magazine only at its last shot), the seat finds a full magazine, and the reserve never goes down. The Bildt Negotiator's box magazine is swapped as a rifle's is, so its empty box holds the well and leaves first.

## Revolvers

A revolver has no magazine prop, so nothing drops from it: every magazine route would wait on a drop that cannot happen. It is reloaded as the films do it (`reload/revolver.rs`, `reload/cylinders.rs`). Its skeleton carries the crane ([`WeaponData::CHAMBER_BONE_HASH`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##const-CHAMBER_BONE_HASH)) and the cylinder on it ([`CHAMBER_SPIN_BONE_HASH`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##const-CHAMBER_SPIN_BONE_HASH)). The game's reload clips swing the cylinder out by turning the crane about the barrel's line, the left-hand clip one way and the right-hand clip the other, with a little slide; the reload swings it the way the holding hand's clip does (`revolver::CRANE`, decoded from the clips with `tools/door_handles/havok.py`), writing both bones after the gun's pose update (`reload/bones.rs`).

- A flick of the gun hand rolling the gun about its barrel, away from the side the cylinder swings to, at `revolver.flick_dps` or faster throws the cylinder out over `revolver.open_s`, with the detent pulse. Flicks are at least `revolver.flick_cooldown_s` apart. The gun cannot fire while the cylinder is out (`FireHold::CylinderOpen`).
- Tipping the muzzle `revolver.dump_elevation_deg` above the horizon with the cylinder out dumps every chamber, spent or not, with the eject pulse, and six casings fall from the cylinder's rear (`reload/casings.rs`, drawn instances with no physics body, the `casings` tuning). The rounds still in the cylinder go back to the reserve (`engine::dump_cylinder`): topping up a part-fired cylinder should not cost rounds the player never fired, and the game's own revolver reload never loses one.
- A speedloader from the belt pouch seats as it meets the swung-out cylinder's rear face (a seat depth of zero) and loads the cylinder whole through the weapon's reload. A cylinder that is shut, or out with its casings in, refuses it with the red ring and the buzz.
- A flick rolling the gun back throws the cylinder shut over `revolver.close_s`, spinning it `revolver.spin_turns` turns as it closes, easing to a stop over `revolver.spin_s`.

The belt push is the one-handed reload, for a revolver in each hand or a busy free hand: with the cylinder shut, the cylinder's rear face is pushed onto the speedloader standing on the belt pouch, and the weapon's reload fills the cylinder over the rounds in it, returning those to the reserve. A swung-out cylinder is not pushed onto the belt, and the reload button ejects nothing from a revolver (`LoadKind::ejects`). A revolver whose skeleton has no crane loads over its rounds from the belt or the hand. While a cylinder is out, unlimited ammunition does not top it up. The belt pouch draws the speedloader as six of the gun's pistol casings standing mouths up in a ring ([pouch-models.md](pouch-models.md)); the game's archives name no speedloader or moon-clip model.

## The chamber

The game has no chamber inventory: its loaded-round count covers every round in the gun. The reload partitions that count into magazine-owned and chamber-owned rounds (`reload/ammo/mod.rs`) without creating ammunition. Feeding moves one magazine round into a chamber without changing the total. A drop transfers only magazine-owned rounds, so a live chamber stays on the weapon and can fire once with the magazine absent; the shot callback consumes its ownership at once, even when the native burst debit lands later. A tactical reload keeps the chamber and returns only the replaced magazine's rounds to the reserve; the game's full reload is run against a temporary magazine-only count for its reserve arithmetic, and the chamber's ownership is restored once after. Persistent records mirror the partition across weapon changes; a weapon with no adopted partition falls back to the native count.

Every plan's action is none (`ReloadPlan::cocked`): a seated magazine chambers its first round, nothing waits on an action, no slide catches at the rear, and no handle is offered. The bolt rifle's update runs with its bolt-action setting cleared, so the game never plays its bolt act, and its bolt lock ([`SniperWeapon::m_HasFiredThisInput`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::SniperWeapon##field-m_HasFiredThisInput)) is cleared once the trigger falls to the weapon's hold threshold ([`WeaponTuning::m_trigger_sensitivity`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponTuning##field-m_trigger_sensitivity)), so it fires once per pull (`engine.rs`). The pump-action shotgun keeps the game's own pump after every shot.

A gun cannot fire while its chamber and magazine are empty, its magazine is out with no live chamber, it is being ejected, a round is going in, the other hand is pulling its magazine, its cylinder is out, or it sits in the belt pouch after a push (`FireHold`): the input tick keeps its trigger from the game and plays `Event::DryFire` ([haptics.md](haptics.md)) at the pull's press edge, and the ammunition check clears the gun's shot as well against a buffered one (`empty.rs`, `fire_hold.rs`). With the dual-wield split a held pistol's trigger is kept from the split, so the other pistol still fires.

### The hand-worked action

The code for an action worked by hand stays, though no plan reaches it: a slide, charging handle, bolt, or pump as a part that follows the free hand along its travel from the table's handle (`travel.rs`, worked in `action.rs`, the `action` tuning), racking at `action.pull_fraction` and cycling home past `action.return_fraction`, with a slide that catches on an empty magazine. It is drawn on a separate slide part through the late update of the gun's parts (`render.rs`) or on the gun's pump or bolt bone by a post-call detour on [`WeaponData::UpdatePreSim`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##func-UpdatePreSim) (`bones.rs`), and the foregrip rides the pump (`foregrip::set_pump_slide`). A rack discards exactly one native loaded round through `SetMagazineAmmo`, never through [`WeaponBase::ConsumeAmmo`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-ConsumeAmmo) (which also advances the burst and can take reserve) or `Reload` (which can refill). `reload/steps/action_tests.rs` covers it with a native-operation adapter. Turning it back on means removing the `cocked()` call in `steps::weapon_tick`.

## Unlimited ammunition

With unlimited ammunition the magazine never empties, so reloading is optional (`reload/infinite.rs`). The game's own unlimited ammunition only makes its reload free: each shot still empties the magazine, and the game's reload, which the stop refuses, would refill it ([weapon-ammo-and-reload.md, "Unlimited ammunition"](../../engine/gameplay/weapon-ammo-and-reload.md#unlimited-ammunition)). Instead, while a magazine is in a gun reloaded by hand, each shot puts its round back at the per-shot seam, so the magazine is full before the gun's next ammunition check and a pistol's slide never locks back, and each input tick tops up a magazine that came in short, so a gun taken from a character fires at once. The magazine can still be ejected or pulled, the pouch still gives one, and whatever seats is full from then on. A magazine dropped meanwhile carries no rounds into the world, so none of the made-up rounds reach a later finite load, and it ages out as an empty one does. A launcher of one round is loaded again after each shot.

Whether the ammunition is unlimited is the game's rule read for the local player (`engine::unlimited`): [`Character::HasUnlimitedAmmo`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/character::character::Character##func-HasUnlimitedAmmo) of the player, or the weapon tuning's [`m_unlimited_ammo`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponTuning##field-m_unlimited_ammo). The weapon's own query reads the weapon's user, which for a gun taken from another character or armed in a hand need not be the player. The same rule decides whether the pouch has a round to give and whether a seat draws on the reserve, for both hands and every kind of load.

## Each hand's gun

Every gun in a hand is reloaded on its own, whichever hand holds it and whether the game wields it or it is armed in its hand ([two-handed-inventory.md, "The per-hand tick"](two-handed-inventory.md#the-per-hand-tick)): its plan, well, magazine, chamber, and fire hold are its own weapon's, and the game's reload is stopped while either weapon is reloaded by hand. With a gun in each hand no hand is free for the pouch, so each gun is ejected with the reload button (the driest first) and loaded with the belt push.

A single pistol ([physical-weapons.md, "Separate pistols"](physical-weapons.md#separate-pistols)) is a weapon of its own with half the pair's tuned magazine, rounded up, and the character's reserve. The game's reload fills it to the tuned size, so such a load is brought down to the half at once, the rounds over it returning to the reserve. The game's pair, while the pistols are not separate, is one weapon of one magazine with a gun in each hand: each hand's eject drops that gun's prop and takes the pair's magazine out, and a load fills the pair.

A weapon is remembered by its loadout item when the table holds it, and otherwise by its object (`records.rs`), so item-keyed chamber values survive the spawn reset's replacement of the object. The pre-reset boundary discards object-only records and releases the ammunition ledger's native owners outside its locks; a replacement seeds its partition from its current native total and any surviving item values. A gun's entries are kept by its index in its weapon rather than by the hand, so a weapon handed to the other hand keeps them.

### Armed weapons left to the game

The game's reload only ever reloads the wielded weapon, and an armed weapon's own request for it is refused for the local player, so a weapon armed in a hand whose reload is the game's (one with no plan, or any weapon with the reload off) would never reload. Such a weapon is refilled through [`WeaponBase::Reload`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponBase##vfunc-Reload) once its magazine has stayed empty for `refill_delay_ms`, with its magazine in and rounds in the reserve or unlimited ammunition (`reload/native.rs`). No animation plays, and a single pistol is brought down to its half. The log reads `reload: the game's reload refilled a weapon armed in a hand`. A weapon with no magazine limit, as every heavy weapon is, fires straight from the reserve and is never refilled ([two-handed-inventory.md, "Heavy weapons"](two-handed-inventory.md#heavy-weapons)).

## Haptics

Each step plays a cue of the weapons category ([haptics.md](haptics.md)): `Event::Eject` on the gun hand, `Event::PouchTake` and `Event::PouchEmpty` at the pouch, `Event::WellCatch` on both hands when the well catches, `Event::MagazineSeat` (or `Event::BeltSeat` for a belt seat) as a full-strength thud on the gun hand, `Event::MagazineKnock` on both hands at a knock, and `Event::ActionDetent` for a revolver's cylinder meeting its stop. A seat that leaves the gun able to fire plays `Event::ReadyToFire` on the gun hand `ready_cue_delay_s` after the thud, a double pulse (`ready_cue_pulses`) told apart from the thud. A refusal plays `Event::DryFire`, played by the weapon handling's trigger refusal ([physical-guns.md](physical-guns.md)) with the reason the reload holds the gun, once per pull.

## Sounds

The game voices a reload, a draw, and a holster from its clips' track messages and its reload start ([weapon-ammo-and-reload.md, "The guns' sounds"](../../engine/gameplay/weapon-ammo-and-reload.md#the-guns-sounds)), none of which runs while the hands do the work. So each move plays the gun's own sound at the gun where the gun's effects ([`WeaponData::m_AttachedEffects`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData##field-m_AttachedEffects)) carry one, the first usage the gun has from a list per move (`controllers::weapons::sounds`, `GunSound`), and is silent otherwise:

- A seat plays the insert sound ([`WeaponData::RELOAD_INSERT_AMMO_USAGE`](https://ferrobrew.github.io/pyxis/#/JustCause3_Steam_20206564/item/equipment::weapon::WeaponData), which only the shell-fed shotgun and the Bildt Negotiator carry), else the end of a reload (`RELOAD_END_USAGE`, played by the game when a timed reload with no animation runs out), else the dry-fire click (`OUT_OF_AMMO_FIRE_USAGE`) borrowed as the magazine's catch (`engine::play_seat_sound`).
- A refusal plays the dry-fire click.
- A draw off a socket plays the gun's draw sound and a dock its holster sound ([weapon-sockets.md, "Drawing and docking"](weapon-sockets.md#drawing-and-docking)).

Every other gun's reload sound is the whole reload in one event, so the eject, the knock, the pull, and a revolver's cylinder swinging have nothing to play; a dropped magazine's landing comes from the prop itself. Each sound played or missing logs `reload: played the gun's sound` (or `hold: ...` for a draw or a dock) at debug level.

## The readout

The debug UI's Weapons > Reload and gun action page opens with the `Magazines` status row ([status.md](../status.md)) and the serial mailbox's state (`ReloadStatus::serial`: installation, admission, slot states, counts, cancellation, and the last refusal), then the counters (ejects, knocks, seats, belt reloads, slides locked back, empty pouch grabs, and the game's reload starts refused), the world magazines in reach and dropped, and for each reloaded weapon its name hash, load, whether its well came from the table, the magazine and reserve, and each gun hand's chamber, belt push, and fire hold, then the round in hand and its distance from the mouth.

The session log carries what a take needs to follow a reload step by step, under `reload:` at info level: every reload event the readout lists, each change of what holds a hand's gun from firing (`what holds the gun from firing changed`), and each change of a gun's magazine that is not a shot (`the gun's magazine changed`, so a change with no reload event before it is the game's own).
